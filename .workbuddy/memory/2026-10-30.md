## M1 判卷（12:35）

用户提交 M1 六题 + 验证 + 自评 + 沉淀 v1。**发现一个跨题的系统性病根**，比单题对错重要：

**N08「分层边界感缺失」——把 A 的活算到 B 头上**。同一处出现在四个地方：
1. Q1「一个 IP 多个网站靠**端口映射**」
2. Q3「HTTP/1.1 加了 Host 后就可以**通过端口**区分网站」——恰好说反，Host 的意义正是**不用换端口**
3. 沉淀「浏览器不拆解导致**服务端**不知道处理哪些请求」——服务端看不到拆解过程
4. 沉淀「一条请求一条响应导致资源浪费」当成**拆解机制**的代价

这是 M0 那个病的延续：M0 把"判定"和"网关"混成一个；M1 把"端口"和"Host"混成一个。**统一命名为分层边界感**，建 N08，回访 1（M3 后）。

### 逐题
| 题 | 判 | 要点 |
|---|---|---|
| Q1 | △ | 交出去的应是 字节流+IP+端口；他写"HTTP协议+主机名+端口"。主机名已在 DNS 变 IP，且进 Host 头，不在"目的地"里。补：只给 IP 会**静默**连默认端口，不报错 |
| Q2 | ✔ | 最后一句"补了机制仍然无状态"对。纠：无状态 ≠ 服务端记不住（Session 就存在它那儿），是**协议不要求**。Cookie/Session/Token 分别答"怎么带上/存哪/怎么不存也能验" |
| Q3 | ✘ | 结论对，但"靠端口区分"是反的。且不是 HTTP/1.0「强制」，是**报文里没有承载域名的字段**（能力缺失≠规定）。补变通办法：多 IP / 多端口 / 反代按域名分流（=手搓 Host） |
| Q4 | △ | 漏了**同域名并发上限 4–6 条**，所以是"排队"不是"文件大"。区分排队 vs 队头阻塞。自查点：他的输出里 ALPN 协商结果是 http/1.1 |
| Q5 | ✔ | 最好的一题。类比自推。补：不只是换编码，是**拆进不同类型的帧**（HEADERS :method/:path/:authority + DATA），HPACK 压缩 |
| Q6 | △ | 把 CA 与"每次挑证书"混了。真机制 = **SNI**（ClientHello 明文带域名）。他的 curl 输出里三行就是铁证。补安全视角：SNI 明文 → ECH |

### 验证区（关键失败）
**三段式没做**，仍是描述式，全文没有一个"所以"。N06 关闭条件"连续两单元"**计数归零**。
四个证据未读：
1. `ALPN: curl offers h2,http/1.1` → `server accepted http/1.1`（协议可协商）
2. **`TLSv1.3 (OUT) Client hello` vs `TLSv1.2 (IN) Server hello`，最终用 1.2**——真实降级现场，安全面最有价值
3. `subjectAltName matches "*.baidu.com"`——证书看 SAN 不看 CN；通配符恰好掩盖 SNI 必要性
4. `> Host:` 出现在 `Certificate (11)` **之后**——Q6 答案就在他自己输出里
另：他跑 https 未跑导读要求的 http 明文，看不到"交出去的字节流"。

### 自评
前半"解决了哪个网站"对，"也就是服务器的**地址**"错（Host 里是域名）；后半"是对服务器的请求"是定义不是假设。正解：HTTP 默认**一个地址=一个站点**，Host 头是承认这个默认不成立后打的补丁。
