用户隔三天交回 v2。**这次物件全选对了，剩下的是深浅。**

- **① 过**：「字节流 + IP + 端口」骨架对（从 Q1 搬来）。措辞要修「传输给服务器」→ 交给**本机协议栈**（后续 M4/M5 要在这段前面层层加头）。缺「据此决定什么」，该半句被放到了 ④。

- **④ 第一句对、第二句反**：URL 直接写 IP → 落到 default_server，是标准「机制照常执行、结论不对」，最佳失效场景。第二句「两域名同 IP 按配置分配**路由**」是 Host **生效的正常场景**，且残留 Q3 的错（路由 vs vhost 匹配粘在一起）。给了真正第二个失效：Host 头缺失（1.1 应 400，1.0 落默认站）。

1. **顺序错了，不是方法错**：现地图按书序 M0→M18（客户端视角"一次请求的旅程"），但他工作需要**控制点视角**（谁能拦/在哪拦/方向）。建议 M3 后直接跳 **M9 NAT → M11 防火墙 → M12 代理 → M13 CDN**，M4-M6 挪后快过，M10 跳，S4 后置。

### 「针对性 vs 完整」的答案
按知识形状分：**因果链型**（网络/认证/攻击链）骨架必须完整、血肉可砍；**清单型**（工具/漏洞类型）针对性；**模型型**（权限/检测/定级）范围小但必须能推演。网络属第一类 → 骨架完整（M0-M3+M9+M11+M12+M13），血肉针对性。

### 几个自己满意的判据设计
- **M4 的"命中即停"实验**：属主位 `---`、组位 `r--`，你是属主 → 读被拒。证明 Linux 不 fallback，与 Windows"所有组累加"相反
