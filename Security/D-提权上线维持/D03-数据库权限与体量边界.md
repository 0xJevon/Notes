# D03 · 数据库权限与体量边界

> 只学两件事：**库能干什么**、**能拿出多少条**。不学 SQL 教程。
> 来源：Career 原《必学清单》第 4 项（2026-11-18 拆分后迁入，判据是库主的）。
> 状态：判据稿，未实测。

---

## 一、库能干什么（权限模型）

| 库 | 要看什么 |
|---|---|
| **MySQL** | `user@host`——**同一账号不同来源 IP 权限不同**；库级 / 表级 / 列级三层授权 |
| **SQL Server** | login → user → schema 三级；`sa` 与 `dbo` 不是一回事 |

**从权限推到动作**：
- `secure_file_priv` 决定 `INTO OUTFILE` / `LOAD_FILE` 能不能用，以及能写哪个目录
- SQL Server 的 `xp_cmdshell` 与 `OPENROWSET` 是两条不同的执行路
- 低权限账号也能 `LOAD_FILE` 读文件（只要 `FILE` 权限 + 路径在允许范围内）

## 二、能拿出多少条（体量轴）

| 方法 | 能不能当证据 |
|---|---|
| `count(*)` | **能**——实测计数 |
| 分页接口返回的 `total` | **能**——但要与 `count(*)` 对一次 |
| `information_schema.table_rows` | **不能**——是估算值，会差几倍 |

**体量轴的硬规矩**（与 `SEVERITY-RUBRIC` 一致）：
- 单数据集/单接口实测计数，不按接口数或表数推算
- 抽样 ≥30 条验证字段真实填充与号码校验位
- 同一请求复测一致
- **区分"记录条数"与"去重实体数"**——台账类数据的身份证常属经办人，一条记录 ≠ 一个自然人

## 三、字段识别（半件事，但别丢）

证件号、手机号、银行卡号长什么样，校验位怎么算。这是判"数据轴取 2 还是取 3"的唯一依据。

> 手机号/身份证统计必须用「正则 + 校验位 + 结构化字段取值」三件套，禁止只跑正则——见用户级铁律。
