# D06 · 日志与告警反推

> **会看告警不等于会推演告警。** 这一篇的目的是：看到一条告警，能反推它由什么行为触发、命中了哪一层。
> 来源：`Career/03-必学清单` 第 3 项（2026-11-18 迁入）。
> 状态：判据稿。**验收必须用你手上的真实日志，不用样本。**

---

## 一、关键事件 ID（记这八个，不记全表）

| ID | 内容 | 看什么 |
|---|---|---|
| **4624** | 登录成功 | **LogonType**：2 交互 / 3 网络 / 10 远程桌面——意义完全不同 |
| **4625** | 登录失败 | 短时间大量 = 爆破或喷洒；**离线爆破（Kerberoast）不产生这个** |
| **4688** | 进程创建 | 要开审核策略才有；**命令行在这** |
| **7045** | 服务安装 | psexec 的硬指纹（服务名 `PSEXESVC`） |
| **4768** | TGT 请求 | 预认证未启用（AS-REP 可打）会在这里显出异常 |
| **4769** | TGS 请求 | Kerberoasting 的痕迹；RC4（0x17）加密类型可疑 |
| **4720** | 创建用户 | 隐藏账号也会留 |
| **1102** | 日志被清 | 自己人干的事，等于自曝 |

## 二、Sysmon 四个够用

事件 1（进程）、3（网络连接）、11（文件创建）、13（注册表写入）。其余的用到再查。

## 三、检测层次（绕过必须在同一层想）

| 层 | 在哪 | 绕过是什么 |
|---|---|---|
| 用户态钩子 | ntdll / kernel32 的 API 被改 | unhooking、直接 syscall |
| ETW 与内核回调 | 内核登记的回调 | 关 ETW、换未监控的 API |
| 行为规则 | 进程树、命令行特征、时序 | 换父进程、混淆命令行、拉长周期 |

**判错层的典型**：想躲行为检测，却去做字符串加密（那是静态层）。

## 四、日志侧的四个高价值特征

1. 编码后的命令行（`powershell -enc`）
2. 异常父进程（`w3wp.exe` 起 `cmd.exe`）
3. 服务二进制落在临时目录
4. 短时间大量 4625

## 五、验收

**任取一条你手上的真实告警**，说出：
- 触发它的具体行为是什么
- 命中哪一层检测
- 如果要绕，该在哪一层动

> 你每天都看防火墙和终端日志，但没系统学过日志怎么产生——这是"会用告警、不会推演告警"的根因。这一篇补的就是推演。

## 六、反向用途（这是安服的用法）

安服不追求"不被发现"，但要求**做完一步能说出自己留了什么**。做完一次操作后，在日志里找齐自己的全部痕迹——这是 D06 的另一半，也是复测时判断"客户到底有没有监测能力"的依据。
