# C06 · AI 应用与 Agent 面

> **审计对象变了，不是能力变了。** 过去只有 Web 应用一种对象，现在暴露面上还有一类：别人部署的 LLM 应用与 Agent。
> 源：大白哥 19–21 · V2027-1 专题二（AI 大模型安全）。
> **开线条件**：本单位或客户暴露面上确实有大模型应用（AI 问答、AI 公文、智能客服、Agent 平台）。没有就不开——这一篇是判据稿，不是任务书。

---

## 一、四层攻击面（先判在哪一层，再谈怎么打）

| 层 | 面 | 典型问题 |
|---|---|---|
| **提示词层** | 系统提示与用户输入没有硬边界 | 提示词注入、系统提示泄露、越狱 |
| **工具层** | Agent 能调用什么 | 过度授权、tool 参数未校验、间接提示注入诱导调危险工具 |
| **数据层** | RAG / 知识库 / 会话历史 | 越权检索到别人的文档、上下文串号 |
| **部署层** | 模型服务与网关 | 未授权 API、调试端点、密钥硬编码、SSRF 到内网模型 |

**判断顺序**：先看它有没有"工具层"。没有工具调用的纯对话应用，攻击面只剩提示词层与数据层；有工具调用的，**工具层是最重的一层**——因为它把"说错话"变成了"做错事"。

## 二、四条判据

| # | 判据 | 怎么算成立 |
|---|---|---|
| **1** | **系统提示能不能被套出来** | 用角色扮演、编码、分段拼接等方式让它复述前置指令；能拿到原文即成立 |
| **2** | **用户输入能不能覆盖系统规则** | 不是"它说了不该说的"，而是**它执行了系统提示里明确禁止的动作** |
| **3** | **tool 的权限边界在哪** | 列出它能调的 tool（读文件？发请求？执行命令？查库？），逐条问：**这个 tool 的参数由谁控制** |
| **4** | **RAG 能不能越权检索** | 用一个账号去问另一个账号才该看到的文档标题，看它答不答 |

**判错层的典型**：把"模型说了脏话/说了不该说的话"当成漏洞。那不是漏洞，是内容策略问题。**真正算数的是"它做了一件系统提示禁止它做的事"，而且这件事有后果。**

## 三、这一层最容易踩的坑：你自己的工具链

你在用 MCP + Skill 搭工具集。这意味着：

- **stdio 方式的 server = Agent 能起本地进程**。server 脚本的入参谁来校验？能不能被诱导成任意命令执行？
- **Skill 里写的红线，是唯一能约束顺序与禁止项的地方**。MCP 只管"有哪些工具"，不管"什么顺序、什么不许做"
- **工具切太碎或太粗，都会出问题**：太碎模型选不过来，太粗等于把危险档位焊死在最高

**判断一句话**：MCP 是能力清单，Skill 是行为规矩。**安全的红线属于流程层，不属于工具层。**

## 四、验收

- 打一次提示词注入，**让系统执行它明确禁止的动作**，留下原始请求与响应
- 审一个 Agent 的 tool 清单，写出每个 tool 的「参数来源 / 能碰什么 / 最坏后果」三列
- 说清这个应用的四层攻击面里，哪一层是空的（没做）、哪一层做了但形同虚设

## 五、不学

- 模型训练、微调、推理优化——你是使用者不是研究者
- OWASP LLM Top10 逐条背诵——清单读一遍就有，**只有能实测的那几条值得花时间**
- AI 生成内容的合规审核——那是内容安全，不是渗透
