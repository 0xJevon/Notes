# 04 · 双线能力线（交付线与红队线）

> **一句话**：两条线，一个终点。红队线是终点（V1–V4），安服代审线是当前必须打通的交付段；**同一时间只有一条线占「学习时间」**，另一条只维护索引与证据。
> 上位：[[000-知识库总纲]] §2.6、§2.7。通用规则：[[_通用/00-索引|通用索引]]。

---

## 一、两条线的定位

| | 安服代审线 | 红队线 |
|---|---|---|
| 终点 | 能独立交付一套系统的代码审计（报告 + 复现包） | V1–V4：打穿一条链且不被发现 |
| 验收 | A1–A4，见 [[10-安服代审能力地图]] | V1–V4，见 [[00-红队能力地图]] |
| 当前状态 | **active（6 周）** | **paused（维护索引，不加新料）** |
| 入口 | [[10-安服代审能力地图]] · [[11-安服代审学习计划]] | [[00-红队能力地图]] · [[03-学习计划]] |
| 产物 | 样本卡 + 判定卡 + 证据 + 报告骨架 | 证据 + 问题 + 链路图 + 报告 |
| 时间预算 | 8–10 h/周，6 周 | 安服线 Gate 通过后接续 M1 第二段（内网） |

**为什么先安服线**：它是手上项目的交付要求，也是红队 A/B 两段的入口能力；先打通它，红队线才有稳定的练习来源（真实项目 = 有约束的靶场）。

### 1.1 红队线内部再分两段（代审子线 / 内网子线）

红队线不是一块整料：代码审计出身的人，先走**代审子线**，再回 M1 的内网段。

| 子线 | 文件 | 何时启动 | 产物 |
|---|---|---|---|
| **红队代审子线** | [[12-红队代审能力地图]]（R1–R4）· [[13-红队代审学习计划]]（4 周） | 安服线 A1–A4 通过后 | 作战判断卡 + 检测面卡 |
| **内网子线** | [[03-学习计划]] 的 M1 第二段（内网四关） | 代审子线结束后 | V2 的前半程 |

代审子线**不是第三条主线**：它只把安服样本卡第 6 节的“红队口径”练成判断，结束即转维护；同一时间仍只有一条线占学习时间。

---

## 二、切换规则（防两条线互相抢时间）

1. **同一周只允许一条线占「学习时间」**；另一条只做三件事：更新索引、补证据链接、记一行台账。
2. 切换点只有一个：安服线 **A1–A4 全部通过**（见 10 的验收表）。
3. 切换后安服线转为「按项目维护」：只在真实项目里加卡，不再按周排期。
4. 任何一条线要停超过两周，必须在 [[001-驾驶舱]] 的四问里写明原因，否则视为漂移。

## 三、共用与不共用

| 共用（两层） | 不共用（各建各的） |
|---|---|
| `Security/_证据/`：原始输出 | 能力域目录：安服线不建 A–E 的攻击链目录 |
| `Security/_问题库/`：卡点与关闭条件 | 学习计划：两条线各一份，不合并 |
| `Security/_项目/`：靶场与真实项目 | 产物格式：样本卡 vs 链路图 |
| `_模板/`、`_通用/`：规则与骨架 | — |

**投影关系**：安服代审线对应红队线的 A（入口发现）/ B（初始访问）两段，是 V1 的前半程；C 只覆盖「落地后读配置/找凭据」的判断，不覆盖驻留与对抗。投影不出来的内容（如报告定级），归安服线的交付域，不硬塞进 A–I。

## 四、越界阈值的临时修订（有期限）

总纲 §2.6 的规则是「非 A–E 目录行数超过 A–E 合计 → 当季复核」。安服线开工后，代码审计与样本卡会继续变厚，这条会持续触发。

**2026-11-13 起，6 周内（至 2026-12-25）按下面执行**：

- 阈值改为：**安服代审线（含样本卡）非空行数 > 红队 A–E 合计的 2 倍** 才触发复核；
- 到期（2026-12-25）无条件复评一次：要么安服线 Gate 通过并转维护，要么砍掉一半样本卡目标；
- 复评结论写进 [[001-驾驶舱]]，不改总纲原文。
