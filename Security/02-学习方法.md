## 一、环形训练法（G19 的红队实例）

《学习思想》的原话是"线性思维不好使，学到后面前面的又忘了"。所以不用 W1→W2→W3→W4 分段，改成：

**选同一个靶场（Vulnstack 1），每轮都从外网入口走到横向，但只考核一个焦点。**

| 轮次 | 走什么 | 焦点（只考核这一项，其余做到就行） |
|---|---|---|
| **Loop 1** | 外网入口 → 落地 → 提权 → 横向，**全走一遍** | **定位**：我是谁 / 我在哪 / 周围有什么 / 凭据在哪 |
| **Loop 2** | 同一环境 | **提权**：应用池账号 → SYSTEM |
| **Loop 3** | 同一环境 | **横向**：psexec / wmiexec / winrm 的痕迹差异 |
| **Loop 4** | 同一环境 | **全链质量**：无冗余步骤、痕迹最少 |
| **Loop 5** | 同一环境 + 开 Defender/Sysmon | **对抗**：不触发有效告警 |
| **Loop 6** | 同一环境 + 限时 4h + 只给一个入口 | **决策**：什么时候放弃一条路 |

**关键差别**：每轮都是完整链路（保持全局感），但只考核一个焦点，其余环节"做出来就行，不管质量"。

### 每轮时间分配（5–10 小时/周）

- 打靶 **65%**
- 复盘 30%（画链路图 + 写机制结论）
- 查资料 **5%**

> 强化 A 域（打点）时比例反过来：阅读 40% / 模拟推演 40% / 真实目标 20%。但那是第二阶段——现在读两百篇文章不解决 Windows 空白。

### 卡点记录必须在打的当时写，不隔夜

隔夜回忆出来的"卡点"是重构过的，不是真的。这是唯一不能妥协的纪律。

## 二、一次单元的产出（G17 的红队落点）

```
1. Security/_证据/2026-11-03-vulnstack1-Loop1-定位.md
   └─ 原样粘贴：敲的命令 + 终端返回。不改写、不美化、不补全"应该返回"的部分

2. Security/_问题库/为什么找不到域控的DNS.md
   └─ 现象 + 我的猜测 + 实验设计 + 关闭条件

3. 正文（对应能力域下的一节）
   └─ 一句话机制结论，能指到上面第 1 条
```

### 阅读的产出是"假设"（G06 的红队版）

没条件打的时候，读是唯一能产生假设的方式。产出形态：

| | 打靶 | 阅读 |
|---|---|---|
| 产出 | **证据**（实测记录） | **假设**（待验证的判断） |
| 落点 | `_证据/` | `_问题库/`，`status: 待验证` |

模板三行，**第三行写不出就放弃这篇**：

```
我读到的做法：<一句话概括，不抄步骤>
如果是我遇到这个环境：<我会怎么改？哪里会卡？>
可验证的假设：<一句能被实验证伪的话>
```

> **禁止**：把文章步骤抄成笔记。那不是知识库，是别人的博客备份（G16）。

## 三、"这个技术我真的会了"——红队版

G07 的五格，在红队里长这样。以「wmiexec 横向」为例：

| 要素 | 红队语境下的答案 |
|---|---|
| **输入空间** | 有目标主机的管理凭据（hash 或明文）；135/445 可达；目标未禁用 WMI |
| **映射关系** | 通过 DCOM/WMI 远程创建进程；**为什么有效**：不落可执行文件，命令由 `WmiPrvSE.exe` 代执行 |
| **适用范围** | 445 被拦时失效；WMI 服务被禁用时失效；目标开了严格的应用白名单时，命令本身会失败 |
| **预测目标** | 一条命令的回显 + 一个在目标上执行的上下文，**不落地 exe** |
| **判别模型** | 目标有 EDR 且监控 WMI-Activity / 4688 命令行 → **换别的**；只有 445、没有 135 → 换 psexec 但会留服务 |

**填不满第五格的，不算会，只算会抄。**（G08）

## 四、AI 在红队的具体分工

G10 的三层判断，落到红队的实际任务上：

| 层 | 红队里的具体活 |
|---|---|
| **托管层**（输出对不对一眼能看） | 资产测绘、指纹匹配、CVE 检索、报告初稿、工具参数、字典生成 |
| **加速层**（能验证结果） | PoC 改写、免杀变异、审计可疑点扫描、日志分析脚本 |
| **无效层**（没有标准答案） | 下一步打哪、为什么这台机器提权失败、防守方此刻在看什么 |

### 为什么 AI 到不了高级红队（这条是红队特有，通用层讲不了）

**AI 的输出是语料里的平均解。而防守方的检测规则，恰恰是拿"平均攻击解"喂出来的。**

1. AI 能把你快速抬到「平均攻击者」水平——**而那正好是最容易被 SOC 抓到的水平**
2. 高级红队的定义，就是**不在平均值上**。那个偏离平均值的东西（对环境的判断、对防守方反应的预判、什么时候收手的决断）没有语料，只能靠真实对抗攒

所以"一线红队都在用 AI"要拆开看：他们用 AI 干的是写报告、整资产、生成钓鱼话术、写一次性脚本、辅助审计——全在托管层和加速层浅层。**没有人用 AI 决定内网怎么走**，因为那个决策依赖私有上下文，喂上下文的成本高于人自己判断。

### 这一点和 `_证据/` 的规则是同一件事

`_证据/` 只收实测事实，所以**库里的每一条都是可信语料**。别人接本地检索要过滤噪声，这里天生没有噪声。

**建库这个动作本身，就是在给未来的 AI 协作攒燃料。**

## 五、红队域额外的禁止入库项

G16 的通用清单之外，红队再加四条：

- ❌ **漏洞原理复述**（"SQL 注入是把输入拼进 SQL"）—— 知道这个不算能力
- ❌ **工具参数与用法** —— 有 `--help`
- ❌ **面试题答案** —— 在 `_素材/面试题库/`，它是检查表不是知识
- ❌ **靶场 walkthrough 的步骤** —— 打了靶场留下的是"我在哪卡住、为什么"，不是"第几步敲什么"

## 六、复盘三问（G18 的红队版）

1. **换防护还能用吗？** —— 换 EDR / 换 WAF / 开日志审计，这招还成不成立？
2. **这条路堵死，还有别的吗？** —— 强制说出 2 条备选，哪怕很烂
3. **本质是什么？能迁到哪？** —— 剥掉具体工具，这个原理还能用在什么场景

> 三问里第 3 问最关键：**它是"打了这个靶场"和"长了横向能力"的分界线。**

## 八、自检

### 每轮 Loop 结束

- [ ] 卡点是不是在打的当时记的？（隔夜回忆的不算）
- [ ] 本轮焦点那个动作，能不能不看清单做出来？
- [ ] `_证据/` 里有没有这次的原样记录？
- [ ] 这次撞到的规律，去 `_通用/` 搜过了吗？（撞到了 → 加一行印证）

### 每月

- [ ] `_问题库` 里 `待验证` 超过 15 条？→ 停掉新输入先清队列
- [ ] 有没有标 `blocked: 前置` 的？→ 超过 3 条说明难度超标，按 G05 降级
- [ ] 本月有没有一条完整链路的复盘？→ 没有的话，这个月在攒碎片
- [ ] 正文里有没有指不到 `_证据/` 的论断？→ 标「待验证」或删掉
- [ ] `00-红队能力地图` 的 V1–V4 有没有变化？→ 连续两月无变化，检查是不是在舒适区
