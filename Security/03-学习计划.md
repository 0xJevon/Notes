# 03 · 红队路线（交付优先，2026-11）

> **终点没变，是顺序变了。** 目标仍是 `00-红队能力地图` 写的那条：**技术能力足够的红队工程师**（小迪那套 320 天课瞄准的就是这个，V1–V4 是它的验收表）。变的只是当前约束——必须先能独立交付安服项目。
> 本版取代同日两版：v1（纯深度突破，不顾交付）、v2（纯交付优先，把红队主线降为"进阶期"）。**v2 的具体判断全部保留，只是重新放回红队主线里定位。**

## 一、这是一条路，不是两条

先定性质，否则每次都要重议：

| | 内容 |
|---|---|
| **终点** | 高级红队：拿到一个公司名能自己打穿，且不被发现（V1–V4） |
| **当前约束** | 手上项目要交，代码审计与内网渗透不能独立 |
| **两者关系** | **交付能力是红队能力的子集，且是它的前两段**——不是岔路 |

理由：红队打穿一条链，中间必然要做"审代码找入口""进内网横向"这两件事。安服项目只是把这两件事**去掉隐蔽要求、加上报告要求**。练的是同一批技能，考核重点不同。

所以本文按里程碑排，不按"交付/进阶"分家：

```
M0 现状  →  M1 能交付  →  M2 V1  →  M3 V2  →  M4 V3/V4
   web已会     审计+内网     8h拿第一台   有EDR到域管   隐蔽与对抗
   2026-11    90 天        2027-05      2027-12      2028→
```

## 二、重合度：哪些投入是复用的（决定投入顺序）

同样是学一件事，练法不同，对红队的价值差一半。这张表是本计划的分钱依据：

| 能力 | 安服口径 | 红队口径 | 复用度 |
|---|---|---|---|
| **内网渗透** | 客户给段、不隐蔽、到指定目标 | 自己打、要隐蔽、到域控 | **100% 同一条线**，红队只多加"隐蔽"一段 |
| **代码审计** | 覆盖多少模块、报几条、定级对不对 | **这个东西我怎么进去** | **约 50%**，口径不对会白练（见第四节） |
| **Web 漏洞** | 找洞 | 把入口变成执行权限 | 80%，你已会 |
| 云/资产 | 覆盖 | 外网打点的延伸 | 70% |
| 免杀 / C2 基建 / 钓鱼 | 不做 | **V2 的必经** | 0，纯红队增量 |
| 域渗透深入 | 多数合同不要求 | **V2 核心** | 20%，安服只到"能进域" |

**结论：内网这条线可以全押，怎么练都不浪费。代码审计要换口径，否则练成"报告机器"，对红队没用。**

## 三、M1 交付期（2026-11-11 → 2027-02-08，90 天）

### 3.1 安服内网 ≠ 红队 V2（先省下一年的错觉）

| 环节 | 安服内网项目 | 红队 V2 |
|---|---|---|
| 隐蔽性 | 不需要（客户陪同、可关 AV） | 核心考核 |
| 入口与凭据 | 常由客户给段/给跳板，弱口令即可 | 必须自己打出来 |
| 深度 | 指定目标机，1–3 跳 | 必须域控 |
| 免杀 | 不做 | 自研 |
| 时间 | 1–3 天 | 24 小时连续 |
| 真实主要工作量 | **连通性排障** | 排障 + 规避告警 |

安服内网 ≈ V2 的 40%，缺的 60% 是最贵的部分。**但它不是白练——那 40% 正好是 V2 的第 1–3 段。**

### 3.2 内网四关（这条线全押，不设取舍）

| 关 | 内容 | 现状 | 小迪天次（以课件目录为准） |
|---|---|---|---|
| 1 **连通** | 出网判断、隧道选型（ICMP/DNS/HTTP/SMB）、代理链、路由与防火墙 | **最弱，先补** | 243–247 |
| 2 收集 | 本机信息、凭据位置、BloodHound | 有操作，讲不清 | 248–249 |
| 3 横向 | IPC/PTH/PTT/委派/WMI/WinRM 的适用条件与痕迹 | 做过，说不出选型理由 | 250–253 |
| 4 提权 | Windows 令牌/特权/服务/DLL；数据库提权 | 自评 Q3 答错过 | 195–208 的 Windows 段 |

第 1 关是硬门槛：安服内网的卡壳绝大多数是"打下来了连不回来"或"给了段扫不通"。这关过了，后三关有工具和 AI 兜底就能交付；同时它也直接是 V1 的第 3–5 段。

`_项目/靶场/内网打靶.md` 的 VPC3–5 不需要重写，**只补"当时为什么卡住、怎么排出来的"那几段**——排障经验是本阶段唯一必须自己攒、AI 给不了的东西。

### 3.3 代码审计：四步法，但口径要按红队改

安服审计拆开四步，AI 可用度差别极大：

| 步 | 动作 | AI 可用度 | 你的动作 |
|---|---|---|---|
| 1 定范围 | 列出入口（Controller/路由/接口） | 高 | 核对是否漏了未鉴权入口 |
| 2 找 sink | 危险函数、拼接、反序列化、文件操作 | 高（CodeQL/Semgrep + LLM 比人快） | 只做候选筛选，不下结论 |
| 3 **验可达** | 污点能否从入口走到 sink，中间有无拦 | **低（误报主要来源）** | **全部自己做**，逐个画调用链 |
| 4 落危害 | 真打一次，拿到数据/权限 | 零 | 自己跑，返回原文进证据 |

效率提升约 2–3 倍，风险从"审得慢"变成"报得错"。

**红队口径的差别只在一步**：第 4 步对安服是"证明危害、写进报告"，对红队是**"这条链能不能给我一个 shell"**。同一份审计笔记，多问这一句，就是 M3 的种子。

> 一个有用的重合点：**安服报告里定级最高的那几条（反序列化、组件 RCE、actuator 泄露凭据），恰好就是红队最想用的那几条。** 两者不冲突，红队只是要多走到"利用成功"。

### 3.4 Java 审计的够用线（不追求通）

1. **三层读法**：Controller → Service → Dao 能顺着调用跳（读得动代码的全部前提）
2. **认得 sink 族**：`Runtime.exec/ProcessBuilder`、`ObjectInputStream.readObject`、`JNDI lookup`、SQL 拼接、`File` 路径拼接、SpEL/OGNL
3. **认得出拦**：全局 Filter/Interceptor、参数化查询、白名单、权限注解
4. **组件指纹**：FastJson/Shiro/Log4j/actuator 版本与影响范围

到"能审"约 3–4 周。反射原理、链构造留到 M3。

> 现成资产：`Z-知识底座/代码审计/审计案例/` 的 WebGoat、**Tmall-Demo（Java）**、log4j2 三份全是截图，无一条结论。Tmall-Demo 就是现成靶子，重启它，把截图重做成五列：入口 / 调用链 / sink / 有没有拦 / 实测返回。

### 3.5 12 周排期

形态：**学习时间 = 项目时间**，不另挤 6h/周。

| 周 | 代码审计 | 内网 | 交付物 |
|---|---|---|---|
| W1–W2 | 读 Tmall-Demo 路由，AI 扫 sink，自己验 3 条可达链 | 243–247；VPC3 重建一次隧道，记录每次"不通"的判断 | 审计笔记 1 份 + 排障记录 1 份 |
| W3–W4 | 盲审一个模块（不看 writeup），出报告骨架 | VPC4 全程，只考核第 1 关 | 第一份可交付审计报告（脱敏） |
| W5–W6 | 把审计流程做成 skill（源码 → 候选 sink → 人工验 → 报告草稿），接进现有 MCP | 250–253；VPC5 补选型理由 | skill 跑通 + 横向选型表 |
| W7–W8 | 接第一个真实项目（结对），按 SOP 走 | 结对做一次真实内网 | 真实项目分工产出 |
| W9–W10 | 独立审 3–5 个模块 | 独立做内网单段（不给域控要求） | 独立交付 2 份报告 |
| W11–W12 | 复盘：漏了什么、误报几条、定级对不对 | 复盘：卡在第几关 | 一次交付复盘，进 `_项目/` |

**W12 验收**：这两类项目敢不敢不叫人在旁边就签字。敢 = M1 完成。

## 四、M2–M3 红队攻坚（2027-03 → 2027-12）

M1 之后，能力缺口变成这三个，**这才是小迪课真正的主场**：

| 阶段 | 目标 | 小迪天次 | 判据 |
|---|---|---|---|
| **M2 → V1** | 只给公司名，8 小时拿第一台内网主机的稳定控制 | 16–26（信息收集）· 195–208（提权）· 240–253（内网） | 自己打完，全程记录卡点 |
| **M3-a → V2 前半** | 域内深入：委派/RBCD/NTLM Relay/ADCS/ACL/GPO、权限维持 | 254–275 | 单域环境从普通用户到域管，讲清每跳为什么成立 |
| **M3-b → V2 后半** | C2 与基建、免杀入门 | 209–239（免杀）· 276–285（钓鱼/C2 隐匿） | 开 Defender/Sysmon 仍能上线 |
| **M3 验收 = V2** | 有 EDR 环境 24 小时到域管 | — | 按能力地图原表打勾 |

**M2 比你以为的近**：V1 需要的"信息收集 + Web 打点 + 落地 + 提权 + 稳定控制"，你已有前两项和落地，缺的提权与稳定控制正是 M1 内网四关的第 1、4 关。**M1 结束就在 V1 门口。**

**M3 才是真的一年**：免杀、C2、域内深入这三块没有捷径，且互相依赖（不会域就不知道 C2 要什么通道，不会免杀就过不了 EDR）。

## 六、AI 辅助交付的五条红线

前三条是你既有铁律在审计/内网场景的落地，后两条是新增：

1. **AI 说存在的漏洞，没实测不进报告。** 每条能指到一次真实返回。
2. **AI 给的 PoC 自己跑通看返回**，不看"应该返回什么"。它常基于错误的版本假设。
3. **"理论可利用"必须显式标注**，不许在摘要里升格成"可导致任意文件读取"。`摘要不得超出证据` 的直接应用。
4. **内网命令先判破坏性。** AI 会吐出 `net stop`、改注册表、删日志、重启服务；生产环境先问客户，测试环境先跑一遍。
5. **AI 不认客户的"红线资产"**（核心生产库）。它判断"可以打"不构成可以打的依据——范围只认合同和客户确认。

> 反过来，你的 `SEVERITY-RUBRIC.md`（只认已实证、摘要不得超出证据）本身就是借 AI 交付时最缺的质量门。别人的风险是信了 AI，你的规矩天然不允许。

## 七、兜底：能力不够时怎么把项目交出去

安服交付翻车的实际原因排序，从来不是"技术不会"：

| 风险 | 对策 |
|---|---|
| 范围漏了/超了 | 开工第一件事：范围写成一句话，回读给客户确认 |
| 证据不足 | 每个结论配一张原始报文/截图，当场存 |
| 定级虚高 | 按 `SEVERITY-RUBRIC.md` 三轴过一遍；答不出"这响应里有什么数据是对方不希望我看到的"就降级 |
| 复现不了 | 交付前自己按报告步骤复跑一次 |

**不会的地方**：收缩范围 + 明确边界。写"本次覆盖 X 模块，Y 模块因 ZZ 未覆盖"是专业；硬着头皮全覆盖然后一堆误报才是不专业。

## 八、两个待定

1. **本月是否有已排期的代码审计/内网项目？** 有 → 从 W7 切入，W1–W6 压成两周应急版（只补"连通"一关 + 审计四步法）。没有 → 按表走。
