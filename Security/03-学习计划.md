# 03 · 里程碑与年节奏

> **定位（2026-11-18 修订）**：攻防兼备的高级渗透测试工程师。详见 [[00-能力地图]] 的 Q1–Q5 验收与六域。
> **本文件只管"什么时候到什么程度"**；具体学什么、对应哪几节课，看 [[05-课程映射与学习顺序]]。
> 上一版把红队当终点、把安服当代价，已作废。**现在是同一份能力，两种交付强度。**

## 一、四个里程碑

```
M0 现状  →  M1 能独立交付  →  M2 能自己打穿  →  M3 能扛演练
 web已会      审计+内网+免杀    只给公司名       攻防演练主攻手
 2026-11      29 周（见 05）    2027-Q3         2028→
```

| 里程碑 | 判据（做不到不算到） | 时间 |
|---|---|---|
| **M0 现状** | Web 会，代码审计与内网不能独立 | 现在 |
| **M1 能独立交付** | 敢不叫人在旁边就签一份渗透报告 + 一份审计报告 | 29 周（S0–S7） |
| **M2 能自己打穿** | 只给一个公司名，8 小时拿到内网第一台主机的稳定控制 | 2027 Q3 |
| **M3 能扛演练** | 开 EDR 的环境里 24 小时到域管；报告被甲方一次通过 | 2028 → |

**M1 与 M2 不重复**：M1 是"按客户给的范围做完"，M2 是"自己找范围打穿"。差别在信息收集与打点那两段——M1 里客户已经告诉你打哪里。

**M3 不追求顶级**：到域管、能落地、不被当场拦下就够了。长期隐匿与对抗取证不在范围内。

## 二、AI 在这条路上是什么位置

不是工具课，是**每一段的收尾动作**。判据一句话：

> **AI 放大重复劳动与覆盖度，不放大判断。**

所以每完成一个阶段（S0–S7），必须把该阶段最耗时的重复动作变成 tool 或 SKILL.md，进 [[Security/工具链/00-索引|工具链]]。做不到这一条，那一段不算完成。

具体到每一段接什么活，见 [[00-能力地图]] 第四节；写规矩的五条红线见本文第六节。

## 三、M1 阶段（29 周，S0–S7）

### 3.1 客户给段的内网 ≠ 自己打穿的内网

| 环节 | 客户给段的项目 | 自己打穿 |
|---|---|---|
| 隐蔽性 | 不需要（客户陪同、可关 AV） | 要过防线 |
| 入口与凭据 | 常由客户给段/给跳板，弱口令即可 | 必须自己打出来 |
| 深度 | 指定目标机，1–3 跳 | 到域控 |
| 免杀 | 通常不做 | 要能落地 |
| 时间 | 1–3 天 | 24 小时连续 |
| 真实主要工作量 | **连通性排障** | 排障 + 规避告警 |

客户给段的那种只占后者的 40%，缺的 60% 是最难的部分。**但那 40% 正好是它的第 1–3 段**——所以 S6 先补连通，再谈域。

### 3.2 内网四关（这条线全押，不设取舍）

| 关 | 内容 | 现状 | 小迪天次（以课件目录为准） |
|---|---|---|---|
| 1 **连通** | 出网判断、隧道选型（ICMP/DNS/HTTP/SMB）、代理链、路由与防火墙 | **最弱，先补** | 243–247 |
| 2 收集 | 本机信息、凭据位置、BloodHound | 有操作，讲不清 | 248–249 |
| 3 横向 | IPC/PTH/PTT/委派/WMI/WinRM 的适用条件与痕迹 | 做过，说不出选型理由 | 250–253 |
| 4 提权 | Windows 令牌/特权/服务/DLL；数据库提权 | 自评 Q3 答错过 | 195–208 的 Windows 段 |

第 1 关是硬门槛：安服内网的卡壳绝大多数是"打下来了连不回来"或"给了段扫不通"。这关过了，后三关有工具和 AI 兜底就能交付；同时它也直接是自己打穿的第 3–5 段。

`_项目/靶场/内网打靶.md` 的 VPC3–5 不需要重写，**只补"当时为什么卡住、怎么排出来的"那几段**——排障经验是本阶段唯一必须自己攒、AI 给不了的东西。

### 3.3 代码审计：四步法，但口径要按红队改

安服审计拆开四步，AI 可用度差别极大：

| 步 | 动作 | AI 可用度 | 你的动作 |
|---|---|---|---|
| 1 定范围 | 列出入口（Controller/路由/接口） | 高 | 核对是否漏了未鉴权入口 |
| 2 找 sink | 危险函数、拼接、反序列化、文件操作 | 高（CodeQL/Semgrep + LLM 比人快） | 只做候选筛选，不下结论 |
| 3 **验可达** | 污点能否从入口走到 sink，中间有无拦 | **低（误报主要来源）** | **全部自己做**，逐个画调用链 |
| 4 落危害 | 真打一次，拿到数据/权限 | 零 | 自己跑，返回原文进证据 |

效率提升约 2–3 倍，风险从"审得慢"变成"报得错"。

**红队口径的差别只在一步**：第 4 步对安服是"证明危害、写进报告"，对红队是**"这条链能不能给我一个 shell"**。同一份审计笔记，多问这一句，就是 M3 的种子。

> 一个有用的重合点：**安服报告里定级最高的那几条（反序列化、组件 RCE、actuator 泄露凭据），恰好就是红队最想用的那几条。** 两者不冲突，红队只是要多走到"利用成功"。

### 3.4 Java 审计的够用线（不追求通）

1. **三层读法**：Controller → Service → Dao 能顺着调用跳（读得动代码的全部前提）
2. **认得 sink 族**：`Runtime.exec/ProcessBuilder`、`ObjectInputStream.readObject`、`JNDI lookup`、SQL 拼接、`File` 路径拼接、SpEL/OGNL
3. **认得出拦**：全局 Filter/Interceptor、参数化查询、白名单、权限注解
4. **组件指纹**：FastJson/Shiro/Log4j/actuator 版本与影响范围

到"能审"约 3–4 周。反射原理、链构造留到 M3。

> 现成资产：`Security/代码审计/Java/92-案例-Tmall-Demo`、`94-案例-log4j2` 与 `Security/_项目/靶场/WebGoat` 三份记录全是截图，无一条结论。Tmall-Demo 就是现成靶子，重启它，把截图重做成五列：入口 / 调用链 / sink / 有没有拦 / 实测返回。

## 四、M2–M3（2027 起）

M1 之后缺口只剩三个，**这才是小迪课真正的主场**：

| 阶段 | 目标 | 小迪天次 | 判据 |
|---|---|---|---|
| **M2** | 只给公司名，8 小时拿到内网第一台主机的稳定控制 | 16–26（信息收集）· 195–208（提权）· 240–253（内网） | 自己打完，全程记录卡点 |
| **M2 后半** | 域内：Kerberoasting → ACL → 一条委派或 ADCS 路径 | 254–263 | 单域环境从普通用户到域管，讲清每跳为什么成立 |
| **M3** | 免杀到能过 EDR、维持三类手法、C2 会用 | 209–239（免杀）· 大白哥 7·11 | 开 Defender + 一台 EDR 仍能上线并维持一次 |
| **M3 验收** | 演练强度：24 小时到域管 | — | 按 [[00-能力地图]] Q1–Q5 打勾 |

**M2 比你以为的近**：它需要的"信息收集 + Web 打点 + 落地 + 提权 + 稳定控制"，你已有前两项和落地，缺的提权与稳定控制正是 M1 内网四关的第 1、4 关。**M1 结束就在 M2 门口。**

**M3 才是真的一年**：免杀、维持、域内路径这三块没有捷径，且互相依赖（不会域就不知道 C2 要什么通道，不会免杀就过不了 EDR）。但**只到"能过、能维持、能到域管"**，不再往上（自研兵器、对抗取证都不做）。

## 六、AI 辅助交付的五条红线

**先定分工**：AI 出候选，人出结论。它可以替你跑完 200 个子域、读完 3 万行代码、写 8 版报告初稿；它不能替你判断"这条值多少钱、会不会把业务打挂"。

下面五条，前三条是你既有铁律在审计/内网场景的落地，后两条是新增——**建议直接写成 SKILL.md，不要指望每次自己想起来**：

1. **AI 说存在的漏洞，没实测不进报告。** 每条能指到一次真实返回。
2. **AI 给的 PoC 自己跑通看返回**，不看"应该返回什么"。它常基于错误的版本假设。
3. **"理论可利用"必须显式标注**，不许在摘要里升格成"可导致任意文件读取"。`摘要不得超出证据` 的直接应用。
4. **内网命令先判破坏性。** AI 会吐出 `net stop`、改注册表、删日志、重启服务；生产环境先问客户，测试环境先跑一遍。
5. **AI 不认客户的"红线资产"**（核心生产库）。它判断"可以打"不构成可以打的依据——范围只认合同和客户确认。

> 反过来，你的 `SEVERITY-RUBRIC.md`（只认已实证、摘要不得超出证据）本身就是借 AI 交付时最缺的质量门。别人的风险是信了 AI，你的规矩天然不允许。

## 七、兜底：能力不够时怎么把项目交出去

安服交付翻车的实际原因排序，从来不是"技术不会"：

| 风险 | 对策 |
|---|---|
| 范围漏了/超了 | 开工第一件事：范围写成一句话，回读给客户确认 |
| 证据不足 | 每个结论配一张原始报文/截图，当场存 |
| 定级虚高 | 按 `SEVERITY-RUBRIC.md` 三轴过一遍；答不出"这响应里有什么数据是对方不希望我看到的"就降级 |
| 复现不了 | 交付前自己按报告步骤复跑一次 |

**不会的地方**：收缩范围 + 明确边界。写"本次覆盖 X 模块，Y 模块因 ZZ 未覆盖"是专业；硬着头皮全覆盖然后一堆误报才是不专业。
