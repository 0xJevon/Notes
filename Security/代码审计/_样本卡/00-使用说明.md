# 样本卡 · 使用说明

> **一张卡 = 一次判定，不是一次阅读。** 卡的价值不在“记录了哪个洞”，而在“第 7 节：我当时怎么判的、错在哪”。
> 模板：`_模板/样本卡-新建.md`；索引：[[Security/代码审计/00-索引|代码审计索引]]；上位：[[Security/10-安服代审能力地图|安服代审能力地图]]。

---

## 一、什么时候建卡

满足任意一条就建：

1. 跟通了一条 `入口 → sink` 的链（无论成不成立）；
2. 判错了一次（把不成立当成立、或把成立漏了）；
3. 同一 sink 出现第二个入口，需要判断是否同根因；
4. 组件类结论（版本→前置→入口）走完三步。

**不建卡的情况**：只有截图没有结论、只有工具输出没有判定、抄来的步骤（G16）。

---

## 二、命名与编号

- `S-001-简短标题.md`，标题写“目标 + 现象”，如 `S-003-MCMS-cms-content-list-sqlWhere.md`。
- 编号只增不减；删卡留号不复用。
- 同一条链的后续复测，在原卡追加“复测”小节，不另开新号。

---

## 三、必填字段（frontmatter）

```yaml
type: 样本卡
target: <项目名/靶场>
entry: <方法 + 路径>
sink: <命令执行/SQL/上传/...>
verdict: 成立 | 被拦 | 误判 | 未定
status: 未实测 | 已实测
created: YYYY-MM-DD
tags: [代码审计, <sink类>]
```

`status` 只由实测改写；没有 `Security/_证据/` 原文的，只能是 `未实测`。

---

## 四、六节内容 + 第 7 节

1. **入口**：方法、路径、参数、鉴权结论，全部带 `文件:行号`；
2. **链**：逐跳表格（跳次 / 位置 / 变量 / 变换 / 可控性 / 结论）；
3. **sink**：危险调用 + 成立条件 + “缺什么就不成立”；
4. **拦截**：过滤器/参数化/白名单，写“挡得住/挡不住”及依据行号；
5. **实测**：链接到 `_证据/` 的原文；没有就写“未实测”；
6. **红队口径**：能不能变成执行权限，下一步是提权还是横向（一句话）；
7. **判定记录（必须本人写）**：我最初判成什么 → 实际是什么 → 错在哪 → 下次先看哪一行。

> 第 7 节是这张卡唯一不能被 AI 代写的部分（[[_通用/06-AI写库协议|AI 写库协议]] 禁止档）。

---

## 五、挂索引与周配额

- 每张卡必须挂到**所属语言线索引**的对应条目（[[Security/代码审计/Java/00-索引|Java]] / [[Security/代码审计/PHP/00-索引|PHP]] / [[Security/代码审计/NET/00-索引|.NET]]），并回填覆盖状态。
- `sink:` 字段取统一词表，便于按类检索：`命令执行` / `代码执行` / `SQL` / `文件读` / `文件写` / `文件上传` / `解压穿越` / `SSRF` / `XXE` / `模板注入` / `反序列化前置` / `鉴权`。
- 卡类型只有四种：样本卡 `S-`、入口卡 `E-`、判定卡 `J-`、组件卡 `C-`（见 [[Security/代码审计/00-索引|总索引]] §四）。
- 周配额：**4 张样本卡 + 1 张判定卡 + 1 份证据**。
- 连续两周少于 4 张 → 本目录视为“预建负债”，暂停新建，先补卡或回退目录（总纲：没开始做的事不建目录）。

## 六、AI 能做什么

| 可以做 | 不能做 |
|---|---|
| 套模板、查缺列、修链接、更新索引 | 写“我的猜测”与结论 |
| 按五列逐列问“这列空着，依据在哪” | 判断“这条成不成立” |
| 给结论出反例，逼出失效条件 | 代写第 7 节 |
| 把原始输出搬进 `_证据/`（不改写） | 把截图/文章步骤概括成“经验” |

细节见 [[_通用/06-AI写库协议|AI 写库协议]]。
