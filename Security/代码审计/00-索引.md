# 代码审计 · 00 索引

> **一句话**：代码审计是**跟踪代码**——给定一套源码，判断"有没有洞、在哪一行、怎么证明"。它不负责造链，那是 [[Security/Java安全/00-索引|Java 安全]] 的事。
> 上位：[[Security/10-安服代审能力地图]]（A1–A4 验收）· [[Security/11-安服代审学习计划]]（6 周）· [[Security/04-双线能力线]]（线规则）。

---

## 一、先分清两件事（分错就会白学）

| | **代码审计**（本目录） | **Java 安全**（[[Security/Java安全/00-索引\|独立目录]]） |
|---|---|---|
| 问题 | 这套系统有没有洞、在哪个入口、能不能验证 | 这个机制能不能被打、链怎么造 |
| 动作 | 从入口跟到 sink，判拦截，出复现包 | 从 gadget 推到触发点，写利用 |
| 对象 | **一套别人的业务系统** | **一个机制或组件**（反射、CC、JNDI、Fastjson） |
| 产物 | 样本卡 + 判定卡 + 证据 | 链路图 + 本地复现环境 |
| 本线做不做 | 做，且是当前主线 | **判前置时查，链构造留红队 M3** |

**这条界线的依据**：Java 安全 = 研究代码（反序列化、CC 链、Fastjson/Shiro 原理）；Java 代码审计 = 跟踪代码（SQL 注入、文件上传、SSRF、鉴权）。两者互相促进，但**学习形态完全不同**——前者可切碎读，后者必须整块跟源码。

框架与架构（Servlet、SpringBoot、MVC、Maven）**归本目录**，不归 Java 安全：它们回答"这套系统的入口长什么样"，是审计的第 0 步。

## 四、样本卡（唯一硬产物）

| 类型 | 编号 | 放哪 | 规则 |
|---|---|---|---|
| 样本卡 | `S-001-标题` | `_样本卡/` | 一条链一张，五列齐全（入口/链/sink/拦截/实测） |
| 入口卡 | `E-001-平台-框架` | `_样本卡/` | 一套系统一张，回答"路由从哪来" |
| 判定卡 | `J-001-主题` | `_样本卡/` | 一个判断一张（如"这个 Filter 是否真拦得住"） |
| 组件卡 | `C-001-组件` | `_样本卡/` | 版本 → 前置 → 可控入口，三步写全 |
