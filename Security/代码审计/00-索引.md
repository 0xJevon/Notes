# 代码审计 · 00 索引

> **一句话**：代码审计是**跟踪代码**——给定一套源码，判断"有没有洞、在哪一行、怎么证明"。它不负责造链，那是 [[Security/Java安全/00-索引|Java 安全]] 的事。
> 骨架来源：小迪安全 V2024-11 第 155–184 天（PHP 155-166 / .NET 167-169 / JavaEE 170-184）。四类形态与八条章节点取自原文，判据是我按审计动作补的。
> 上位：[[Security/10-安服代审能力地图]] · [[Security/11-安服代审学习计划]] · [[Security/04-双线能力线]]。

## 一、与 Java 安全的分界（分错，两边都白学）

| | **代码审计**（本目录） | **Java 安全**（[[Security/Java安全/00-索引\|独立目录]]） |
|---|---|---|
| 问题 | 这套系统有没有洞、在哪个入口、能不能验证 | 这个机制能不能被打、链怎么造 |
| 动作 | 从入口跟到 sink，判拦截，出复现包 | 从 gadget 推到触发点，写利用 |
| 对象 | **一套别人的业务系统** | **一个机制或组件**（反射、CC、JNDI、Fastjson） |
| 产物 | 样本卡 + 判定卡 + 证据 | 链路图 + 本地复现环境 |
| 本线做不做 | 做，且是当前主线 | 判前置时查，链构造留红队 M3 |

**同一个组件会有两份文件，不许互相抄**：本目录的组件单元回答"项目里引了哪个版本、有没有用不安全写法、从哪个入口能触达"；Java 安全那篇回答"这条链怎么接、JDK 版本卡在哪"。前后是"判可达"与"会利用"的关系。

## 二、四类开发形态（决定用什么眼光看这套源码）

四类名称取自小迪原文，判据是我按"第一眼该看什么"补的。

| 形态 | 判据（第一眼看哪） | 典型洞 | 落在本库 |
|---|---|---|---|
| **原生态** | 无统一入口，文件即路由；SQL 直接拼在页面里 | 注入、上传、任意文件读写、变量覆盖 | PHP 01-02 · .NET 01-02 · Java 06-07 |
| **框架类** | 单入口 + 路由表 + ORM/模板引擎 | 路由越权、SSTI、框架反序列化、不安全写法 | Java 03-05 · PHP 03-08 |
| **组件类** | `composer.json` / `pom.xml` / `packages.config` 里有一堆三方包或整套产品 | 版本 1day、危险默认配置、组件反序列化 | Java 15-16-18 |
| **前端类** | 模板直出 或 前后端分离（前端只调 API） | SSTI、XSS、加密逆向 | Java 14 · PHP 10 · [[Security/代码审计/JS/00-索引\|JS 线]] |

**审计顺序（小迪"教学计划"那条，跨语言不变）**：漏洞原理 → 审计思路 → 完整源码 → 应用框架 → 验证并利用。
**挖洞的根本（同一份简要点）**：可控变量 × 特定函数 × 不存在过滤或过滤不严谨。这三件套的清单在 [[20-漏洞清单与挖掘思路]]。
