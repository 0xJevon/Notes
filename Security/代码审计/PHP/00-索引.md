## 二、接 PHP 项目先答的问题

| # | 问题 | 在哪看 | 现状 |
|---|---|---|---|
| 1 | 单入口还是文件即路由 | 有无 `index.php` + `.htaccess`/nginx `rewrite`；还是每个功能一个 `.php` | 待建 |
| 2 | 用的是不是框架 | `composer.json`、`vendor/`、`think`/`laravel` 目录特征 | 只有 ThinkPHP 一条 |
| 3 | 危险函数落在哪些文件 | 全局搜 20 篇的关键词表 | 有表，无项目验证 |
| 4 | 文件包含有没有被控制 | `include`/`require` + 变量；`allow_url_include` | **空白** |
| 5 | 反序列化入口 | `unserialize(`、`__wakeup`/`__destruct`/`__toString` | **空白**（Java 安全那套链不通用） |
| 6 | 上传落点能不能控 | `move_uploaded_file` 的第二参数、后缀校验位置 | 有函数名，无判定 |

**1、4、5 是本线最大的三个空白**，也是 PHP 项目和 Java 差别最大的三处——不能拿 Java 的思路套。

## 三、开线时要产出的东西

1. 一张 **PHP 入口建模卡**（`E-xxx`）：单入口/多入口、路由规则、伪静态。
2. 一张 **危险函数 → 可利用条件** 判定卡（`J-xxx`）：每个函数写清"参数可控 + 无过滤 + 有回显/可带外"三件。
3. 至少 3 张样本卡：文件包含、上传、SQL 拼接各一。

模板与编号规则见 [[Security/代码审计/00-索引|总索引]] §四。

## 四、不做的

- 不抄函数大全（`php.net` 能查的，不入库）。
- 不建 CVE 清单；只对项目里**真实出现**的版本做匹配。
- 不在没有项目时预写"PHP 审计教程"。
