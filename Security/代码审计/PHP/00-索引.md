## 二、判形态：接 PHP 项目先答六问

| # | 问题 | 在哪看 | 落在哪单元 |
|---|---|---|---|
| 1 | 单入口还是文件即路由 | 有无 `index.php` + `.htaccess`/nginx `rewrite`；还是每个功能一个 `.php` | 原生 vs MVC 分界 |
| 2 | 用的什么框架 | `composer.json`、`vendor/`、`think`/`laravel`/Yii 目录特征 | 06 或 11 或 12 |
| 3 | 危险函数落在哪些文件 | 全局搜 [[20-漏洞清单与挖掘思路]] 的关键词表 | 01 / 02 |
| 4 | 文件包含能不能被控 | `include`/`require` + 变量；`allow_url_include` | 02 / 08 |
| 5 | 反序列化入口在哪 | `unserialize(`、`__wakeup`/`__destruct`/`__toString`、Phar 读取点 | 05 / 07 |
| 6 | 上传落点能不能控 | `move_uploaded_file` 第二参数、后缀校验位置 | 02 |

**1、4、5 是与 Java 差别最大的三处**：PHP 的"入口"常是一个文件而不是一个路由；文件包含是 Java 没有的独立洞类；反序列化靠 `__destruct` 自动触发而不是 `readObject`。不能拿 Java 的思路套。

## 三、开线时先产出三样

1. **PHP 入口建模卡**（`E-xxx`）：单入口/多入口、伪静态规则、控制器定位方式。
2. **危险函数 × 可利用条件** 判定卡（`J-xxx`）：每个函数写清"参数可控 + 无过滤 + 有回显或可带外"三件。
3. 至少 3 张样本卡：文件包含、上传、SQL 拼接各一。

编号与模板见 [[Security/代码审计/00-索引|总索引]] 第五节。

## 四、不做的

- 不抄函数大全（`php.net` 能查的不入库）。
- 不建 CVE 清单；只对项目里**真实出现**的版本做匹配。
- 没有项目时，不预写"PHP 审计教程"——骨架留在这里，等真源码。
