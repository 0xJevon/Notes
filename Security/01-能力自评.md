# 01 · 能力自评（起点诊断）

> 目的不是考你，是**定位起点**。答错比答对有用——错的地方才是要花时间的地方。

1. **不许查资料、不许问 AI、不许开靶场。** 想到什么写什么。

### Q1 · 落地之后 `C 执行与驻留`

你刚通过一个文件上传点拿到了 Windows Server 2012 的 webshell（PHP 环境，权限是 IIS 应用池账号）。
**进机器后的头 10 分钟，你会敲哪些命令？按顺序写，并说清为什么是这个顺序。**

> 我的回答：先通过whoami确认已经获得的主机权限，以此判断是否需要提权以方便后续的横向渗透，然后使用net user /domain 命令看主机是否处于域环境中，如果是则要进行后续的域渗透，然后命令我想不起来了，但一般操作应该是看能否与外网通信，然后上传免杀的隧道建立攻击机与受控机的直接通信方便后续的内网信息收集，或者直接上传fscan进行内网扫描，然后是通过impacket或mimikatz进行横向渗透如pth、ptk等，或是扫描出来的其他服务如smb之类的同样可以用于横向渗透，但具体做法和命令确实还需要在靶场中实践。

> 反馈：**判定 = 经验归纳（顺序是"工具驱动"而非"信息驱动"）**

方向对：确认权限 → 判断域环境 → 建通道 → 扫描 → 横向，这条主干没错。但顺序里藏了两个问题。

**问题一：`whoami` 不是第一步，`whoami /all` 才是。** 差一个 `/all`，丢掉的是 privileges 和 groups——而这两项直接决定"能不能提权、走哪条提权路"。只看到 `iis apppool\xxx` 这个结论，等于白看。

**问题二（主要问题）：你把"横向"当成了默认下一步，跳过了"我在哪"。** 内网渗透的第一步不是找路，是**定位**。缺的动作按优先级：

| 动作 | 为什么要先做 |
|---|---|
| `ipconfig /all` + `route print` + `arp -a` | 不看网卡，你不知道自己在哪个网段、有几张网卡。**多网卡 = 你可能站在跳板上**，这决定后续往哪走 |
| `netstat -ano` | 这台机器正在跟谁通信？有没有连内网数据库、有没有连域控。**这是现成的内网拓扑** |
| `systeminfo` | 补丁级别决定能不能用本地提权 exp，比盲试快十倍 |
| `tasklist /svc` | 有什么杀软、什么业务、什么账号在跑 |
| **翻配置文件** | ⚠️ 你完全没提，这是最大遗漏，见下 |

**问题三：`net user /domain` 用早了，而且可能报错。** 在非域机器或域不可达时会直接失败。更早的信号：`systeminfo | findstr /i domain` 或 `echo %userdomain%`——先确认"是不是域"，再决定要不要用域命令。

**最大遗漏：读配置文件拿凭据。** 这是内网渗透投入产出比最高的一步，比抓 lsass 高得多。IIS 的 `web.config`、数据库连接串、计划任务里的脚本、`ConsoleHost_history.txt`——**这些是明文凭据，不需要任何工具，不触发任何告警**。你直接从"建隧道、上 fscan"开始，等于放着抽屉里的钥匙不用，去撬保险柜。

**该补什么**：见 `C-执行与驻留/落地后前10分钟-自查清单.md`（只给问题不给答案，打靶时自己填）。

### Q2 · 能不能活过重启 `C 执行与驻留`

这台机器明天凌晨会重启。
**你的 webshell 还在吗？如果不在，你怎么做持久化？哪些持久化手法在装了 Defender 的机器上会当场死？**

> 我的回答：这里我不太理解机器重启和webshell是否存在的关系是什么，webshell是作为文件落地到目标机器的，哪怕机器重启导致网站服务更新应该也不会影响webshell的存在，但假设不在了我首先会做的持久化还是创建隐藏账户，可以直接再次登录，然后其他的持久化方法就有点想不出来了

> 反馈：**判定 = 结论对、深度不足（但你质疑题目前提这件事加分）**

**核心判断你是对的**：PHP webshell 是文件，重启不删文件。你反过来质疑题目——这个习惯要保持，比答对更值钱。出题人（我）故意埋了这个坑。

但真正该问的不是"重启会不会删文件"，而是——**这个 webshell 靠什么活着？**

它依赖三件事，任何一件变了自己就死：

1. **文件还在**（重启不影响，但 **Defender 的例行扫描会删**——冰蝎/菜刀的默认特征全世界都知道）
2. **Web 服务在跑**（重启后 IIS 会起来，通常没事）
3. **执行权限还在**（应用池账号没被改）

**真正的例外是内存马**：如果你是通过漏洞把代码注入到 `w3wp.exe` 进程里（而不是落地文件），**重启 = 进程重建 = 马没了**。这是"重启"真正会杀死的东西。

**持久化部分你答得太薄**，而且隐藏账户这个选择要打个问号：
- 隐藏账户（`net user xxx$ /passwd`）不算"当场死"，但它是**低质量持久化**：需要 RDP/登录才能用，暴露面大，且 EDR 对 `net user /add` 有告警
- 该知道的层次（按隐蔽性排）：**WMI 事件订阅**（不落地文件）> **DLL 劫持 / 白加黑** > **计划任务**（可伪装成系统任务）> **服务**（`sc create`，最经典但最容易被看）> **注册表 Run 键**（最显眼）
- **在装了 Defender 的机器上"当场死"的**：`sc create` 一个名字可疑的服务、Run 键里直接写 `powershell -enc`、带已知特征的服务二进制

**该补什么**：这题的核心认知是「**webshell 的存活不取决于重启，取决于它依赖的三件事是否还在**」。记住这个框架，比记十种持久化手法有用。

### Q3 · 提权的前提条件 `D 提权`

`whoami /priv` 输出里有 `SeImpersonatePrivilege`。
**列出你知道的利用方式，每一种都写清前提条件**（不要只写工具名，要写"什么情况下这个工具能用"）。

> 我的回答：这个不太会，只知道Linux系统中可以使用漏洞提权如脏牛也就是内核漏洞，或者是SUID提权，找到拥有SUID权限的文件，也就是可以执行root用户权限的特殊文件以此来提权，或者是使用定时任务，也有点类似suid提权，只不过是把反弹shell命令写入了定时文件中，大概就能想出来这么多

> 反馈：**判定 = 真实缺口（且暴露结构性问题）**

**你答的不是"不会"，是"答了另一个系统"。** 题目问 Windows 特权，你答脏牛、SUID、定时任务——全是 Linux。

这个偏科比答错更值得警惕：**你的知识栈是 Linux + Web 单一栈，一进 Windows 就断。** 而"高级红队"的主战场恰好是 Windows 域环境。这不是补一个知识点能解决的，是要补一整套平台认知。

**先给结论对的部分**：Linux 那三条（内核漏洞 / SUID / 定时任务）描述准确，说明你不是没基础，是没换过平台。

**SeImpersonatePrivilege 是什么**：
- 这个特权允许进程「**模拟**」另一个用户的令牌——说白了，**让你能"变成"别人**
- **谁默认有它**：IIS 应用池、SQL Server 服务账号、以及所有服务账号。**普通用户没有**——这个前提是第一道门，很多人不知道
- 有它 ≠ 能提权。还需要一个**能强制 SYSTEM 向你认证的通道**

**利用的本质是一条链**：

```
强制高权限进程（SYSTEM）向"我控制的通道"认证
        ↓
我从这个认证过程中拿到 SYSTEM 的令牌
        ↓
模拟它 → 我就是 SYSTEM
```

**Potato 家族全部是这个原理的不同"通道"实现**：

| 工具 | 用的通道 | 前提（这才是重点） |
|---|---|---|
| Juicy Potato | COM/DCOM | **Windows 2016 及以下**。2019/2022 已修，直接用会失败 |
| Rogue Potato | RPC | 需要能控制 RPC 连接 |
| PrintSpoofer | 打印后台（Spooler） | **2019+ 可用**，但**前提是 Spooler 服务开着** |
| GodPotato | RPC/多通道 | 覆盖面广，但依赖系统版本 |

**什么情况下这套全部失效**：2019+ 且 Spooler 被禁用 + RPC 补丁已打 → 换路（令牌窃取、服务配置错误、AlwaysInstallElevated）。

**该补什么**：不要背工具名，背**判据**——「**我需要一个能强制 SYSTEM 向我认证的通道**」。有通道 → 能提权；没通道 → 换别的路。工具只是通道的实现。

### Q4 · Hash 能干什么 `D 提权 / E 横向`

你从 lsass 里抓到一个本地管理员的 **NTLM hash**，没有明文密码。
**这个 hash 能直接 RDP 登录吗？能用来做什么、不能用来做什么？为什么？**

> 我的回答：hash是加了密的自然不能直接用于RDP登录，但可用于横向移动也就是PTH，因为kerberos或者是其他的三方检查机构有点记不到了检查用户凭证并不直接比对明文密码而是比对凭证与已保存的凭证是否对应，所以可以通过截获的hash伪造用户身份访问其他服务

> 反馈：**判定 = 结论对、理由混淆（记忆污染边缘，需纠正）**

**结论是对的**：不能直接 RDP，可用于 PTH。

**但理由里有三处要修**：

**一、"hash 是加了密的"——这个理解要改。** NTLM hash 不是"加密的密码"，它是密码的 **MD5(MD4)** 摘要，**不可逆**。关键点在于：**NTLM 认证从来不需要明文密码**。认证过程是挑战/响应——服务端发一个随机挑战，客户端用 hash 计算响应，服务端用自己存的 hash 验证。**所以只要有 hash，你就能算出正确响应**。这才是 PTH 成立的根本，不是"伪造身份"这种模糊说法。

**二、把 NTLM 和 Kerberos 混在一起了。** 你说"kerberos 或第三方检查机构"——NTLM 和 Kerberos 是两套完全不同的认证协议：
- **NTLM**：挑战/响应，直接用 hash → 这就是 PTH
- **Kerberos**：票据体系，用 hash 换票据 → 叫 **Over-Pass-The-Hash**，是另一回事

**三、RDP 为什么不行——真正的原因不是"hash 加密了"**，而是 **RDP 在 NTLM 之上还要建立交互式登录会话**，这需要能还原成凭据的密码（CredSSP/Kerberos 路径），NTLM hash 转不过去。
- **例外**：目标开了 **Restricted Admin 模式**（Win 8.1+/2012R2+），PTH 可以直接打 RDP。这个例外要知道。

**能做什么（你没答全，这是关键）**：
- PTH 打 SMB → `psexec` / `wmiexec` / `smbexec`
- PTH 打 WMI
- Over-Pass-The-Hash：用 hash 换 Kerberos 票据，然后"正常地"用 Kerberos 访问
- 打 MSSQL / LDAP（未强制签名时）

**最重要的一个盲点**：你抓的是**本地管理员**的 hash。本地账号在域内**不通用**——这个 hash 只能 PTH 到「**同样用这个本地管理员密码的其他机器**」。
> 新手常犯的错：以为拿到本地管理员 hash 就能横着走。实际上，**除非这个密码被复用过（内网很常见），否则它出不了这台机器。**

**该补什么**：见 `_问题库/Windows上凭据藏在哪.md`。

### Q5 · 横向手法的痕迹差异 `E 横向移动`

psexec、wmiexec、winrm 三个横向手法。
**从「落地文件」和「日志记录」两个角度，说它们的差异。你会优先用哪个，为什么？**

> 我的回答：应该都需要落地impacket组件来进行横向移动吧，但是具体细节就不清楚了

> 反馈：**判定 = 工具使用者（且有一个必须先纠正的错误前提）**

**先纠正那个错误前提：「都要落地 impacket 组件」——不成立。**

impacket 是**装在你攻击机上的 Python 工具集**，它不上目标。落地到目标的是它**上传过去的文件**，而且三个手法在这一点上差异巨大——这恰好就是你被问的东西：

| | 落地文件 | 关键日志 |
|---|---|---|
| **psexec** | ✅ 上传 `PSEXESVC.exe` 到 `ADMIN$`，注册服务执行 | **7045（服务安装）+ 4624 Type 3**，服务名 `PSEXESVC` 是硬指纹 |
| **wmiexec** | ❌ 不落地 exe（只写临时输出文件） | **4688（进程创建）** + `Microsoft-Windows-WMI-Activity/Operational` |
| **winrm** | ❌ 完全不落地 | 4624 Type 3 + WinRM Operational + **4104（PowerShell 脚本块）** |

**优先用哪个——没有绝对答案，取决于对方看什么**：
- 有 EDR 盯进程树 → **winrm**（不落地，进程树干净）
- 只有 Windows 日志、没人看 WMI → **wmiexec**（不留服务）
- 目标禁 WinRM、又必须走 SMB → **psexec 兜底，但它最吵**（7045 太显眼）

**这题真正考的是**：你能不能把"手法"和"它留下的痕迹"对上号。**免杀的尽头是不产生痕迹，而不是把痕迹藏起来。**

**该补什么**：见 `_问题库/横向三兄弟的痕迹差异.md`。

### Q6 · 域内最短路径 `F 域渗透`

你现在有域内一台普通工作站的**本地管理员**权限（不是域管）。目标是域控。
**你脑子里第一条路径是什么？这条路径上最可能卡在哪一步？**

> 我的回答：首先要定位域控，然后收集域控信息，最好是有能直接利用的漏洞，不行就看能否通过PTH或者psexec等其他横向手法移动，或者应该还能通过约束委派进行移动，内网渗透最容易卡住的还是易被杀软察觉，然后就是配置不满足横向移动的前提

> 反馈：**判定 = 框架有、顺序错（外网思维的惯性）**

你有框架感（定位 → 收集 → 利用 → 横向），还提到了约束委派，说明资料看过。但**这条路径是"盲目枚举"，不是"基于信息"**，而且跳过了一整个环节。

**你跳过的环节：抓凭据。** 你从"定位域控"直接跳到"找漏洞/PTH"。但你现在是**本地管理员**——这意味着你能读 lsass，能拿到**这台机器上所有登录过的人的 hash**，其中可能就有域管。

正确的第一问不是"域控在哪"，是——**这台机器上有没有域管登录过？**

有 → 直接拿域管 hash → 结束。不需要任何漏洞，不需要任何横向。
没有 → 再问第二个问题：**本地管理员组里有没有域账号？**

**这是内网渗透最根本的思维转变**：

> **外网是找洞，内网是找人。**
> 外网打的是程序（有 bug 的程序），内网打的是人（会登录、会复用密码、会被加进组的人）。

你现在的路径全程在"找洞"，这是外网惯性的延续。

**你说会卡在"杀软"和"配置不满足"**——判断方向对，但太笼统。真实卡点通常是：**你不知道下一步该问什么信息**。信息问对了，路自己会出来。

**最短路径的正确顺序**：
1. **抓本机凭据**（lsass / 配置文件 / 浏览器 / 计划任务）
2. 有域管 → 直接用
3. 没有 → 枚举「谁能登录这台机器」（`Get-LocalGroupMember Administrators`，看有没有域账号）+ `nltest /dclist:` 找域控
4. **找 ACL 可写**（BloodHound：这个用户/这台机器对谁有 GenericAll / WriteDACL）—— 最容易被忽略的高价值路径
5. Kerberoast / AS-REP（需要一个普通域用户身份）→ 离线爆破
6. **最后**才是找漏洞

**约束委派补充一句**：它不是你随时能用的手法，前提是**你先控制了一台被配置了约束委派的机器或服务账号**。所以它是"发现了才能用"，不是"想到了就能用"。

### Q7 · Kerberos 的触发条件 `F 域渗透`

**Kerberoasting 和 AS-REP Roasting，触发条件有什么不同？什么样的账号配置分别会成为目标？**

> 我的回答：我知道这两个应该都是密码喷洒的利用，但确实内网渗透相关经验较少，所以不太清楚

> 反馈：**判定 = 记忆污染（优先级最高，必须立刻纠正）**

**「都是密码喷洒」这句是错的，而且错得会导致实战出事。** 这两者跟密码喷洒是**完全相反**的东西：

| | 密码喷洒 | Kerberoasting / AS-REP |
|---|---|---|
| 在哪做 | **在线**，直连目标反复试 | **离线**，拿回 hash 在自己机器上爆破 |
| 日志 | **大量 4625（登录失败）** | **没有失败登录** |
| 会不会被抓 | **极容易**（4625 是 SOC 最基础的告警） | 几乎没有失败记录，只留正常的票据请求 |

把它们混为一谈的后果很具体：**你以为在"离线"，实际在"在线"，直接触发告警。**

**两者的真实区别**：

|      | **Kerberoasting**                  | **AS-REP Roasting**                          |
| ---- | ---------------------------------- | -------------------------------------------- |
| 前提   | **有任意一个域账号**（普通用户即可）               | 目标账号**关闭了 Kerberos 预认证**（`DONT_REQ_PREAUTH`） |
| 目标特征 | **有 SPN 的服务账号**（SQL、IIS、备份服务等）     | 该标志位被勾选的账号（多因配置失误或老应用需求）                     |
| 拿到什么 | 用该服务账号 hash 加密的 **TGS 票据**         | 用该账号 hash 加密的 **AS-REP**                     |
| 关键日志 | **4769**（TGS 请求，etype 0x17/RC4 可疑） | **4768**（预认证未启用）                             |
| 可怕之处 | **不需要任何特权**，一个普通域用户就能打全部服务账号       | **甚至不需要有效账号**，知道用户名就行                        |

**为什么这两个是域渗透的入门必修**：它们是「**不需要提权就能拿到高价值凭据**」的少数路径之一。一个普通域用户，一次请求，拿回 hash，离线慢慢爆——全程不碰任何敏感操作。

**该补什么**：见 `_问题库/Kerberoasting凭什么不需要特权.md`。

### Q8 · 流量最先暴露在哪 `G C2 与基建`

假设你自己写一个 beacon 回连 VPS。客户端环境是：NGFW + 全流量分析 + EDR 三层都在。
**你判断最先暴露的是哪一层——协议特征、证书、心跳周期、还是进程行为？为什么？**

> 我的回答：完全没搭建过红队基建

> 反馈：**判定 = 真实缺口（但你有一个别人没有的入口）**

诚实标注，有效信息。G 域确实是从零开始。

**先给答案**：最先暴露的是**心跳周期**，不是协议、不是证书。

理由是其余三项都能被伪装，唯独周期性是行为指纹：
- **协议特征** → 走标准 HTTPS 443，流量看起来就是浏览网页
- **证书** → 用合法 CA 签的域名证书，或直接蹭 CDN
- **进程行为** → 注入到 `svchost.exe` 里，看起来是系统进程
- **但心跳**：每 60 秒一次、每次固定几百字节、响应体大小几乎不变——**全流量分析做时序分析，这个规律性一眼就看出来**

**你的隐藏优势**：你每天都在看防火墙日志和告警。别人要买设备、搭环境才能获得的视角，**你上班就在看**。

所以 G 域该反过来做：不要先学怎么搭 C2，而是**先翻你自己的告警数据，回答一个问题——"什么样的流量，我不会抓它？"** 从防守侧的盲区反推攻击侧的设计，这是你比纯红队出身的人快的地方。

**该补什么**：这个域暂不开启（按地图的触发条件：需要"从外网连回内网"时才建）。但**现在就可以攒素材**：日常告警里遇到的 C2 流量，把特征记进 `_证据/`。

### Q9 · 免杀的排序 `H 对抗与免杀`

mimikatz 原始 exe 一落地就被杀。
**你能想到几种绕过思路？按「成功率从高到低」排，每种写清前提。**

> 我的回答：我还有印象的免杀应该就是白加黑，代码混淆之类的，成功率上单一方法都容易被杀软抓住特征，应该还是要混合方法才不易被察觉吧

> 反馈：**判定 = 方向对、层级混乱**

**"混合优于单一"这个直觉是对的**，而且是很重要的直觉。但白加黑和代码混淆**不在一个层级**，没法排序——它们解决的是不同的检测手段。

**免杀必须先看清"你在躲什么"**，按检测手段分层：

| 层 | 杀软在查什么 | 绕过手段 |
|---|---|---|
| 1. 静态特征 | 文件 hash、字符串、导入表 | 字符串加密、API 动态解析、加壳 |
| 2. 签名 | 无签名 / 黑签名 | **白加黑**、窃取签名、LOLBin |
| 3. 行为 | API 调用序列、进程树 | 内存加载（不落地）、直接系统调用（syscall）、unhooking |
| 4. 内存扫描 | EDR 扫 lsass 读取行为 | 换手法：**不读 lsass** |
| 5. 网络 | C2 特征 | 走合法服务 |

白加黑在**第 2 层**，代码混淆在**第 1 层**。正确的说法不是"哪个成功率高"，而是"**你的目标环境在哪一层设了检测，就往别的层走**"。

**最重要的一课**：**mimikatz 原始 exe 的问题不是"没混淆"，是"全世界都知道它长什么样"。**

所以正确思路不是"想办法混淆 mimikatz"，而是——**根本不用 mimikatz**：

```
用 comsvcs.dll 的 MiniDump 把 lsass 内存 dump 出来
        ↓
下载回本地
        ↓
在本地（无杀软）用 mimikatz 解析
```

**目标机上从头到尾没有 mimikatz**，没有可查的特征。

> **免杀的最高境界，是不让杀软有机会看到你**——不是把特征藏得更深。

### Q10 · 同一个洞，两种报告口径 `I 目标达成与报告`

安服报告里，一个能拖库的 SQL 注入通常是"高危"。
**同样这个注入，放在红队报告里，你定什么级？为什么？**

> 我的回答：红队的评价标准是数据和权限，如果被拖库的数据库包含大量个人敏感信息或企业机密信息，比如过十万条甚至是千万条便绝对是高危或者叫危害，此外便是可以通过sql注入执行命令获得主机权限，从而能突破逻辑隔离进入内网也能算高危，否则没什么数据也拿不到权限也就算个中危漏洞因为只获得了单一数据库的权限和数据

> 反馈：**判定 = 已具备（这题答得比很多安服报告好）**

你的判据是「**数据量 + 权限突破**」两个轴——这和红队定级的实际逻辑高度一致（数据轴 × 能力轴 × 体量轴）。特别是"**突破逻辑隔离进入内网也算高危**"这句，抓住了红队定级的要害：**洞的价值不在洞本身，在于它能把你送到哪。**

补一个红队特有的差异：**红队报告是按"链走到了哪"定级，不是按洞的数量**。
- 安服：每个洞单独定级，追求覆盖全
- 红队：一个中危洞串起来打到域控，整链价值远高于单个孤立高危洞；反过来，一个高危洞如果只是"能拖库、没往下走"，价值反而有限

**这条是你现有的、可以直接迁移的资产**——不用重学。

## 结构性结论（比单题对错重要）

### 一、你的知识栈是 Linux + Web 单一栈

Q3 问 Windows 特权，你答脏牛和 SUID；Q5 把三个 Windows 横向手法归为"都落地 impacket"。
**一进 Windows 就断**，而高级红队的主战场恰好是 Windows 域。

这不是补一个知识点能解决的，是**要补一整套平台认知**（Windows 权限模型 → 凭据体系 → 认证协议 → 域结构）。

### 二、你的思维是「找洞」，不是「找人」

Q6 从"定位域控"直接跳到"找漏洞/PTH"，**整条路径没有一个环节在问"谁登录过这台机器"**。
这是外网渗透惯性的直接延续：

> 外网打程序（有 bug 的程序），内网打人（会登录、会复用密码、会被加进组的人）。

### 三、有两个概念必须立刻纠正（优先级高于一切新知识）

1. **Kerberoasting / AS-REP ≠ 密码喷洒**（Q7）——一个离线一个在线，混用会直接触发 4625 告警
2. **impacket 不落地到目标**（Q5）——它在你的攻击机上

这两个错的共同特点：**不影响你"说出正确答案"，但会让你在实战中做出错误的动作。** 这比"不知道"危险。

### 四、判据能力是在的，缺的是执行手段

Q10 定级答得比很多安服报告好，说明你的**判断力、体量意识、危害评估**是完整的。
你不是"能力弱"，是**偏科**——"脑子"够用，"手"只长在 Web 上。

这意味着：**后续不需要重学思维方法，只需要补 Windows 内网这一段的实操和机制。**

## 据此调整的第一条链

原计划（`00` 里写的）是从「外网入口 → 落地 → 驻留 → 提权 → 抓凭据 → 横向」直接进 Vulnstack 完整场景。

**现在改为：先用单机把 Windows 平台认知补起来，再上完整链。**

理由：Vulnstack 默认你已经懂 Windows（知道去哪找凭据、知道特权是什么、知道三种横向的差别）。你现在上完整场景，会变成"跟着 walkthrough 敲命令"，正好落进"验证 AI 平均解"的陷阱。

| 阶段          | 内容                                  | 验收                                     |
| ----------- | ----------------------------------- | -------------------------------------- |
| **W1（2 周）** | 单台 Windows：我是谁 / 我在哪 / 周围有什么 / 凭据在哪 | 能不看资料列出 6 个定位动作，并说清每个"为什么要做"           |
| **W2（2 周）** | 提权：从 IIS 应用池账号到 SYSTEM              | 能说清"强制认证→模拟令牌"的链条，能判断哪种 Potato 在当前版本失效 |
| **W3（2 周）** | 横向：三种手法的痕迹差异                        | 能对着 EVTX 说出每种的落地文件和日志 ID               |
| **W4**      | 再走 Vulnstack 1 完整链                  | 完整攻击链图 + 痕迹清单                          |

**每阶段都按「同一环境打五遍」的约束递进。**
