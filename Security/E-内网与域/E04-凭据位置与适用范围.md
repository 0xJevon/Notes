# E04 · 凭据位置与适用范围

> 内网渗透一半时间在**找凭据、判凭据能不能用**，不在打洞。
> 来源：Career 原《必学清单》第 2 项（2026-11-18 拆分后迁入，判据是库主的）。
> 状态：判据稿。自评 Q4 在这里栽过——把本地管理员 hash 当成能横着走。

---

## 一、存在哪

| 位置 | 装什么 | 谁能读 |
|---|---|---|
| **lsass** | 交互式登录的凭据（明文或 hash） | 本地管理员 + `SeDebug` |
| **SAM** | 本地账户 hash | SYSTEM |
| **NTDS.dit** | 域内全部账户 | 域控管理员（或 DCSync 权限） |
| **DPAPI** | 浏览器、凭据管理器 | 该用户的上下文（或主密钥） |
| **配置文件与脚本** | 明文密码、连接串、AK/SK | 能读文件就行——**投入产出比最高** |

> 最后一行是最容易被跳过的一行。`web.config`、数据库连接串、计划任务脚本、`ConsoleHost_history.txt`——**明文、不需工具、不触发告警**。放着抽屉里的钥匙不用，去撬保险柜，是新手的典型动作。

## 二、NTLM hash 能干什么、不能干什么

**能**：
- PTH 打 SMB（psexec / wmiexec / smbexec）
- PTH 打 WMI、MSSQL、LDAP（未强制签名时）
- Over-Pass-The-Hash：用 hash 换 Kerberos 票据

**不能**：
- **直接 RDP**——RDP 要建立交互式登录会话，需要能还原成凭据的密码（CredSSP/Kerberos 路径）
  - **例外**：目标开了 **Restricted Admin 模式**（Win8.1+/2012R2+），PTH 可以直接打 RDP
- **跨机器通用**——本地管理员账号在域内不通用。除非密码被复用过（内网很常见），这个 hash 出不了这台机器

## 三、票据

| | 说明 |
|---|---|
| **TGT** | 证明"我是谁"，KDC 签发，存在内存里 |
| **TGS** | 证明"我能访问这个服务"，用服务账号 hash 加密 |
| **Kerberoasting 打的是 TGS**，不是 TGT——这点混了，判断全错 |

## 四、一条必须建立的区分

| | 密码喷洒 | Kerberoasting / AS-REP |
|---|---|---|
| 在哪做 | **在线**，直连目标反复试 | **离线**，拿回 hash 自己爆 |
| 日志 | 大量 4625 | 没有失败登录 |
| 会不会被抓 | 极容易 | 几乎不留失败记录 |

**混为一谈的后果很具体：你以为在离线，实际在在线，直接触发告警。** 自评 Q7 就错在这里。

## 五、验收

拿到一个 hash，说清：它属于谁、能打哪几台、为什么打不了另外几台。
