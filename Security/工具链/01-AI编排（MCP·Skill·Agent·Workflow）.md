# 01 · AI 编排（MCP · Skill · Agent · Workflow）

> 一句话：把"我手上几个工具"变成"一套能被按规矩调用的流程"。
> **课程实况**：四天正文是逐日累积的（第 1 天 ⊂ 第 2 天 ⊂ 第 3 天 ⊂ 第 4 天），新增内容只占约 1/4，其余是重复。下面只留能改变作业结果的判据。

---

## 一、四层职责（本课唯一不会过期的部分）

| 层 | 管什么 | 不管什么 | 一句话判据 |
|---|---|---|---|
| **MCP** | 有哪些工具、哪些数据可访问 | 调用顺序、分支、禁止项 | 连接层：**能碰到什么** |
| **Skill** | 按什么顺序、什么条件、什么禁止 | 工具本身怎么实现 | 流程层：**什么情况下用哪个** |
| **Agent** | 拆目标、选 Skill、判断结果、纠错重试 | SOP 的稳定复现 | 决策层：**下一步做什么** |
| **Workflow** | 把 SOP 固化成可执行链路（串行/分支/状态/重试） | 开放式探索 | 编排层：**同一套流程重复跑** |

课程的原始例子把分工讲得很清楚：

- MCP 只声明两个工具：`execute_nmap`、`fofa_search`；
- Skill 写的规矩是"给 IP → 判内网/公网 → 内网才 nmap，公网禁止、改用 fofa → 提风险点 → 按模板出报告"。

**这条规矩既不能写在 MCP 里，也不能指望模型每次自己想不起来**——这是本单元最该带走的一句话。安全的红线恰恰属于流程层，不属于工具层。

## 二、接入判据：stdio 还是 SSE

| 方式 | 适用 | 判据 |
|---|---|---|
| **stdio** | 本地进程：操作本机文件、跑本机二进制 | 工具**跑在我的机器上** |
| **SSE** | 远程服务：本身已有在线 API | 工具**已经有 HTTP 接口** |

配置两条路：界面手填（命令 + 参数），或贴 JSON：

```json
{"mcpServers":{"local-nmap":{"command":"python","args":["/path/nmap_mcp_server.py"]}}}
```

自写一个 server 的入口只有一层装饰器：`@mcp.tool()`。

> **我方补充（课程未讲）**：stdio 方式意味着 Agent 能起一个本地进程。这既是能力也是攻击面——server 脚本的入参谁来校验、能不能被诱导成任意命令执行，是这条线必须自己回答的问题。**授权测试场景下，MCP server 的权限边界比它的功能重要。**

## 三、底座选型：先问"能不能委派"

| 产品 | 定位 | 什么时候选它 |
|---|---|---|
| **Pi** | CLI 编排层，权限分 `readonly` / `edit` / `danger`，可把任务委派给 Claude Code、Codex、Devin | 要**编排**、要权限分层 |
| **Claude Code** | 执行者（代码理解、重构、调试、git） | 只干一件具体活，不负责编排 |
| **Hermes / Harness** | 本地 Agent 底座，可配 DeepSeek 等模型 | 要离线、要数据自持 |
| **OpenClaw** | 自托管 Agent 网关，接 IM 渠道触发 | 要"在聊天里随时调起来" |

**Pi 的权限分层是红队场景唯一的硬需求**：Agent 会吐出 `net stop`、改注册表、删日志这类命令，没有危险档位控制就不能让它碰真实目标。

## 四、Workflow：SOP 要从 prompt 里搬出来

课程给的两个产品（ARTEX、CyberStrikeAI）共同点：LLM 配置、任务对话、消息推送、**资产记忆**、**架构拓扑**。

值得记的不是产品名，是它把"资产记忆"和"拓扑"当一等公民——这正是纯 prompt 编排做不到的地方：一次任务里 Agent 得记住"我打过哪些资产、它们之间怎么连"。这也正是我这边台账要解决的问题。

## 五、模型梯队（只记判据，不记型号）

| 档 | 用在 |
|---|---|
| 顶档（课程写 Fable） | 极限长周期任务、最难的代码与推理；最贵、偏慢 |
| 高档（Opus） | 深度研究、复杂方案、高难度 Agent |
| 中档（Sonnet） | **默认**：日常编码、文档、分析、普通 Agent |
| 低档（Haiku） | 批量抽取、分类、路由、简单问答 |

型号会换，判据不会：**默认中档；卡住了才升档；量大且简单的下档。**

## 六、明确不学的（课里有，但对作业无影响）

| 内容 | 为什么不学 |
|---|---|
| 六代技术演进时间线（ChatGPT → Function Calling → ReAct → MCP → Skill → OpenClaw） | 只有一句有用："MCP 只管连接、不管流程"。其余是新闻不是判据，发布日期与治理归属半年就过期 |
| MCP 界面配置步骤（加服务器、等绿灯变绿） | 一次就会，写进自己的操作手册即可，不占单元 |
| 各产品的安装、汉化、仓库地址 | 现查即可 |

## 七、落到我这边

现状是 fscan / spray / EHole 三件二进制 + Burp + ZStack 授权场景。课程给的最小可用路径：

1. **每个二进制包一个 stdio MCP server**（`@mcp.tool()` 一层即可，不重写工具本身）；
2. **写一个 Skill 把红线固定住**：公网目标禁止跑内网工具、动手前先判授权范围、结果必须落资产台账；
3. **先在靶场跑，跑通了再上 ZStack**；
4. "打过哪些资产"由台账或 Workflow 那类东西管，不放在对话记忆里。

课程提到的几个仓库（CyberSecurity-Skills、java-audit-skills、ARTEX、CyberStrikeAI）可作对照实现，但这些工具通常默认"目标可被任意测试"，与授权测试的边界未必一致，**引入前需自行核对其出网行为与权限边界**。
