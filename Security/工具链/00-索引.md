# 工具链 · AI 编排

> **横切能力**（2026-11-18 从"支线"上调）：不在交付链任一段上，但**六域每一段都要用它**。
> 定位不是"会用 AI"，是**能指挥 AI 干活，并把它的产出压进可交付的质量线**。
> 源：小迪 V2027-1 第 1–4 天 + 大白哥 19–21 + 自有实践（fscan/spray/EHole + Burp + ZStack）。

| # | 单元 | 关键判据 | 材料 |
|---|---|---|---|
| T01 | MCP 接入 | stdio 还是 SSE，判"工具跑在谁的地盘上"；一个二进制切成几个 tool 按"判断"切，不按功能切 | [[01-AI编排（MCP·Skill·Agent·Workflow）]] |
| T02 | Skill 封装 | 红线、顺序、禁止项只能写在流程层；写进 prompt 会忘，写进 SKILL.md 不会 | 同上 |
| T03 | Agent 底座与权限分档 | 编排层 vs 执行者；readonly/edit/danger 三档必须开，否则不许碰真实目标 | 同上 |
| T04 | Workflow 固化 | 串行/分支/重试写在代码里，不写在自然语言里 | 同上 |

**杠杆点（本线最重要的一条判断）**：AI 放大的是**重复劳动**与**覆盖度**，不是**判断**。它能替你跑完 200 个子域的指纹比对，不能替你判"这台在不在测试范围里"。

**现状**：1 篇材料全为课程转述，**一条没实测**；T06 完全空白。
**开线条件**：不需要等。手上已有 fscan / spray / EHole + Burp + 授权 ZStack 场景，第一件事就是把它包成 T01。
**起点**：T01（一个二进制 → 一个 tool）→ T02（加规矩）→ 再做 T06（把代码审计里最耗时的 grep 交给它）。**跳过 T03/T04 的选型比较**，那是工具多了以后的事。
**不算完成的标准**：只能在自己电脑上手动跑通 = 没完成。要在靶场里由 Agent 自主跑完一次并留下证据。
