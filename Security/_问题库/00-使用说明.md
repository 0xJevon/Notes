# _问题库 · 使用说明

这是**驱动层**。整个知识库靠它推进，不靠"整理笔记"推进。

## 一个问题要成立的四个字段

```yaml
---
type: 问题
domain: C-执行与驻留
status: 待验证        # 待验证 | 已验证 | 已证伪
created: 2026-11-03
---
```

正文必须包含：

1. **现象** —— 我在哪一步卡住了，实际看到什么（指向 `_证据/` 里的记录）
2. **我的猜测** —— 先写自己的判断，不许空着等答案
3. **实验设计** —— 怎么验证这个猜测，要做什么、看什么
4. **关闭条件** —— 三条同时满足才算关闭：
   - 能不看资料复现
   - 能说清机制（为什么这样能行）
   - 能说出失效条件（什么环境下不管用）

## 命名

用问题本身当文件名，不用编号：

```
为什么mimikatz抓不到明文.md        ✔
问题1.md                          ✘
```

## 队列纪律

- `待验证` 超过 15 条 → **停止新输入，先清队列**。囤问题不做事是这类知识库最常见的死法。
- 每条问题必须挂靠一个 `_项目/` 里的靶场或真实任务，挂不上的不建。
- `已证伪` 的**必须保留**，写清"错在哪"。它的价值是防止半年后重踩。
