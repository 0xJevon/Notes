# 00 · 红队能力地图

> 目标：从**安全服务工程师**（找到洞、写报告）转为**高级红队工程师**（打穿一条链、达成目标、不被发现）。
> 这条线上唯一的进度指标不是"记了多少"，而是**"能在什么条件下做出什么"**。

**为什么是这个方向，而不是"把安服做深"**：[[红队心法]] 对职业路径有个直白的判断——一直干渗透岗、在各厂之间反复跳，是上限最低的一条路（"工资不涨，上限也很低"）；红队是**作战部门**，漏洞研究是**研究部门**，两个工种，路线不同。

所以这条线的终点不是"更资深的安服"，是**进乙方攻防实验室**（360 高攻 / 深信服深蓝 / 长亭攻防这类），在里面把实战能力打出来。判断标准只有一条：**真打的时候能不能日穿对面的站——并且在对方有防守的情况下不被发现。**

> 后半句是我的补充。《心法》通篇在讲"怎么打进去"，几乎没讲"怎么不被发现"，那是它覆盖不到的部分，也正是本库 H/G 两个域存在的理由。

## 一、验收标准（能力轴，不是知识轴）

达到高级红队，必须能独立做到下面四件事。做不到其中任何一条，就不算。

| # | 验收项 | 当前 |
|---|---|---|
| V1 | 只给一个公司名，8 小时内拿到第一台内网主机的稳定控制权 | ☐ |
| V2 | 从一台普通域内主机出发，24 小时内推到域管（有 EDR 的环境） | ☐ |
| V3 | 全程不触发客户 SOC 的有效告警；若被触发，能指出是哪一步、如何规避 | ☐ |
| V4 | 能把整条链画成图，逐段解释"为什么这么走、还有哪些备选、为什么没选" | ☐ |

自检频率：每月一次。V1→V2 之间通常要 6-12 个月，别急。

## 二、十条能力域（按攻击链分段，不按漏洞类型）

> **为什么不按"SQL注入/XSS/SSRF"分？** 那是安全服务的轴，目标是"找到一个洞交报告"。
> 红队的轴是**链路段**，目标是"在不被发现的前提下推进到目标"。
> 同一个漏洞在两条轴里的地位完全不同：红队只关心它"能不能把入口变成执行权限"。

| 域 | 一句话定义 | 现状 | AI 赋能 |
|---|---|---|---|
| **A 侦察与打点** | 从零信息到"可攻击入口清单" | 有 4 篇，偏 Web 侧；**细节调优空白**（字典未沉淀、指纹未验证） | ★★★ 用法 / **★★ 细节** |
| **B 初始访问** | 把入口变成执行权限 | **内容最多**（漏洞攻防/基础入门/6 篇组件漏洞），现有强项 | ★★ 需底子 |
| **C 执行与驻留** | 权限落地后活下来 | 已开打：落地自查清单（待填） | ★★ 需底子 |
| **D 提权** | 从低权到高权 | 1 篇 3.3KB 且是 **Linux 侧**，Windows 空白 | ★★ 需底子 |
| **E 横向移动** | 从一台到多台 | 内网安全 41KB **偏理论**，横向手法体系未建立 | ★ 弱 |
| **F 域渗透** | 从普通域用户到域控 | **空 ← 分水岭** | ★ 弱 |
| **G C2 与基建** | 让流量活下来 | **空 ← 分水岭** | ★ 弱 |
| **H 对抗与免杀** | 让行为不被记录 | **空壳 81 字节 ← 分水岭** | ★★ 军备竞赛 |
| **I 目标达成与报告** | 证明打穿了 | 安服报告经验可迁移，但红队口径不同 | ★★★ 可托管 |

**结论一句话**：你的能力集中在 A、B，E 有素材，而 C/D/F/G/H 五个域几乎为零——其中 F/G/H 正是"安服"与"高级红队"的分水岭。

### AI 赋能怎么看（关键）

AI 的强弱，**和这个环节有没有公开语料高度正相关**：

- A / B / I 的语料海量（资产测绘、漏洞原理、PoC、报告模板）→ AI 给得出 70 分的起点，**这些活不值得你花时间学**
- E / F / G 的语料稀缺且易过期（客户网络长什么样、这台机器为什么打不动）→ AI 只能给平均值，**这些活必须自己在真实环境里攒**
- H 是军备竞赛：AI 帮你变异，防守方的 AI 也在拿变异样本训练检测器

**一句话**：AI 把你三个月抬到「脚本小子 2.0」，但**从脚本小子到高级红队那一段，AI 帮不上忙**——那一段恰好就是这条知识库存在的意义。

具体怎么和 AI 分工，见 [[02-学习方法]] 第四节「AI 协作边界」。

### A 域的真实瓶颈（读《红队心法》后修正）

我原先把 A 域整体判为「★★★ 可托管」，**这个判断过头了**。

《红队心法》把打点拆成一个等式：

> **打点成功 = 信息搜集成功 + 漏洞利用成功**

然后它指出：常规搜集人人都会，**但「全部做到位的人真的不多」**——差别全在细节：

> 现在有的指纹识别系统是不是真的准确，这个需要自己去测，然后自己去调，根据目前的工具来做一些二开。还有目录扫描，就是一个字典的问题，但是很多人就是默认字典在那里搞，没有自己实战中沉淀的字典。

**AI 能给的是「怎么做」，给不了的是「调到什么程度」**：

| 环节 | AI 能给 | AI 给不了 |
|---|---|---|
| 指纹识别 | ✅ 怎么配、怎么用 | ❌ **你自己的目标群，哪些指纹误报率高** |
| 目录字典 | ✅ 通用字典 | ❌ **你打过的行业/中间件，有哪些专属路径** |
| 爆破字典 | ✅ 常见弱口令表 | ❌ **你客户所在行业的密码习惯** |
| WAF 绕过 | ✅ PoC 骨架、常见绕法 | ❌ **这套 WAF 的绕过手感** |

所以 A 域评级改为：**用法 ★★★ 可托管，细节 ★★ 必须自己攒**。

而"细节"有个残酷的属性：**只能在真实目标上攒，靶场练不出来**。所以它不占当前 Loop 1-6 的时间预算，但有落点——见 `A-侦察与打点/字典与指纹-实战沉淀.md`，每次打真实目标后往里加。

## 四、第一条链（当前主攻）

起点是**外网单点**，所以第一跳不是去啃域渗透，而是把"单点"变成"有纵深的路径"：

```
外网入口 → 落地执行 → 稳住权限 → 提权 → 抓凭据 → 横向到第二台 → 复盘痕迹
   A/B        C          C        D       D/E        E          E/H
```

**靶场**：Vulnstack 系列（红日），5-10 小时/周 → 一个场景 2 周内跑完。
**产出**：每次跑完必须留下三件东西（见 `02-学习方法.md`），否则算没跑。

为什么不用 HTB Pro Labs / GOAD：那是 V2 阶段的靶场，现在上会变成"跟着 walkthrough 抄"，学不到东西。

### ⚠️ 诊断后的修正（2026-10-27，以 `01-能力自评` 结果为准）

原计划直接上 Vulnstack 完整链，**已否决**。

原因：Vulnstack 默认你已经懂 Windows（知道去哪找凭据、知道特权是什么、知道三种横向的差别）。而诊断显示你的知识栈是 **Linux + Web 单一栈**——Q3 问 Windows 特权答成脏牛和 SUID，Q5 认为 impacket 会落地到目标。直接上完整场景会变成"跟着 walkthrough 敲命令"，正好落进「验证 AI 平均解」的陷阱。

**改为环形训练：每轮走完整链，只聚焦一个焦点。**

原设计的 W1→W2→W3→W4 是**线性递进**，而且每段都"先学后打"，两条都错了：
- 《学习思想》：「线性思维我实操下来真的不好使，学到后面，前面的东西又忘记了」
- 同篇：「切忌一上来就对着基础知识一个个啃，效率非常之低下，而且没有感觉」

所以 W 阶段不成立，改成 Loop：

| 轮次 | 焦点（**只考核这一项**，其余做到就行） | 通过标准 |
|---|---|---|
| **Loop 1** | **定位**：我是谁 / 我在哪 / 周围有什么 / 凭据在哪 | `落地后前10分钟-自查清单` 前 4 层，不看能填对 |
| **Loop 2** | **提权**：IIS 应用池 → SYSTEM | 说清「强制认证 → 模拟令牌」，能按版本判断哪种 Potato 失效 |
| **Loop 3** | **横向**：psexec / wmiexec / winrm 痕迹 | 对着 EVTX 说出每种落地什么、留什么日志 ID |
| **Loop 4** | **全链质量** | 无冗余步骤、痕迹最少 |
| **Loop 5** | **对抗**（开 Defender/Sysmon） | 不触发有效告警 |
| **Loop 6** | **决策**（限时 4h，只给一个入口） | 能说清哪条路放弃、为什么 |

**每轮都从外网入口走到横向**（保持全局感），全程不考核整体质量，只考核焦点那一段，其余环节"做出来就行"。

> **直接开打，撞墙了再查 `_问题库` 和自查清单——不要先把 Windows 权限模型学一遍再动手。**
> 这是总原则第 3 条（先直面问题，卡住了再补前置）的直接应用。诊断出的 5 条 P0 问题因此**不是课程表，是墙上会撞到的砖**。

详细规则见 [[02-学习方法]] 第二节「环形训练法」。

**唯一不推迟的**：Q7 那个概念错误（Kerberoasting ≠ 密码喷洒）**立刻纠正**，不用等 Loop——它会导致实战误判，属于必须先修的。

## 六、与其他学习线的关系

- **网络基础线**（`Tech/网络基础/`，M0-M18）：是**补短板**，不阻塞主线。只在具体卡住时回补（隧道、代理链、防火墙规则绕过时翻 M0/M11）。
- **代码审计**（`Z-知识底座/代码审计/`）：是**加分项**，不是主路径。红队用它的场景是"打 Java 应用时能自己挖 0day"，等 B 域打透了再说。
- **362 篇面试题库**（`Career/面试题/Sec-Interview-main/`）：**不要读它**。用法是当覆盖度检查表——扫章节名，逐条问"这个点我实测过吗"，答"没有"的就是 `_问题库` 的候选。
