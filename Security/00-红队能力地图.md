# 00 · 红队能力地图

> 目标：从**安全服务工程师**（找到洞、写报告）转为**高级红队工程师**（打穿一条链、达成目标、不被发现）。
> 这条线上唯一的进度指标不是"记了多少"，而是**"能在什么条件下做出什么"**。
>
> **上位入口**：[[000-知识库总纲]]（全库架构与运转规则）· **通用经验**：[[00-索引]]（21 条，本域的每条判断都应先在那查一遍）

**为什么是这个方向，而不是"把安服做深"**：[[红队心法]] 对职业路径有个直白的判断——一直干渗透岗、在各厂之间反复跳，是上限最低的一条路（"工资不涨，上限也很低"）；红队是**作战部门**，漏洞研究是**研究部门**，两个工种，路线不同。

所以这条线的终点不是"更资深的安服"，是**进乙方攻防实验室**（360 高攻 / 深信服深蓝 / 长亭攻防这类），在里面把实战能力打出来。判断标准只有一条：**真打的时候能不能日穿对面的站——并且在对方有防守的情况下不被发现。**

> 后半句是我的补充。《心法》通篇在讲"怎么打进去"，几乎没讲"怎么不被发现"，那是它覆盖不到的部分，也正是本库 G、H 两域存在的理由。

> **状态（2026-11-13）**：本线暂停，当前主线为**安服代审线**（[[04-双线能力线]]，6 周）。**架构已完整，内容大面积空**——这是刻意的不对称：先让每个能力都有可落脚的库，再按交付顺序填。

## 一、验收标准（能力轴，不是知识轴）

达到高级红队，必须能独立做到下面四件事。做不到其中任何一条，就不算。

| #   | 验收项                                 | 挂靠域 | 当前  |
| --- | ----------------------------------- | --- | --- |
| V1  | 只给一个公司名，8 小时内拿到第一台内网主机的稳定控制权        | A → B → C | ☐   |
| V2  | 从一台普通域内主机出发，24 小时内推到域管（有 EDR 的环境）   | E → F（H 制约） | ☐   |
| V3  | 全程不触发客户 SOC 的有效告警；若被触发，能指出是哪一步、如何规避 | G · H | ☐   |
| V4  | 能把整条链画成图，逐段解释"为什么这么走、还有哪些备选、为什么没选"  | I | ☐   |

自检频率：每月一次。V1→V2 之间通常要 6-12 个月，别急。

**四条验收对应 9 个域，没有一条落在"知道多少漏洞"上**——这就是为什么下面按攻击链分段，而不按漏洞类型分段。

## 二、九个能力域（按攻击链分段，不按漏洞类型）

> **为什么不按"SQL注入/XSS/SSRF"分？** 那是安全服务的轴，目标是"找到一个洞交报告"。
> 红队的轴是**链路段**，目标是"在不被发现的前提下推进到目标"。
> 同一个漏洞在两条轴里的地位完全不同：红队只关心它"能不能把入口变成执行权限"。
>
> **每域 3–11 个单元，索引只有一张表。** 单元数不是越细越好——一个单元对应"一个必须做出的判断"，判断相同的合并，判断不存在的不建。

### 一句话结论

结构上，**A–I 九个域全部有索引，每个域都有起点单元**；内容上，**B 域最厚但最浅（速查级），F/G/H 三个分水岭全空**。

这不是"框架搭得太多"，是**过去三年攒的全是 B 域的东西**（组件复现、Web 漏洞笔记），而决定红队身份的三段（域、C2、对抗）一篇没有。骨架的作用是让这个不对称变得可测量——现在它被测量出来了。

## 三、为什么不照搬（308 天 → 106 个单元）

《V2024-11-小迪安全》是**课程**：按工具和章节推进，一部课讲 300 多天，其中大量内容是"这门技术存在"，不是"我需要会"。
骨架是**能力表**：按 V1–V4 反推，只留能决定"打不打得穿"的东西。所以做了三层裁剪：

| 层 | 做法 | 例子 |
|---|---|---|
| **整章剔除** | 与目标无关，或只是工具使用 | Web3（D189–194）、ChatGPT 使用（D14）、APP 隐私合规（D86）、AI 审计系统与 MCP 开发（D185–188）、漏扫与 PoC 开发（D138–143，属安服工具） |
| **同类合并** | 一个判断就够了，不必一个产品一篇 | 5 个 SQL 注入单元 → 2（检测与利用 / 数据库层利用）；4 个 CC 相关域 → 0（链在 Java 安全，本库不重复）；31 天免杀 → 7 个单元 |
| **降级为查阅** | 有价值但不占学习时间 | 内网安全的教科书式总览（E 域一篇汇编）、JS 前端开发 7 天（只留 WebPack 泄漏） |

**保下来的判据只有一条**：这个单元能不能改变"一次攻击的成败"。

- **CSRF 剔除**：它要受害者主动配合，红队链上不占位置（安服报告里另算）
- **XSS 保留**：打后台、钓鱼、拿会话都要它
- **业务逻辑只留 1 个单元**：它是安服交付的高频，不是红队入口
- **域渗透 / C2 / 免杀一个不删**：这三段就是 V2/V3 本身

结果：308 天 → **106 个能力单元**（A–I 48 个 + 代码审计 36 个 + Java 安全 22 个）。

**第二次裁剪（同日，结构层）**：第一版是 131 个单元，用户指出"结构上冗余"。砍的是**单元粒度与索引分节**，不是内容——A 11→6、B 19→11、C 5→4、D 6→5、E 5→4、F 6→5，J 云上攻防与 K 蓝队与应急整域删除（不属于红队验收 V1–V4，日常告警处置在本职工作里练，不需要建库）。每份索引从六节压成"一张表 + 现状 + 起点"。

## 六、第一条链与环形训练

起点是**外网单点**，所以第一跳不是去啃域渗透，而是把"单点"变成"有纵深的路径"：

```
外网入口 → 落地执行 → 稳住权限 → 提权 → 抓凭据 → 横向到第二台 → 复盘痕迹
   A/B        C          C        D       D/E        E          E/H
```

**靶场**：Vulnstack 系列（红日），5-10 小时/周 → 一个场景 2 周内跑完。
**产出**：每次跑完必须留下三件东西（见 `02-学习方法.md`），否则算没跑。

### 环形训练（2026-10-27 诊断后的修正）

原计划直接上 Vulnstack 完整链，**已否决**：Vulnstack 默认你已经懂 Windows，而诊断显示知识栈是 **Linux + Web 单一栈**，直接上完整场景会变成"跟着 walkthrough 敲命令"。

**改为环形：每轮走完整链，只聚焦一个焦点。**

| 轮次 | 焦点（**只考核这一项**） | 通过标准 | 对应单元 |
|---|---|---|---|
| **Loop 1** | **定位**：我是谁 / 我在哪 / 周围有什么 / 凭据在哪 | 落地自查前 4 层，不看能填对 | C01 |
| **Loop 2** | **提权**：IIS 应用池 → SYSTEM | 说清「强制认证 → 模拟令牌」，能按版本判断哪种 Potato 失效 | D04·D02 |
| **Loop 3** | **横向**：psexec / wmiexec / winrm 痕迹 | 对着 EVTX 说出每种落地什么、留什么日志 ID | E04 |
| **Loop 4** | **全链质量** | 无冗余步骤、痕迹最少 | I02 |
| **Loop 5** | **对抗**（开 Defender/Sysmon） | 不触发有效告警 | H01·H06 |
| **Loop 6** | **决策**（限时 4h，只给一个入口） | 能说清哪条路放弃、为什么 | I03 |

**每轮都从外网入口走到横向**（保持全局感），只考核焦点那一段，其余"做出来就行"。

> **直接开打，撞墙了再查 `_问题库` 和对应域索引——不要先把 Windows 权限模型学一遍再动手。**
> 这是 G03（先直面问题，卡住了再补前置）的直接应用。

WHERE type = "问题"
SORT status ASC, file.mtime DESC
