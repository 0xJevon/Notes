# 格二 · 逻辑学（L01–L06）

> 这一格管一件事：**从已知推到未知，这个"推"本身对不对。**
> 它不看内容真假，只看**形式**——前提为真时，结论是不是被真的保证了。
>
> 这里只收六条能日常调用的。逻辑学教材里的名词体系（真值表、三段论格、命题演算）不收，因为库里已有的判据在做的正是这件事，回头学名词没有增量。

---

## L01 · 必要 / 充分条件

**内核** 必要 = 没有它一定不行（有它不一定行）；充分 = 有它一定行（没它也可能行）。**把必要当充分，是所有过度断言的根源。**

**它盯什么** 任何"我看到了 X，所以就是 Y"的句子。写危害结论、写"存在某漏洞"、写"证明是内网做的"。

**怎么用**
1. 把句子改写成："X 是 Y 的**必要条件**，还是**充分条件**？"
2. **找反例**：有没有 X 成立、Y 不成立的情况？找得到 → 只是必要
3. 若只有必要，结论只能写"**不能排除 Y**"，不能写"是 Y"。这两句话的定级差一整个档

**边界** X 与 Y **定义等价**时不用查（"响应头有 Set-Cookie" ↔ "服务端下发了 cookie"）。
**错误方向**：会让你把结论**写得比证据强**。这个偏差不会在现场被发现，只会在一周后被人打回来。

---

## L02 · 演绎 / 归纳 / 溯因（三种推法，别混用）

**内核** 三种推理的保证强度完全不同——
- **演绎**：前提真 → 结论必然真（唯一有保证的）
- **归纳**：样本 → 一般，只给**概率**，永远可能被下一个反例推翻
- **溯因**：结果 → **最可能的原因**，给的是候选解释，不是结论

**它盯什么** 任何"所以"。"日志里有这条命令，所以攻击者执行了它"——这是**溯因**。"这类攻击都用这个手法，所以这次也是"——这是**归纳**。两种都没有必然性。

**怎么用**
1. 标出这句推理属于哪一类
2. **溯因** → 必须列**至少两个**候选解释，然后找能区分它们的证据。只有一个解释的溯因，是确认偏误（M18）
3. **归纳** → 写出它可能被什么推翻；写不出，就是把概率当成了必然
4. 只有**演绎**可以写成"必然"；其余一律用"很可能 / 不能排除 / 首选解释"

**边界** 演绎给的是"形式有效"，不是"事实为真"——前提错，结论照样必然错。
**错误方向**：最常见的滥用是**把溯因当演绎**：看到结果反推原因，然后用"必然"的语气写出来。技术研判里这几乎每天都在发生。

## L03 · 反例与可证伪

**内核** 一个说法如果**说不出什么情况下它不成立**，它就不是知识，是无法被检验的信念。找反例是检验它的唯一低成本手段。

**它盯什么** 任何听起来很顺的解释、任何"各种情况都能解释"的模型、任何"这不是正好说明……吗"。

**怎么用**
1. 写一句：**什么观察会让这个结论作废？** 写不出 → 它已经不可证伪，放弃它
2. 主动找一条反例。**找不到才算过硬**，找得到就改结论
3. 警惕"能解释一切"的模型——解释力越广，通常越空洞

**边界** 有些真命题天然难证伪（"存在一个我们看不到的原因"），这时不要求证伪，但要求**降低它的分量**：不拿它做决策依据。
**错误方向**：会让人**过度怀疑一切**，把可用的经验也一并否定。它的对象是**结论**，不是常识。

## L04 · 量化词（"有些"不是"大部分"）

**内核** 逻辑上：`所有` / `有些（至少一个）` / `没有`。日常语言里"有些"常被自动读成"有些但不全是"，**这个跳跃没有依据**。

**它盯什么** 需求描述、范围承诺、影响面判断。"部分资产受影响""有些接口存在风险""个别用户反映"。

**怎么用**
1. 遇到量化词，**立刻问具体数**：几个？占比？在哪
2. 若拿不到数，结论里就**保留原词**，不要升格成"多数""普遍""大量"
3. 反向用：给别人下结论时，说清范围，避免对方自动升格

**边界** 在**需要快速定性**的场合，纠缠精确数会拖慢决策。
**错误方向**：会让你把"1 个案例"写成"存在该类问题"，进而在报告里制造出不存在的影响面。

## L05 · 范畴错误 / 概念偷换

**内核** 把属于 A 类的东西当 B 类处理，或用同一个词指了两件不同的事，推理看起来成立，实际每一步都在漂移。

**它盯什么** 讨论越来越偏、"你说的和我说的不是一回事"、指标替换、"安全意识不够"这类归因。

**怎么用**
1. 把关键名词**写下定义**，只用这个定义往后推
2. 检查中途有没有**同一词换义**（"风险"一会儿指概率、一会儿指损失）
3. 检查类别是否错位：把**流程问题**当**能力问题**、把**激励问题**当**态度问题**

**边界** 定义过严会让讨论无法推进（什么都得先定义）。
**错误方向**：会变成**抬杠工具**——只在对方身上挑概念，不用来检查自己。正确用法是先查自己那句里有没有漂移。

---

## L06 · 连续体谬误（把连续量切成两半）

**内核** 现实里多数量是连续的（程度），但决策需要二值（做/不做、合规/不合规、高/中/低）。**切点是人选的，不是事物自带的。**

**它盯什么** 分级、达标线、阈值判定、"这算不算漏洞""这算不算高危""算不算达标"。

**怎么用**
1. 承认切点是**约定**，不是发现——写出切点在哪、谁定的、依据什么
2. 检查边界样本：切点两侧各取一个，问"这个差别真的值一整个级别吗"
3. 若边界样本判断反复摇摆 → 说明维度选错了，不是判据不够细

**边界** 有些切点有硬依据（法定标准、协议规定、物理阈值），那些不用讨论，照做。
**错误方向**：会让人**在人为切点上争论不休**（"这到底算中危还是低危"），而真正该讨论的是"这个切点还合不合适"。
