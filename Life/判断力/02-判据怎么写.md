# 判据怎么写

## 一、为什么有这份文件

`01-脊柱清单` 给了 18 个问句，但没回答三个问题：**这些模型有什么用、什么时候用、怎么用**。

补上，一句话各一条：

| 问题 | 答案 |
|---|---|
| **有什么用** | 不提升上限，只设下限。它在你**本来会判错**的地方替你挡一次。判断没出过错的时候，它确实没用 |
| **什么时候用** | 不是在读书时用，是在**要落笔写结论**的那 30 秒用（写报告、定级、给对账结果、下封禁结论） |
| **怎么用** | 三分钟内能走完：找到对应那条 → 回答它那个问句 → 答案改变了你的结论，或者没改变 |

**关键**：它是个**止损工具**，不是知识。所以"学完 18 条"不是目标，"被其中一条救过一次"才是。18 条里通常只有 3–5 条跟你当前的工作真正相关。

---

## 二、正确的启动方式：错题反查，不要从第一条学起

清单按学科分组（形式 / 实证 / 多主体），那是**存放顺序**，不是**使用顺序**。
用的时候按**你犯过的错**来查：

| 我犯过这种错（按出现频率排） | 该调哪条 |
|---|---|
| 把"可能"说成了"已经" | 必要 / 充分条件、相关 ≠ 因果 |
| 数字有假阳性，条数对不上 | 基准率、抽样偏差 |
| 只统计到"能看到的" | 幸存者偏差 |
| 归因错了（改了 A，结果变了，就说是 A 的功劳） | 混淆变量、可控对照、回归均值 |
| 被平均值骗了 | 幂律 vs 正态 |
| 高估别人会照做 | 激励相容、委托代理 |
| 算出来的数离谱 | 量纲与数量级 |
| 论证跳步、循环论证 | 反例优先、守恒 |
| 谈判、验收、报价吃亏 | 信息不对称、逆向选择、边际 |
| 低估对手的反应 | 均衡 |

**动作**：先在左列勾出**真的发生过**的那几行（想不起具体是哪次，就不算），只保留勾中的——通常是 2–4 条。其余 14 条先放着，等它们对应的错真发生了再回来。

## 三、一条判据的写法（五段，缺一段就是摘抄）

```
【它替我省什么】  一句话说清它挡的是哪种错，必须带"我本来会怎么错"
【什么时候响】    我手上的什么动作会触发它（写具体，不写"思考时"）
【怎么做】        1-2-3，三步内能走完
【一次走完】      一个场景，从头到尾走一遍，写出"用之前会得出什么、用之后改成什么"
【什么时候不管用】 失效条件。写不出来的，说明还没会用
```

第三段和第五段是分水岭：
- 写不出【怎么做】的，你只是知道有这个词
- 写不出【什么时候不管用】的，你会把它用过头——**过度调用比不会调用更糟**，它会让每个结论都变成"无法判断"

## 四、三条示范（示例是假设的，不是库主的记录）

### 示范 1 · 基准率

**【它替我省什么】** 把"看起来很准的检测结果"当成事实，然后花两天时间追一批本来就是噪音的告警。

**【什么时候响】** 见到任何百分数：告警准确率、扫描置信度、模型命中率、"99% 检出"。

**【怎么做】**
1. 问基数：这个百分比是在多少条上算的？真样本、假样本各多少？
2. 算绝对数，不算比率：`假阳性条数 = 总条数 × 假阳性率`
3. 比较**假阳性条数**和你**能复核的条数**。假阳性 > 复核能力，这个结果不能直接用

**【一次走完】**
> 假设某规则标称准确率 99%，一次跑出 1 万条命中，其中真问题约 10 条。
> 假阳性 = 10000 × 1% = **100 条**。
> 用之前："99% 准，那应该基本都是真的，先看前 20 条。"
> 用之后：110 条有效命中里 100 条是噪音，命中率 9%。**先提高精确率或抽样估基数，再决定要不要投入人工。**

**【什么时候不管用】** 基数已知且极小（比如只有 3 条命中），算与不算结论一样。这时直接看。

---

### 示范 2 · 必要 / 充分条件

**【它替我省什么】** 把"必要条件成立"当成"结论成立"，在报告里写下自己没有真正证明的话。

**【什么时候响】** 任何"我看到了 X，所以就是 Y"的句子。尤其是在写危害结论、写"存在 XX 漏洞"的时候。

**【怎么做】**
1. 把句子改写成："X 是 Y 的**必要条件**，还是**充分条件**？"
2. 找反例：有没有 X 成立、但 Y 不成立的情况？找得到 → 只是必要条件
3. 若只有必要，结论只能写"**不能排除 Y**"，不能写"是 Y"。两者的定级完全不同

**【一次走完】**
> 假设观察到"目标端口开放"。
> 改写成：端口开放是"服务在监听"的必要条件，不是充分条件——中间可能有防火墙转发、可能是个蜜罐、可能是别的服务占了这个端口。
> 用之前："端口开了，服务在跑，可以按这个服务去做后续。"
> 用之后："**不能排除**该服务在跑。下一步用一次协议级的握手确认它到底是什么。"（结论降级，并给出验证动作）

**【什么时候不管用】** X 与 Y 是**定义等价**的（"响应头里有 `Set-Cookie`" ↔ "服务端下发了 cookie"）。等价的不用查，查了是浪费时间。

---

### 示范 3 · 幸存者偏差

**【它替我省什么】** 用"我看到的"代表"存在的"，然后在一份有系统性缺口的样本上得出分布结论。

**【什么时候响】** 做资产收集、统计漏洞类型分布、复盘"为什么这次成功"、写"整体风险"的时候。

**【怎么做】**
1. 问：这个样本是怎么进来的？谁被**排除**了？
2. 主动去找"不在了的那部分"：扫不到的资产、没爆的洞、失败的项目、被封掉的 IP
3. 在交付里补一句边界：这份统计**只覆盖**什么，不覆盖什么

**【一次走完】**
> 假设统计"本次评估的漏洞类型分布"，数据来自"已确认的漏洞"。
> 排除掉的是：扫描器没覆盖到的路径、手工没时间测的模块、需要内网才能触达的部分。
> 用之前："该单位的主要风险是弱口令和组件漏洞。"
> 用之后："**在已确认的漏洞里**，弱口令和组件漏洞占多数；未覆盖范围包括 X、Y。**该单位的风险分布不能由这份统计推断。**"

**【什么时候不管用】** 总体可枚举、且确实全部检查过（比如"这台主机上所有对外端口"）。这时样本 = 总体，没有偏差。

## 五、什么写法算失败（三条反例）

| 失败写法 | 为什么失败 |
|---|---|
| 「基准率：指在给定条件下事件发生的先验概率，是贝叶斯推断的重要组成」 | 这是**定义**，不是判据。读完不知道自己下一步做什么，等于没写 |
| 「做判断时要考虑基准率」 | 这是**口号**。没有触发条件、没有步骤、没有失效条件（H4 的三项全缺） |
| 「基准率很重要，我以后要多用」 | 这是**决心**，不是判据。它不会被任何一次具体判断调用到 |

**判据的唯一测试**：把它给一个同水平的人，他能不能在 3 分钟内照着走完，并得出和你一样的结论。不能，就还不是判据。

## 六、剩下 15 条怎么办

**不写。** 等它们对应的错真发生了再回来写——那时你写的是"我刚犯的那个错"，不是"书上说的那个概念"（G06：概念在上，例子在下；但例子必须是自己的）。

如果某条一直没被用到，两个可能，都值得知道：
- 它跟你的工作无关 → 删掉（H10 每月至少删一条）
- 你一直在犯这个错但没察觉 → 那就等它在一次交付里咬你，那时你会主动回来找它
