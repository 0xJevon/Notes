# Career · 职业线

> **技能与排期全在 [[Security/00-能力地图|Security]]，本文不重复。**

## 一、当前定位（1–3 年）：高级综合渗透测试与安全评估工程师

> 这一层管**个人技术能力**：把交付做扎实，靠自己的手能不能干完一张合同。长期方向见第二节，两层不冲突但重点不同——先有能力，再谈放大。

> **高级综合渗透测试与安全评估工程师**

| 项          | 内容                                                |
| ---------- | ------------------------------------------------- |
| **目标市场**   | 政府、国企及相关政企客户的网络安全服务市场                             |
| **核心业务**   | 以渗透测试和综合安全评估为主要交付能力，代码审计为差异化专项能力，具备必要的红队纵深和内网验证能力 |
| **差异化优势**  | 既理解应用业务、又能分析源码，同时能完成攻防验证和自动化交付                    |
| **职业发展目标** | 稳定的专业技术竞争力、较好的市场议价能力、长期可持续的收入增长，同时保留个人时间和生活质量     |

### 核心能力（五条，做到才算）

| #   | 能力                                       | 判定                            |
| --- | ---------------------------------------- | ----------------------------- |
| 1   | 独立完成常规授权渗透测试：资产与攻击面分析、漏洞发现、验证、影响判断到报告交付  | 一张合同从开场到收尾不靠人带                |
| 2   | 在授权范围内完成必要的主机与内网安全验证，理解常见身份认证、权限与域环境     | 该走到主机的走到主机，该到域控的到域控           |
| 3   | 独立审计至少一个主流技术栈的业务系统，提供源码位置、调用链、漏洞成因与可复现证据 | **Java 为主，能判 PHP/.NET 的常见入口** |
| 4   | 利用 Python、自动化工具和 AI 提升测试覆盖率、审计效率与交付质量    | 覆盖度与效率有可对比的提升，不是"装了个工具"       |
| 5   | 建立标准化的测试、审计、复核、报告与复测流程                   | 第二人接手续跑不断线                    |

### 能力边界

不追逐 APT 式长期潜伏、复杂 C2 武器化和极端免杀对抗；不以 0day 研究和顶尖红队竞技为职业必修课。**对超出项目范围的技术需求，能够识别并合理协作**——不硬扛，也不丢单。

### 交付标准（七条，前五条即 Q1–Q5）

| # | 标准 | 落点 |
|---|---|---|
| 1 | 测试覆盖完整 | Q1 |
| 2 | 漏洞结论可复现 | Q2 |
| 3 | 风险定级合理 | Q3 |
| 4 | 影响验证充分 | Q4（纵深到位） |
| 5 | 授权边界清晰 | Q5 |
| 6 | 整改方案可执行 | 报告要能指导改，不是只列洞 |
| 7 | 全过程可追溯 | 每条结论指得回 `Security/_证据/` 的原文 |

**为什么不是"安全研究员"或"演练攻击手"**：那两条的产出物是"成果"（洞、战果），只认时间堆；按每周 20 小时算，单一方向就要 800 小时以上，且没有项目喂就练不出来。报告能靠流程放大，成果不能。

**与两条相邻路线的分界**：

| 对照    | 差别                                     |
| ----- | -------------------------------------- |
| 对顶级红队 | 不要求"不被发现"，要求"真的走到了"；安服反向要求全过程可追溯（标准 7） |
| 对普通安服 | 能自己挖、能到域控、报告带源码行号与调用链，不只是跑扫描器出清单       |

## 二、长期方向（3–5 年）：AI 时代的复合型专业工程师

> 这一层管**工作方式**：产出不再跟工时线性绑定，靠 AI 与自动化承担重复劳动，自己去做任务设计、判断和验收。它是第一节的放大，不是替换——**没有第一节的技术底子，第二节只是熟练使用工具**。

| 项          | 内容                                           |
| ---------- | -------------------------------------------- |
| **专业定位**   | 以网络安全为核心专业，以渗透测试和代码审计为主要交付能力，兼具必要的红队纵深       |
| **工作方式**   | 用 AI 和自动化承担大量重复性工作，把专业经验封装成可复用的 Skill、工具与工作流 |
| **核心职责**   | 不只完成任务，还要负责**任务设计、复杂问题判断、结果验证、最终交付质量**       |
| **差异化竞争力** | 专业知识 + 工程化能力 + AI 工作流设计 + 业务交付能力             |
| **长期目标**   | 能带着 AI 与自动化工具独立完成更多复杂任务，而不是靠大量人工操作维持产出       |

### 四维竞争力，我现在的位置

| 维度           | 现状                       | 3–5 年要到               | 缺口                  |
| ------------ | ------------------------ | --------------------- | ------------------- |
| **专业知识**     | 六域骨架完整，B/E 有料，C/F 空      | 独立接完一张含内网到域控的合同       | 纵深未串通一次（D→E）        |
| **业务交付能力**   | 会做验证，但 `_证据/` 近空、F 域 0 篇 | 报告经得起第二人复核与客户追问       | **最弱的一维**，也是长期目标的入口 |
| **AI 工作流设计** | 会零散用，没形成稳定流程             | 同类任务能拆给 AI、能验收 AI 的输出 | 缺"什么该交、什么不能交"的清单    |
| **工程化能力**    | 基本为零                     | 能把重复动作写成可复用的工具或流程     | 唯一需要**新增**的能力维度     |

### 一个必须说清的边界

长期目标里的「封装成可复用的 Skill、工具与工作流」**不等于每做完一段就必须交一个工具**。判据是经验密度：

| 情形 | 做法 |
|---|---|
| 这类活第一次做 | 只做，不封装——没跑过的东西封出来是空的 |
| 同一类活做过 3 次以上、动作稳定了 | 才值得封成 tool / Skill，因为此时你已经知道哪些步骤是必需的、哪些是浪费 |
| 封装后三个月没再用 | 删掉，不要留"看起来很工程化"的资产 |

这和第一节第 4 条「提升覆盖度与效率，不是装了个工具」是同一件事：**封装是结果，不是指标**。

## 三、两层怎么接

| 当前定位在练的        | 长期方向在用的                                       |
| -------------- | --------------------------------------------- |
| 六域 33 单元       | 专业知识维度的底子                                     |
| 代码审计 A1–A4     | 差异化里"能看源码"那一条，别人难替代                           |
| Q1–Q5 + 交付标准七条 | 业务交付能力；其中标准 6（整改可执行）、标准 7（全程可追溯）就是长期"结果验证"的雏形 |
| 工具链 T01–T06    | AI 工作流设计的实操场                                  |
| 每个项目留下的 `_证据/` | 将来封装 Skill 的原料——没有原始记录，经验封不出来                 |

**一句话**：短期攒的是"我能做"，长期换的是"我能让一套东西替我做，而我能验收它"。前者靠练，后者靠把练过的东西记下来、拆开、固定成流程。

## 四、读物里的三条判断（仍有约束力）

| 判断                                | 出处               | 对我的约束            |
| --------------------------------- | ---------------- | ---------------- |
| 一直干渗透岗、在各厂之间反复跳，是上限最低的一条路         | [[红队心法]]         | 不接受"资深安服"作为终点    |
| 红队是**作战部门**，漏洞研究是**研究部门**，两个工种    | 同上               | 选路时先选部门，再选技术栈    |
| **定位优先于短板**：团队缺什么，比我自己缺什么更重要（G20） | [[_通用/05-复盘与迁移]] | 学什么之前先问"这个位置缺什么" |

> `红队心法` 的盲区：通篇讲"怎么打进去"，几乎不讲"怎么不被发现"，也不讲"怎么证明"。那正是 Q2/Q3 存在的理由。

## 六、下一步

1. **每季度一次方向探测**（问题与判定表见 [[01-职业定位与分层判据]] 第五节）——定位定了不等于不校验
2. **团队定位那件事仍空着**：我在团队里补的是哪一块？这个答案决定 D/E/F 三域的投入权重，比任何课表都优先
3. 用面试题库做一次覆盖度扫描（1 小时，只扫目录不读内容），把"完全没碰过"的章节列出来，作为补漏清单
4. **长期方向的第一个动作不是学 AI，是把验证过程记下来**——`_证据/` 从 0 到有、F 域从 0 到 1。"结果验证"和"交付质量"这两条职责，靠的是可追溯的记录，不是工具；没有原料，将来也封装不出东西
