# 01 · 能力分层与学习大纲

> 结论先行：
> 1. **方向未定不是问题，把方向定死才是问题。** 刚毕业的第一年，目标不是选对赛道，是让三条赛道都愿意要你——所以精通层只押"哪条路都升值"的东西。
> 2. **只有三件事值得精通，其余全部降到"能审核"。** 精通的定义不是"重要"，是"这件事做不顺，整条链就断，而且 AI 帮不上"。
> 3. **你现在最值钱的不是技术，是每天能看到的真实客户环境。** 但这份情报正在被浪费——它变成了交付报告，没有变成你的资产。

---

## 零、当下 90 天：只做三件事

如果这份文档只看一段，看这段。

### 先切清楚 AI 到底替代了什么

不是"替代能力"，是替代**可被一眼验证的输出**和**有公开语料的流程**。

| 被替代 | 没被替代 |
|---|---|
| 报告初稿、扫描结果整理、定级套模板、工具参数、漏洞原理讲解、字典生成、资产测绘 | 判断这台机器为什么打不动、下一步该问什么信息、这个洞值不值得报、防守方此刻在看什么 |

对你的具体含义：**危险不是"AI 会做渗透"，是"AI 让标准交付变便宜，只会做标准交付的人被挤掉"。** 所以发力点不是"比 AI 更会打"，是站到 AI 交不出来的那一端。

### 发力点一句话

> **从"报告生产者"变成"结果证明者"。**

厂商安服交付的是报告，而报告正在因为 AI 而泛滥、贬值。反过来，"我实际拿到了这个数据""我实际打到了这台机器"这种**证据**，因为泛滥的报告而变得更值钱。这个身位现在几乎是空的，且和 AI 趋势正好相反。

### 三件事（按 ROI 排序，共约 120 小时）

| 顺序 | 学什么 | 为什么是它 | 时间 | 产出 | 验收 |
|---|---|---|---|---|---|
| 1 | **Windows 单机闭环**：定位 → 凭据 → 提权 | 你唯一的硬缺口（知识栈是 Linux+Web）；是所有证据能力的载体，不补则后面全部悬空；靶场就能练，不依赖客户环境 | 85h（周末整块为主） | 填满的落地自查清单 + 提权路径判别表 + 3 份原始证据 | 给一台陌生 Windows：10 分钟不看清单定位，30 分钟排出 3 条提权路径并说出各自失效点 |
| 2 | **证据能力**：定级 + 举证 + 情报卡 | 你**现在就有优势**的一项，边际成本近零——上班就在产生素材，别人要搭环境你要现成 | 25h（碎片，寄生在真实项目上） | 一页定级判据卡 + 5 份脱敏举证样例 | 20 条扫描告警里筛出 1 条真洞，其余 19 条逐条给出"不计"理由 |
| 3 | **最小流水线**：扫描输出 → 去重 → 指纹 → 复核清单 | 唯一能让你 10h/周跑出 30h 效果的东西；也是你押注的第二个方向 | 13h | 一条能跑通的脚本链，不是平台 | 同一个客户项目做第二遍，人工时间减半 |

**顺序不能换。** Windows 是"能拿到"，证据是"能证明"——拿不到就没有可证明的东西。但第 2 件和第 1 件**并行做**，因为它不占整块时间。

### 90 天明确不碰

域渗透、C2 基建、免杀、代码审计、云与容器、考证、靶场刷数量。

不是它们不重要，是它们**现在投入会分散掉唯一的整块时间**，而这三件事的复利期在 12 个月后。

### 判断"某个东西值不值得学"的三问

不确定的时候用这个筛，比任何清单快：

1. **AI 做出来，我能不能一眼看出对错？** 能 → 不值得学，学到"能审核"就够。
2. **离开这家公司、这个客户，它还成立吗？** 不成立 → 那是流程知识，不是能力。
3. **练一次能复用几次？** 只对当前项目有用 → 不做。

三问全过，才值得占整块时间。

## 一、前提修正：方向未定，怎么排

你说不确定兴趣偏好，只想走"能持续积累、有复利"的路。这句话本身已经给出了答案，只是它容易被误读。

**误读**：那就什么都学一点，保留可能性。
**正解**：什么都不精的人没有可能性。复利的前提是**本金**——你必须先在某一个点上形成"别人替不了"的能力，复利才有得算。

所以第一年的正确结构是：

| | 内容 | 作用 |
|---|---|---|
| **一个纵深** | 内网推进（攻防实战深度） | 本金。这是你押注的方向，也是唯一能让你从"安服工程师"里分出来的东西 |
| **一个杠杆** | AI 工程化流水线 | 利息。同样 10 小时，你能跑别人 3 遍的量 |
| **一个横向** | 危害举证与交付 | 变现。技术再强，说不清危害就拿不到价 |

这三者叠加的产物是一个具体的身位：**懂甲方资产、能打穿、还能证明打穿了的攻击者**。这个身位在乙方实验室值钱，在甲方安全部也值钱——这就是"保留选择权"的正确做法，不是靠学得杂，是靠组合稀缺。

### 一个必须说清的风险

你在厂商做安服，这个岗位有一条默认路径：**做 2-3 年标准化交付 → 转售前或项目经理**。那条路的技术复利接近于零，越走越难回头。

它不会以"你选错了"的形式出现，而是以"你越来越熟练"的形式出现。**熟练度增长 ≠ 能力增长**，这是这份大纲要防的第一件事。

## 二、分层判据：按可替代性，不按重要性

| 层 | 判据 | 投入占比 | 判断错的表现 |
|---|---|---|---|
| **精通** | 决策质量决定成败，且**结果无法事后验证对错**（没有标准答案） | 55% | 做不顺，整条链直接断 |
| **掌握** | 能审核输出、能定位失败原因、能改一版 | 30% | 只能照抄，出错不知道为什么 |
| **了解** | 知道它存在、知道何时调用、知道代价 | 15% | 不会主动想起用它 |

这个判据和 `_通用/03-AI协作边界` 的 G10 是同一件事的三层：**精通 = AI 无效层，掌握 = 加速层，了解 = 托管层**。

一句话记法：**AI 越擅长的，你越只需"了解"；AI 越帮不上的，你越必须"精通"。**

## 三、精通层（3 项，不能再多）

### P1 内网推进的决策链

**范围**：定位 → 凭据 → 提权 → 横向 → 域。不是漏洞类型，是链路段。

**为什么必须精通**：这是你押注的攻防深度，也是 AI 唯一帮不上的地方——AI 的输出是语料里的平均解，而防守方的检测规则恰好是拿平均攻击解喂出来的。走平均路线的人，正好是最容易被 SOC 抓的那一档。

**达标怎么验**（三条，缺一不算）：

| # | 验收 | 通过标准 |
|---|---|---|
| 1 | 单机定位 | 进任意 Windows 主机，10 分钟内不看清单列出 6 个定位动作，并说清每个"为什么是这个顺序" |
| 2 | 提权判别 | 给 `whoami /priv` + `systeminfo` + 服务列表，当场排出 3 条可行路径，按成功率排序，指出每条的前提失效点 |
| 3 | 横向选型 | 对着 EVTX 说出每种手法的落地文件与事件 ID，能从"对方看什么"反选手法，而不是从"我会什么"选 |

**当前缺口**（据能力自评）：Windows 平台认知是空的，思维是"找洞"不是"找人"。这两条不补，后面全部无效。

**AI 在这一层能干什么**：查命令、解释报错、生成一次性脚本。**不能干的**：决定下一步打哪、判断这台机器为什么打不动、预判防守方此刻在看什么。

---

### P2 漏洞验证与危害举证

**范围**：从"扫出一个告警"到"证明一个可复现的危害"，含定级、举证、自我否决。

**为什么必须精通**：这是你当下岗位的核心产出，也是唯一**现在就已经具备**的能力（自评 Q10 判为"已具备"，且你的定级口径比多数安服报告严）。它不该被当成"已经在做的事"忽略掉——这是你最该固化成判据、然后拿去换价的东西。

**达标怎么验**：

| # | 验收 | 通过标准 |
|---|---|---|
| 1 | 正向 | 任一漏洞：给出可直接复测的完整原始报文 + 按 能力×数据×体量 定级 + 一句话"这条能让甲方连夜改代码吗" |
| 2 | 反向 | 给 20 条扫描器告警，筛出 1 条真漏洞，其余 19 条逐条给出"不计"的理由 |
| 3 | 边界 | 能当场说出"这个洞我不报"的判断依据，且理由站得住 |

第 2 条是**成本最低、收益最高**的训练，而且你每天都在产生素材。

---

### P3 AI 工程化流水线

**范围**：把"重复的判断"变成"可复核的链"。不是学 AI 原理，是把采集→匹配→验证→报告接起来。

**为什么必须精通**：这是你押注的第二个方向，也是唯一能让你在 10-15 小时/周的条件下跑出别人全职效果的杠杆。

**但有一个前提必须说清**：这条**不能单独学**。脱离真实任务的"学 AI 工具"三个月就过期（G12）。正确形态是**寄生**——每个阶段把该阶段的重复劳动接进流水线，流水线是副产品，不是科目。

**达标怎么验**：同一条链跑第二遍时，人工步骤减少 50%，且每一步都留有原始输出可复核。**"用 AI 省了时间"不算达标，"第二遍比第一遍快一半"才算。**

**你已经有的底子**：fscan / spray / EHole + MCP + skills + workflows + Burp。这套东西的方向是对的，缺的不是更多组件，是"每跑一次真实项目就回灌一次"的闭环。

## 四、掌握层（能审、能改、能定位失败）

**统一验收标准**：给一个失败样本，30 分钟内定位失败发生在哪一层。做不到就是"了解"，不是"掌握"。

| # | 内容 | 为什么停在这一层 | 到什么程度就够 |
|---|---|---|---|
| M1 | 身份与认证（令牌 / 会话 / 完整性级别、NTLM / Kerberos、AD 结构） | 是 P1 的前置，判据密度最高的一块 | 能解释"工具为什么失败"，不要求背协议字段 |
| M2 | 代码阅读与审计（Java 为主） | **读是底座，审计是技能**；不会读，B 域上限锁死 | 先能看懂一个功能的数据流向，再谈定位 sink |
| M3 | C2 与基建 | 自研 C2 是团队级投入 | 能搭一条能用的、能说清暴露面、能改配置 |
| M4 | 免杀工程 | 军备竞赛，个人追不动 | 会用现成框架改，能说清在躲哪一层检测；**不写 loader** |
| M5 | 云 / 容器 / 虚拟化 | 客户环境正在往这走（ZStack 已碰到） | 能测常见错配：未授权 API、元数据、快照、镜像凭据 |
| M6 | 报告与合规口径（等保 / 攻防演练规则） | 是语言，不是能力 | 能和客户对上话，知道边界在哪 |
| M7 | Python 到"能写工具" | 不学工程化 | 能改现成脚本、写一次性 exp、处理扫描输出 |
| M8 | 资产测绘与暴露面推理 | **你的差异化加分项，但不是主押** | 能从台账推出"哪条路能通"，标注每条的前置条件 |
| M9 | 凭据体系（lsass / SAM / NTDS / DPAPI / 配置与浏览器） | 内网渗透一半时间在找凭据，不在打洞 | 能说出每种凭据存在哪、什么权限能取、取到能干什么 |
| M10 | 日志与检测（关键事件 ID、Sysmon、EDR 原理、日志侧攻击特征） | 你每天看日志，但从没学过日志怎么产生 | 看到一条告警，能反推它由什么行为触发、怎么避开 |
| M11 | 应急响应与处置（WebShell 处置、封禁依据、日志保全） | 你正在做，但依据没成文 | 每个处置动作能说出判据，且能说出误判后的回滚方式 |
| M12 | Web 漏洞利用工程（可用性判定，不是原理） | P2 举证的前提是"能打到" | 给一个点，能判断它通不通、缺哪个条件、补得上吗 |
| M13 | 数据处置与法律边界（授权范围、留存、销毁、披露） | **风险不对称，成本一小时** | 一页 checklist，任何项目开工前能对着念完 |
| M14 | AI 应用安全（prompt 注入、MCP 工具滥用、RAG 数据泄露） | 新战场，语料少，正好是 AI 帮不上的地方 | 能说出你的工具链有哪几个新的攻击面 |
| M15 | **数据库**（库表结构、账号权限模型、导出边界） | 底座板块，被判级工作直接依赖 | 能从注入点判断"能导出多少条、什么字段" |
| M16 | **密码学应用层**（hash / 加密 / 编码 / 签名的区分） | 底座板块，Q4 已栽（"hash 是加了密的"） | 拿到一个串，能判断它是哪一类、能不能逆 |
| M17 | **Web 应用架构**（IIS/Nginx/Tomcat/Spring 的请求流转） | 底座板块，"洞在哪一层"的前提 | 能说出一个请求经过谁、在哪一层被改写 |

**M8 单独说明**：你在甲方资产台账上花的时间，产出的是"从资产清单反推攻击路径"的能力。这个能力纯红队出身的人没有（他们拿到的是 IP 列表，不是组织关系），纯甲方的人也不会用。它现在排在掌握层，是因为你押注里没选它——但它是最容易变成个人标签的一块，别丢。

### M9–M14 是补遗，六块都漏不得

前面几版按"能力域"排，漏掉了这六块。它们都不是"以后再说"的类别，理由各不相同：

| 项 | 为什么漏不得 |
|---|---|
| **M9 凭据体系** | 已经被 Q4 暴露：你抓到本地管理员 hash 后，判断不出它"出不出得去这台机器"。内网渗透一半时间在找凭据、判断凭据的适用范围，不在打洞 |
| **M10 日志与检测** | 你每天看防火墙和终端日志，但从没系统学过**日志是怎么产生的**。这导致你会用告警、不会推演告警——而"不触发有效告警"要求的正是后者 |
| **M11 应急响应** | 你在做 IP 封禁和 WebShell 处置，但封禁依据是什么、误封怎么回滚，还没有成文判据。这是判断，不是知识 |
| **M12 Web 利用工程** | P2 举证的隐含前提是"能打到"。知道 SQL 注入原理，和真能从注入点拿到数据，中间隔着闭合方式、WAF、编码、库权限、文件读写条件五道门 |
| **M13 数据处置与边界** | **风险不对称**：一次数据处置事故能毁掉整个职业记录，而成本只有一小时。你现在接触大量客户真实数据，这条优先级不低 |
| **M14 AI 应用安全** | 你正在用 MCP + skills 搭工具链，等于在自己身上开了新的攻击面。这块语料新、公开案例少，正好是 AI 给不出平均解的地方 |

**共同点**：六块的判据密度都高、公开语料都少、AI 都给不了平均解——符合 [[03-AI协作边界]] 的分层标准，所以全部落在"掌握"，且必须自己攒。

## 五、了解层（知道何时调用，不学细节）

| 内容 | 为什么只到了解 |
|---|---|
| 漏洞原理细分类与绕过花式 | 知道"这类洞大概怎么打"就够，细节查得到 |
| 工具参数与用法 | 有 `--help` |
| 逆向 / 二进制 / 驱动 | 与你的身位无关，是另一个工种 |
| 密码学数学 | 会用原语即可，推导不是你的活 |
| AI 模型原理与训练 | 你是使用者，不是研究者（G12） |
| 语言深度（Java 生态 / Go） | 到"能读能改"，不到"能架构" |
| 社工话术库 | 需要时说得出原理，不背脚本 |
| 合规条文 | 查得到，且会变 |
| CTF 解题技巧 | 与实战能力相关性弱，成绩不等于能力 |
| 全量方法论框架（PTES / OWASP 通读） | 框架是给人看的，不是给人背的 |

### 原理性内容：不按学科分，按判据分

"计算机网络""操作系统"是**学科名，不是能力单元**，所以不能整体回答"要不要学"。拆成三类，处理方式完全不同：

| 类型 | 特征 | 处理 | 例子 |
|---|---|---|---|
| **判据型** | 出现在现场的选择题里，选错的代价不可逆；它是排除法的依据 | **必须内化**，但只能由卡点逐个触发，不能成课学 | TCP 连接状态、路由与 NAT、DNS 递归/迭代、令牌与完整性级别、代理与端口转发 |
| **解释型** | 不影响你的动作，只影响你的措辞；写报告时要一句 | **查** | TCP 拥塞控制算法、进程调度、文件系统实现、HTTP/2 帧格式 |
| **考试型** | 只存在于面试和教材里，现场永不出现 | **不学** | OSI 七层背诵、TCP 十一状态全图、算法复杂度、编译原理 |

怎么分？问一句：**"这个原理我答错，会不会做错动作？"** 会 → 判据型；只会说错话 → 解释型。

### 你必补的 6 个判据专题（共约 21 小时）

| 专题 | 它决定什么判断 | 时长 |
|---|---|---|
| TCP 连接生命周期（5 个关键状态） | 看到 `SYN_RECV` / `TIME_WAIT` 时，判断是扫描、断连还是中间设备 | 3h |
| 路由表 + NAT + 防火墙的包处理顺序 | "这个端口为什么不通"、"这台机器有几条出路" | 4h |
| DNS 解析链（递归 vs 迭代、缓存层级） | 内网域名解析失败，是 DNS 挂了还是网络挂了 | 3h |
| 代理 / 隧道 / 端口转发（SOCKS 与端口映射的差别） | 内网穿透走哪一跳、哪一跳断 | 4h |
| Windows 令牌 / 会话 / 完整性级别 | 提权路径活不活、能不能横向 | 4h |
| 内存保护与句柄（用户态 / 内核态边界） | 能不能读 lsass、注入会不会被 EDR 拦 | 3h |

**换算**：21 小时 ≈ 你两周的学习时间；而系统读一遍《计算机网络》+《操作系统概念》约 200 小时，且三个月后忘掉七成。**200 小时 ≈ 放弃四个月靶场，约 16 遍 Loop。**

**OS 教材那一套里，你需要的只有最后一行那一小块**——不是"操作系统"这门课，是"权限模型"这个专题。进程调度、内存分配算法、文件系统实现，对红队没有动作层面的影响。

### 怎么补：不做预测就不算补

每一条都用"预测 → 验证"闭合，不读书：

- **网络**：`tcpdump` + `curl -v` + `dig +trace`，先写下预测再跑，不符就只查那一条
- **OS**：在靶场里从"这个 exp 为什么打不成功"倒推

这个形态你 `Tech/网络基础/` 已经在跑（跑到 M3），定位是对的——"你缺的不是解释，是不看答案能不能预测一条链路的行为"。**别再另起一套教材，那等于把已有的训练场废掉。**

### 一个要防的陷阱

**"补原理"是最高级的拖延。** 它感觉像在学习，实际是在逃避"打不动靶场"的挫败感。判据很硬：**补的时候有没有一个具体卡点？** 有 → 补 30 分钟就停，立刻回去打；没有 → 会补成一本笔记，然后忘掉。

### 明确不做（第一年）

- 不刷靶场数量。**同一个环境打五遍 > 五个环境各一遍**（G01）
- 不按学科系统学网络和操作系统。判据型专题必须补（见上），解释型查得到，考试型不学
- 不追新工具。工具三个月换一茬，判据不变
- 不追求"全能"。第一年追求全能，第三年就是"什么都干过、什么都不精"
- 不为了简历学东西。凡是"学了但没产出"的，三个月后归零

## 六、不可替代性的三个来源

按你押注的顺序排：

| # | 来源 | 为什么 AI 拿不走 | 怎么积累 |
|---|---|---|---|
| 1 | **私有环境情报** | 客户网络长什么样、扫描器在哪漏、这个行业用什么密码——没有公开语料 | 每个项目结束 30 分钟内写一张卡，进 `_证据/` |
| 2 | **从报告到证据的转换** | AI 给平均口径，客户要的是**可辩护的判断** | 每条结论必须能指到实测报文；指不到就写"待验证" |
| 3 | **流水线速度** | 别人 10 小时跑 1 遍，你跑 3 遍——差距在次数上复利 | 每阶段把重复劳动接进流程，只接真的重复过的 |

第 3 条是杠杆，前两条是护城河。**护城河不修，杠杆只会让你更快地变成平均人。**

## 七、12 个月大纲

### 时间形态（比总量更重要）

10-15 小时/周，但**必须要分清两种时间**：

| 时段 | 时长 | 只能做什么 | 不能做什么 |
|---|---|---|---|
| 工作日晚上 | 3 × 1.5h | 读判据、写证据卡、审 AI 输出、复盘 | **打靶**（连续 2h 以下没有全局感，等于白打） |
| 周末整块 | 1 × 5h | 打靶、搭流水线、跑完整链 | 查资料（会碎掉整块时间） |
| 每月一次 | 2h | 方向自评 + 问题库清队列 | 学新东西 |

合计约 10h，弹性到 15h 时加打靶轮次，不加新科目。

### 阶段表

| 阶段 | 周期 | 焦点（只考核这一项） | 硬产出 | 验收 |
|---|---|---|---|---|
| **S0** | 3 周 | 把工作的剩余价值变成资产 | 情报卡模板 + 定级判据卡 + 一条最小流水线 | 下一次交付省 30% 时间 |
| **S1** | 3 个月 | 单机闭环：定位 + 提权（Loop 1-2） | 6 个定位动作的机制说明 + 提权路径判别表 | P1 验收 1、2 |
| **S2** | 2 个月 | 横向与痕迹（Loop 3） | 三种手法的落地文件 / 事件 ID 对照表 | P1 验收 3 |
| **S3** | 2 个月 | 整链质量 + 对抗（Loop 4-5，开 Defender/Sysmon） | 完整链路图 + 告警触发点清单 | 全程不触发有效告警，被触发能指出哪一步 |
| **S4** | 2 个月 | 域内最短路径（F） | 从普通域用户到域管的路径判定树 | 30 分钟内判断出最短路径且说清为什么不找漏洞 |
| **S5** | 1 个月 | C2 与基建（G） | 一条自建通道 + 暴露面分析 | 能说清"这条流量为什么不会被时序分析抓" |
| **S6** | 1 个月 | 限时决策 + 红队口径交付（Loop 6 + I） | 4h 限时链路 + 一份红队口径报告 | 能说清哪条路放弃、为什么 |

### S0 单独说，因为它是唯一"不学技术"的阶段

刚毕业最缺的不是知识，是**把工作变成复利的习惯**。三件事，20 小时做完：

1. **情报卡**：每个项目结束 30 分钟内，写清——这个环境长什么样、扫描器漏了什么、哪个告警是真的、我最初判断错在哪。进 `_证据/`。
2. **定级判据卡**：把 能力×数据×体量 压成一页 A4，含每级的举证要求。你已经有一套很严的口径，但它散在记忆里，没变成可交付的东西。
3. **最小流水线**：扫描结果 → 去重 / 初筛 → 人工复核清单。用现成工具加脚本，不上框架。

**为什么排在最前面**：它立刻省时间，而省下的时间就是后面 11 个月的预算。**先造杠杆，再用杠杆干活**——顺序反了，就永远没时间。

### 每阶段必做的三件事（不做等于没跑）

```
1. 一份原始记录进 _证据/       —— 原样粘贴，不改写、不补全"应该返回"的部分
2. 一个卡点进 _问题库/         —— 现象 + 猜测 + 实验设计 + 关闭条件
3. 一次复盘三问               —— 换防护还成立吗 / 路堵死还有别的吗 / 本质能迁到哪
```

## 八、方向探测：不靠想，靠做

你说不确定偏好。**兴趣在没做过之前是不存在的**，所以不要靠"想清楚"来决定，要靠"做过之后还愿不愿意做"来测。

**规则**：每 3 个月一次，只问一个问题——

> 过去三个月，哪件事让我愿意在下班后无偿再干 2 小时？

**判定**（第 12 个月做一次总结）：

| 现象 | 说明 | 走哪 |
|---|---|---|
| 无偿想打靶 | 攻防深度是真实偏好 | 乙方攻防实验室 / 红队 |
| 无偿想把流程理顺 | 工程化是真实偏好 | 安全工程 / 自动化 / 甲方安全建设 |
| 无偿想研究某个漏洞机理 | 研究偏好 | 漏洞研究（但要接受收入曲线更平） |
| 三个都没有 | 不是没兴趣，是**当前岗位没有给你足够的刺激** | 换环境优先于换方向 |

最后一行很重要：**很多时候不是你不喜欢这行，是这份工作里没有能让你喜欢的那部分。**

## 九、非技术（4 项，精简）

| # | 能力 | 为什么值得单列 | 到什么程度 |
|---|---|---|---|
| 1 | 一页纸结论 | 客户和领导只看第一页，后面是附件 | 任何事能用一页说清"结论 / 依据 / 建议" |
| 2 | 3 分钟口头汇报 | 决定你在会上有没有位置 | 讲清"做了什么、危害多大、建议什么"，不超时 |
| 3 | **授权与边界管理** | 安服最容易出事的地方，也是可迁移的护城河 | 每次测试前能说清"哪些不做、越界了怎么办" |
| 4 | 一次性输出 | 不做个人品牌，但要让作品可被检索 | 一年 4 次：内部技术分享 / GitHub / 复盘文章 |

第 3 项优先级最高。它对技术能力没有帮助，但它是唯一能让你的技术不被浪费的东西。
