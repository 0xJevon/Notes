## 一、时间形态决定内容形态

不是"什么重要排什么"，是"什么内容配什么时间"。排错了，同样的内容效果差一半。

| 内容类型 | 需要连续专注 | 需要动手 | 允许中断 | 放哪 |
|---|---|---|---|---|
| 机制/原理推演（掩码、NAT、令牌） | 中（30-60 分钟够） | 否 | 是 | **工作日** |
| 概念辨析（递归 vs 迭代、LSA vs 令牌） | 低 | 否 | 是 | **工作日** |
| 答题/写作（四空沉淀） | 中 | 否 | 是 | **工作日** |
| 打靶、搭环境、抓包排障 | **高（≥2h 才有全局感）** | **是** | **否** | **周末** |
| 读源码、调工具、写脚本 | 高 | 是 | 半 | 周末 |

**一条硬规则**：碎片时间禁止打靶。1.5 小时打靶只能打到"刚登进去"就结束，下一次要重新找状态，实际训练量接近零。

## 二、针对性学还是完整学：先看知识是哪种形状

这个问题没有统一答案，取决于知识的形状。三种形状，三种策略：

| 形状 | 特征 | 策略 | 属于它的内容 |
|---|---|---|---|
| **因果链型** | 缺一环整条断，前后强依赖 | **骨架必须完整**，血肉可以砍 | 计算机网络、认证协议、攻击链 |
| **清单型** | 条目之间互不依赖，用到才需要 | **针对性**，用到才查 | 工具、命令、漏洞类型、CVE |
| **模型型** | 范围小但必须能推演，不能只记结论 | **完整到能推演**，范围极小 | 权限模型、检测模型、定级模型 |

**网络属于第一类。** 所以答案是：**骨架完整、血肉针对性。**

具体到你的网络线：

| 单元 | 处理 | 理由 |
|---|---|---|
| M0-M3（地址/DNS/连接） | **必须做完** | 整条链的地基，M3 还有 4 条问题挂着 |
| **M9 NAT 与包过滤** | **提前，重点** | 你工作时天天遇到"内网为什么能上外网"、"这个端口为什么不通" |
| **M11 防火墙规则** | **提前，重点** | 你每天看防火墙日志，这是唯一能用真实数据验证的一章 |
| **M12 代理与负载均衡** | **提前** | 内网穿透、判断真实入口全靠它 |
| **M13 CDN 与缓存** | **提前** | 资产梳理时判断"这个 IP 是不是真的" |
| M4-M6（序号/窗口/以太网帧/信号） | **快过** | 知道现象即可，细节打靶时再回查 |
| M10（接入网/运营商） | **跳** | 与你的战场无关 |
| S4（TLS/HTTP2/云/容器） | **后置到第二年** | 现在用不上，等客户环境逼过来 |

**这里有一个顺序上的实质问题**：原地图是 M0→M18 的线性顺序，那是"一次请求的旅程"（客户端视角）。但你的工作需要的是**控制点视角**——谁能拦、在哪拦、方向如何。这两条线不一样。

所以建议把 S2 的核心四章（M9/M11/M12/M13）提到 M4-M6 前面。**先拿到能用的，再补齐细节。**

### 底座板块只有六块，不是几十块

和"计算机网络"同一个级别的东西，叫**底座板块**——它决定你理解世界怎么运转，而不是提供做事的手段。区别在于：**底座必须少而完整，工具可以多而浅。**

判断一个科目算不算底座，三问：

1. 它是不是**因果链的一环**？缺了后面推不动。
2. 是不是你**每次判断都要调用**？不是偶尔用一次。
3. 能不能被 AI 变成"查一下"？能，就不是底座。

| 底座板块 | 状态 | 说明 |
|---|---|---|
| **计算机网络** | 在学 | 骨架完整、血肉针对性（第二节已排） |
| **OS 权限模型** | 已在 M1 | 只补令牌/会话/完整性/句柄，不学教材那套 |
| **数据库** | **漏了，必须补** | SQL 语法 → 权限 → 文件读写 → 提权是一条链；且你的定级工作直接依赖它：`count`、分页 total、表结构、字段名。**不会数据库，拖库条数和数据边界都判不准** |
| **密码学应用层**（不是数学） | **漏了，必须补** | 只需搞清四组区分：hash / 加密 / 编码 / 签名；对称与非对称各用在哪；TLS 谁验谁；JWT 结构。**Q4 那句"hash 是加了密的"就是这块缺失** |
| **Web 应用架构** | 有料但不成体系 | 请求在 IIS / Nginx / Tomcat / Spring 里怎么流转、session 与 token、反代如何改变 Host 判断。这是"洞在哪一层"的底座 |
| **代码阅读**（不是审计） | 弱 | 看懂一个功能的数据从哪来、到哪去。不会读，B 域上限锁死 |

**明确不列**：数据结构与算法、编译原理、软件工程、微积分、离散数学。它们过不了第二问——你不需要每次判断都调用。

**Linux 系统层不用补**：那是你现有的强项，而且主战场在往 Windows 转。

**恶意代码分析只到轻量**：不看汇编，只看行为与配置——这个马干什么、外联地址在哪、怎么持久化。够用于监控和应急，不够用于样本研究。

**这四块为什么要新补**：网络解决"包怎么走"，数据库解决"数据长什么样、能不能拿走"，密码学应用解决"这个串是 hash 还是密文"，Web 架构解决"这个洞在哪一层"，代码阅读解决"这个功能谁在做什么"。五者互不替代，缺任何一块，判断都会停在术语层。

## 三、补遗：六块必须补的知识

前面按"能力域"排，漏了六块。它们的共同点是**判据密度高、公开语料少、AI 给不出平均解**——正好符合"必须自己攒"的标准。

| # | 知识块 | 现状 | 为什么漏不得 | 强度 |
|---|---|---|---|---|
| **M9** | **凭据体系**（lsass/SAM/NTDS.dit/DPAPI/配置/浏览器） | Q4 已暴露：抓到本地管理员 hash，判不出它出不出得去这台机器 | 内网渗透一半时间在找凭据、判断凭据的适用范围，不在打洞 | 精读 + 实测 |
| **M10** | **日志与检测**（事件 ID、Sysmon、EDR 原理、日志侧攻击特征） | 每天看日志，但从没学过日志怎么产生 | **会用告警 ≠ 能推演告警**，而"不触发有效告警"要的是后者 | 精读 + 用自己日志练 |
| **M11** | **应急响应与处置**（WebShell 处置、封禁依据、日志保全） | 正在做，依据没成文 | 封禁依据是什么、误封怎么回滚——这是判断，不是知识 | 建流程卡，不读书 |
| **M12** | **Web 漏洞利用工程**（可用性判定） | B 域有原理，缺"能不能打通" | 知道 SQLi 原理，和从注入点拿到数据，中间隔着闭合方式、WAF、编码、库权限、文件读写条件五道门 | 建判定表，不背原理 |
| **M13** | **数据处置与法律边界** | 未成文 | **风险不对称**：一次事故毁职业记录，成本一小时 | 一页 checklist |
| **M14** | **AI 应用安全**（prompt 注入、MCP 工具滥用、RAG 泄露） | 新 | 你在用 MCP + skills 搭工具链，等于自己开了新的攻击面 | 了解 + 一张攻击面图 |

### 第二轮再补（6-12 个月后）

| 内容 | 为什么现在不补 |
|---|---|
| 内网协议与服务攻击面全表（SMB/WMI/RPC/MSSQL/Redis/NFS…） | 清单型知识，用到才查。先有一张粗表，Loop 3 打的时候会自然填满 |
| 云与容器深入（K8s RBAC、元数据、对象存储） | ZStack 已碰但项目量少，等第二个云项目再深入 |
| 社工与钓鱼 | 你现在做安服不做红队项目，且涉及法律边界。先只学原理与授权边界 |
| 代码审计深入 | 研究岗的活，掌握层已经够 |

### 明确不补

逆向/二进制、密码学数学、AI 模型训练、语言深度、CTF 技巧、社工话术库、OSI 背诵——[[01-能力分层与学习大纲]] 的"了解层"与"明确不做"已经列过，不重复。

## 四、现有网络学习法：评审

### 好在哪（这四条别改）

| # | 设计 | 为什么是真好 |
|---|---|---|
| 1 | **先答后看 + 负知识保留** | 这是唯一能让训练量不为零的设计。多数人学网络是"读书+画图"，读完感觉懂了，一考就露 |
| 2 | **四空沉淀**（机制/矛盾/代价/失效条件） | 强制产出因果链。第四空"失效条件"是"真懂"和"记住"的分界线 |
| 3 | **闸三：阶段产物** | 单题对错只能证明"这一块懂"，全链路图才能证明"连起来通" |
| 4 | **问题库挂回访点** | 防止问题库变成坟场。绝大多数人的问题库三个月后就死了 |

### 三个要改的地方

#### 改动一：错误必须在第 2 次出现时当场收敛

**问题**：N04（单向可达）第 2 次复发、N08（分层归属）第 3 次、N09（有无应答）第 3 次。三条状态都是"稳定倾向"，处理方式都是"挂到后面的单元"。

**这是设计缺陷，不是执行问题。** "错题留着、反馈并列"防的是"改答案掩盖思路"，但它有个副作用：**允许带着同一个洞往前走，而且记录越详细越像在解决问题**。

**改法**：区分两种错，处理方式不同。

| 类型 | 判据 | 处理 |
|---|---|---|
| **概念洞** | 第一次出现，是"不知道" | 挂后，等对应单元 |
| **倾向洞** | **同一处第 2 次出现** | **当场收敛，不许挂后** |

倾向洞的收敛动作（3 分钟，当次做完）：

```
合上所有材料，把正确的推理链自己说一遍，录音或写下来
→ 说得出 → 拆掉"待验证"，标"已收敛"
→ 说不出 → 才是真的前置缺失，才允许挂，并写明缺哪一块
```

**记录不等于纠正。** 病历写得再详细，病还在。

#### 改动二：脚手架要递减

**问题**：一个单元 7 步、5 个文件、3 道闸、90 分钟。真正的学习时间（读书 20-30 + 答题 20-30）约占 55%，其余是流程。19 个单元走下来，流程成本会累积成"我一直在学习"的错觉。

**改法**：M6 之后降一次，S2 开始再降一次。

| 项 | M0-M6 | M7-M13 | S3/S4 |
|---|---|---|---|
| 导读 | 给机制 + 坑 + 页码 | 只给页码 + 一个坑 | 只给页码 |
| 答题 | 5 题 | 3 题 | 2 题（只问"什么时候失效"） |
| 沉淀 | 四空 | 三空（机制/代价/失效） | 两空（机制/失效） |
| 闸 | 每单元 | 每 2 单元 | 每阶段 |

**脚手架的用途是建起来，不是一直扶着。** 判断降得对不对：降级后错误率上升超过一倍，说明降早了，退回上一档。

#### 改动三：每个单元开工前挂一个本周的真实现象

**问题**：现在每个单元都在纵向深入，但没有机制保证"这个机制我工作时什么时候用"。学习地图写了"每个单元必须落到具体现象上"，但问答里没有强制动作。

**改法**：单元开工第一句，先写一行：

```
本周我在__（防火墙日志/DNS 报错/端口不通）里见到过__，我猜它是__机制。
```

这一行不判对错，只用来给知识挂锚点。**带着真实现象读，和空着读，吸收率不是一个量级。**

而且你有一个别人没有的条件：防火墙日志、终端告警、内网资产台账，每天都有现成的现象。别人要造场景，你只要抬头看。

## 五、可迁移到其他内容的五个元件

这套方法里真正值钱的不是"网络怎么学"，是五个可复用的元件。迁移到别的内容时，每个都要改一个参数：

| 元件 | 原来怎么用 | 迁移到实操（靶场/内网） | 要改的参数 |
|---|---|---|---|
| **先答后看** | 先答题再看反馈 | 先写下"我猜这台机器是__、能走__路"，再动手 | 答案从"文字"变成"预测" |
| **四空沉淀** | 机制/矛盾/代价/失效 | 机制/**前提**/代价/失效（"矛盾"换成"需要什么条件才成立"） | 第二空换掉 |
| **闸三产物** | 全链路图 | **攻击链图 + 痕迹清单** | 产物形态 |
| **问题库回访** | 每 3 单元口述 | 每轮 Loop 结束回访 | 触发点 |
| **90 分钟颗粒** | 一个单元 | **一次聚焦只练一个动作** | 单元定义 |

**不能直接迁移的两个**：

1. **"读书 + 答题"的形态**——实操不能靠答题，只能靠打。靶场里"答对了但打不出来"是常态。
2. **线性顺序**——网络线是 M0→M18 线性推进，因为知识有依赖；实操必须环形（每轮走完整链，只考核一个焦点），因为技能靠重复而非递进。

这两点就是 [[01-能力分层与学习大纲]] 里"工作日原理线 / 周末实操线"必须分开排的原因。**用同一种方法排两种内容，一定有一边是错的。**

## 六、立即做四件事（本周）

1. **做 M3 收口 + 回访 1**。4 条问题挂着，其中 2 条已第 3 次，不清掉就往下走是在堆债。
2. **给 N04 / N08 / N09 各做一次 3 分钟收敛**（合书口述正确推理链），说得出就拆"待验证"，说不出就写明缺哪块前置。
3. **改 M4-M6 的优先级**：M3 之后直接跳 M9 / M11 / M12 / M13，M4-M6 挪到阶段 B 的空隙快过。
4. **花 1 小时建"数据处置与法律边界"checklist**（M13）。不排进 17 周，因为它不依赖任何前置，而风险是不对称的：一次处置事故能毁掉整个职业记录，成本却只有一小时。内容就五项：授权范围怎么确认、拿到的数据存哪、留存多久、什么时候销毁怎么销毁、谁能看。
