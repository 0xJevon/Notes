# 网络基础 · 节点库

> **这个库不是课程笔记，是骨架。** 一行 = 一个要做的判断，不是一个知识点。
> 课程（导读、问答、反馈）只是施工队；建完之后会留下的，只有这张表和 [[_样本]]。

## 规则

1. **节点必须是判断，不能是名词。** 写「NAT」不算节点；写「出公网的包，源地址在哪一跳被改写」才算。判据：**这句话能不能回答「没有它会怎样」**。
2. **一个节点最多一行。** 一整行由三块拼成：判据（谁 → 做什么 → 得到什么）／什么时候不成立／现场形态（看到什么 → 判成什么）。
3. **没有「什么时候不成立」的节点是教条**（总纲硬规则 4），空着就是没立住。
4. **立住 = 两条都成立**：① 合书能说过程；② [[_样本]] 里同一节点有 ≥3 个不同场景的记录。只有 ① 是「学过」，两条都满足才是「会用」。
5. 节点被真实案例推翻时，**改这一行**，并把旧判断写进「什么时候不成立」——不要另起一行。

| **K01** | 对方在不在我这个网段，据此决定把包丢给谁  | 本机用掩码 AND 目的 IP 得到目的网络号 → 比本机网络号 → 同段就 ARP 对方直接发，不同段就 ARP 网关由它转发                                                                                                                                    | 两端掩码不一致：判定没坏、两端结论相反（单向可达）；地址规划混用；有人代答 ARP                                                                                          | 掩码配错时能 ping 通网关、ping 不通同网段主机                                                                                                 | 骨架 ✔ / 样本 0/3 |
| **K02** | 同一台机器上的多个站点，靠什么区分     | 浏览器按 HTTP 约定拼出字节流并带上 Host 头 → 服务端按 Host 匹配站点 → 匹配不到落默认站                                                                                                                                             | Host 缺失或填的是 IP：机制照常执行、结论不对；HTTP/1.1 下请求不合法（应回 400），1.0 下落默认站。注意「两个域名解析到同一 IP」不是失效，是正常形态                                            | 直接打 IP 或去掉 Host：回的是默认站页面，不是你要的那个站                                                                                            | 骨架 ✔ / 样本 0/3 |
| **K03** | 一个域名变成 IP，中间经过谁，哪一步会坏 | 应用调 resolver 向递归服务器**要答案**（递归：我要结果）→ 递归服务器未命中就从**根**往下逐层问路（迭代：下一台在哪）→ 顶级域指路 → 权威给答案 → 逐层返回并按 TTL 缓存。分层换来规模（不用一台存全表）、自治（各管各的权威）、抗毁（顶级坏了还有缓存和区域 NS）                                                   | 运营商递归强制缓存超过 TTL：机制没坏、改了记录等够时间还不生效，且等多久不可控；被劫持或污染：机制正常、IP 是错的；权威不可达：缓存撑一阵就失败。另记一句——**TTL 是请求不是保证，中间任一层都可以不理它**                      | `dig` 各层 TTL 不同＝各处缓存各自计时；改记录后不同出口看到不同 IP＝缓存未同步；失败时先分「有回应说没有」（NXDOMAIN）还是「没人应答」（超时）                                           | 骨架 ✔ / 样本 0/3 |
| **K04** | 一条连接是什么，靠什么唯一标识       | 套接字是内核里的一条记录（对端 IP/端口、本端 IP/端口、序号、窗口、状态），进程只拿到描述符 → **四元组**唯一确定一条连接 → 三次握手交换双方初始序号 ISN，把「两边从第几个字节开始数」对上表，之后每个字节都从 ISN 起算 → 服务端 accept 后那侧仍是监听端口（80），靠客户端的 IP+端口区分连接                                 | NAT 之后：服务端看到的源 IP 是出口地址，四元组不再指向真身；进程崩了连接不立刻消失（状态在内核，不在进程）；`TIME_WAIT` 占着四元组不放，**客户端**临时端口耗尽；服务端队列被半开连接占满（SYN flood，代价由对端控制）        | 同一远端两条连接仅本地端口不同＝四元组在工作；`netstat` 里几千行都是「本机.80 → 某客户端」＝服务端没换端口；堆 `CLOSE_WAIT` 是应用没关，堆 `TIME_WAIT` 是主动关多了                      | 骨架 ✔ / 样本 0/3 |
| **K05** | 一个包从 A 到 B，中间被谁改过     | 本机按目的 IP 查路由表选下一跳（最长前缀匹配）→ 用 ARP 把下一跳的 IP 换成 MAC，帧里「目的 MAC」这一栏填的**永远是下一个接棒者、不是终点**（同网段填对方，跨网段填网关）→ 每过一个**路由器**重写帧头（源 MAC 换成自己出口、目的 MAC 换成下一跳），**交换机只按 MAC 表转发、一个字段都不动** → 出公网时 NAT 改源 IP 和端口，靠转换表回程 | 跨网段根本没有「目的主机的 MAC」，帧里只能填网关的——这正说明 MAC 是逐跳的；过两层 NAT 就改两次 IP（家宽＋运营商大内网）；默认路由缺失时表内无匹配的包直接发不出去（No route to host）；表错不等于表不存在，表错的表现是绕路或黑洞 | `netstat -rn` 中 Flags 有 `G` 才走网关、Gateway 写 `link#N` 是直连；`arp -an` 里只有同网段的条目（就是这台机最近跟谁说过话）；`curl ifconfig.me` 与本机地址不同＝中间有 NAT | 骨架 ✔ / 样本 0/3 |
| **K06** | 目标前面隔着谁               | 按「谁在动手」分三层：**包过滤防火墙**在网络/传输层看五元组、不看内容；**反向代理**在应用层**终结 TCP**，按 Host/路径分流，源站看到的源 IP 是它；**CDN** 在 **DNS 层**改解析结果，域名不变、IP 换成就近边缘节点，请求压根没往源站去                                                                                                                                                     | 端口 open ≠ 服务在：`reset` 是有人明确拒绝、超时是没人理，两者指向完全不同；反代要看明文必须先终结 TLS，端到端加密／证书固定之后它瞎了，**但 SNI 仍明文**（除非 ECH）；CDN 只导得动可缓存／可拆开的 HTTP 流量，长连接只能透传不能加速，非 HTTP 协议根本进不来；**全端口 open 最可疑**（欺骗式应答或端口黑洞）                                                                                            | `dig` 出 CNAME 指向 CDN 厂商域名＝最硬证据；响应头有 `s-maxage`／`x-cache`／`via`／`x-air-*`＝中间有共享缓存；换 Host 打同一 IP 回不同站＝按域名分流；能握手却立刻断＝应用层拒绝，不是防火墙 | 骨架 ✔ / 样本 0/3 |
| **K07** | 加密发生在哪一层，证书在证明什么      | TLS 夹在 TCP 与 HTTP 之间（不是网络层加密）→ 握手先发 ClientHello 并**明文带 SNI** → 服务端回证书 → 客户端用上一级 CA 的公钥逐级验签，**一路验到本机预装的根证书库**（受信的源头是那 158 个文件，不是某家机构的声誉）→ 协商出会话密钥，之后 Host／路径／Cookie／Body 全是密文。**仍然明文的四样：目的 IP（否则路由器没法转发）、SNI、证书里的域名、流量大小与时间**                                                                                                                                          | **有人把根装进了这台机器：加密与验链全程正常，只是对面换了人**（企业流量审查、杀软 SSL 扫描、拿下终端后做凭据拦截）——判据是 `issuer` 变成公司名，不是「锁没了」；DNS 被劫持 + 签一张 DV 证书：证书真、域名也真，只有 IP 是假的（接 K03）；根本没上 TLS（`http://`）：不存在「破解」，本来就没锁；ECH 普及后 SNI 也看不见，只剩 IP 与流量特征。代价那一面：**每台中间设备都是睁眼瞎，包括你希望它看见内容的那台**（WAF／IDS／反代），所以企业只能靠装根重新看见——这一条同时解释了 2.3 的第三条                                                                                | 抓包能看到 SNI 明文；证书链里出现企业自签根                                                                                                     | 待写            |
