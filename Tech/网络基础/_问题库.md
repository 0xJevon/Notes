# 网络基础 · 问题库

> 按 G15，每条必须四样齐全：**现象 / 我的猜测 / 实验设计 / 关闭条件**。缺一样不许建。
> 关闭条件三层缺一不算关：能复现（操作层）+ 能解释（认知层）+ 能说失效条件（边界层）。
> `待验证` 超过 15 条 → 停输入，先清队列（H8）。当前 **9 条活着**。

## 回访计划

> **没有回访点的问题库就是坟场。** 但这条线只 7 个单元，不设批次、不设 60 秒口述——太重。
> 动作见 [[02-怎么用]] 第七节：第 1 轮结束后 D+2 / D+7 / D+30 各复述一次 [[_结论]] 的节点，复述不出的连回本库查。

| 时机 | 动作 |
|---|---|
| 每个单元开工前（1 分钟） | 扫一眼本单元相关条目，只看"现象"那行，不看结论 |
| 第 1 轮结束后 D+2 / D+7 / D+30（各 10 分钟） | 关书复述 [[_结论]] 的节点名与过程；讲不出的连同相关条目一起回退 `待验证`（排法见 [[02-怎么用]] 第七节） |
| 第 7 单元后（10 分钟） | 拿手绘全链路图当提纲，把 9 条活问题逐条过一遍 |

**哪条问题在哪个单元验**，一律写在条目自己的"回访"字段里，不再集中排批次。

### N04｜我只算发起方，不算响应方（单向可达性）

| | |
|---|---|
| **来源** | M0-Q4（10-28），答"A 能 ping 通 B" |
| **现象** | A/B 掩码不一致时，我判断"A→B 通、B→A 不通"，只推了 A 的发出，没推 B 的回包 |
| **我的猜测** | 我把"包能发出去"等同于"能通"，默认对方一定会回、且回得来 |
| **实验设计** | 两台虚机接同一交换机：A=`/24`，B=`/25`。① 先不给 B 配网关，双向 ping，抓包看 A 的 ICMP 到了 B、B 的 reply 走了哪；② 再给 B 配 `192.168.1.1`，双向 ping；③ 对比两次的路径跳数 |
| **关闭条件** | ① 能给任意一对地址判出双向可达性，并分别说出两端的判断依据；② 能说出"ping 通 = 去 + 回都成立"；③ 能说出单向通是**正常**的场景（防火墙单向策略、NAT 后外部不能主动连内部） |
| **状态** | **未达成，且已复发**（11-02）：M0-Q4 答「A 能 ping 通 B」（只算发出）；M1 沉淀 v3 又写「不带 Host 头会**发不出请求**」——同一处，只站发起方那一侧。已出现两次，说明这是稳定倾向而非偶发失误。M3 讲连接状态机时正面攻 |

| **我的猜测** | 我把"失效"理解成"这条链路走不通"，而不是"这条规则的结论不再成立" |

### N08｜我分不清每一层管哪一段，总把 A 的活算到 B 头上

| | |
|---|---|
| **来源** | M1-Q1、Q3、自评、沉淀（10-30），同一处反复栽 |
| **现象** | ① Q1「一个 IP 上可以搭建多个网站**并通过端口映射**网站服务」② Q3「HTTP/1.1 加了 Host 后就可以**通过端口**区分网站」③ 沉淀「浏览器不对请求拆解导致**服务端**不知道处理哪些请求」④ 沉淀「一条请求一条响应导致资源浪费」当成拆解机制的代价 |
| **我的猜测** | 我记住的是「有个动作/有个字段」，没记住它**管的是哪一段**，所以一到解释就把它挪到相邻那段上去 |
| **实验设计** | 用一张表把 IP / 端口 / Host / 路径 / DNS 五样各写一行：「它区分什么」「它不认识什么」「它错了会表现成什么样」。写完拿 M1 的四道题逐个套，看哪一行套不上 |
| **关闭条件** | ① 能对 IP、端口、Host、路径四者分别说出「区分什么」并各举一个反例；② 能说出某一样出错时，它的**上游**和**下游**各会看到什么现象（而不是一句「不通」）；③ 能说出这条边界在什么情况下被打破（例：反向代理按域名分流 = 把 Host 判断挪到了另一台机器上） |
| **状态** | **部分达成，已第 5 次**（11-04）：M1 端口/Host 混用 → M1 沉淀把服务端的活算给浏览器 → **M2-Q1 把 ICMP 归到传输层** → **M4-Q1 把「改 MAC」的活算给交换机** → **M5-Q2 把「按域名分流」答成「按 /a /b 路径分流」**（K02 刚立过骨架，没往回连）。IP 与 Host 的分工已能说对。**新形态一：进多层配合场景（交换/路由/NAT）角色就错位；新形态二：骨架立过但题目里想不到调用**。M6 沉淀时正面攻 |

### N09｜我分不清「对方明确说没有」和「对方根本没应答」

| | |
|---|---|
| **来源** | 诊断 Q2（10-27）→ M0 验证区（10-28）→ M2-Q5（11-02）→ M3 验证区（11-03），四次 |
| **现象** | ① 诊断 Q2：把 `cannot resolve` 和 `Request timeout` 混为一谈；② M0 验证区：`Time to live exceeded`（路由器明确回寄 ICMP，是「有回应但失败」）当成失败划掉；③ M2-Q5：DNS 配成不存在的地址，答「报错时间取决于缓存时间」（实为超时×重试，与缓存无关）；④ M3 验证区：`netstat -p tcp` 本来就只输出 TCP，却答「没看到 UDP，猜测没有 DNS 解析」——把观察工具的过滤当成了网络的全貌。**新形态：没看到 ≠ 没发生，先查自己的过滤器** |
| **我的猜测** | 我把「失败」当成一个结果，不分它是「有人告诉我失败了」还是「没人理我」。前者秒回、指向明确；后者要等满超时、指向链路或策略 |
| **实验设计** | 同一台机器做三组对照，记录**耗时**与**错误信息**：① 查一个不存在的域名（应得 NXDOMAIN，秒回）；② 把 DNS 指到 `10.255.255.1`（应得超时，10–30 秒）；③ ping 一个不存在的同网段 IP（应得 `Request timeout`）与 ping 一个 TTL 会被耗尽的目标（应得 `Time to live exceeded`）。四组并排看差别 |
| **关闭条件** | ① 能对任意一条失败现象，先判「有没有人回应」，再判「谁在回应」；② 能说出「有回应但失败」至少三种具体形态（ICMP 不可达／ICMP 超时／TCP RST／HTTP 4xx），以及各自的指向；③ 能说出为什么这个区分在安全场景里是分水岭（DNS 被劫持/被墙 = 超时；域名拼错 = NXDOMAIN；WAF 拦 = RST 或 403，处置路径完全不同） |
| **状态** | 待验证（单元 4 连接与端口时正面攻；单元 6 边界（RST / 403）时再用一次） |

### N11｜我把「加密」和「身份」当成同一件事

| | |
|---|---|
| **来源** | M6 沉淀 ③（11-05）：「证书被伪造比如用根签签名就**不会有 TLS 加密**」 |
| **现象** | 同一份文件的 Q2 第 3 问已经答对（装根后浏览器不告警，攻击者借此让本机信任恶意站点），沉淀里却退回到「没有加密」。**题里对、沉淀里错**——M5 那个病（知道但没调出来）的第二次 |
| **我的猜测** | 我脑中的 HTTPS 只有一个开关：有锁＝安全，没锁＝不安全。「对方是不是源站」这一层没有单独的位置，于是"装了根"被翻译成"锁没了" |
| **实验设计** | 用 mitmproxy（或 Charles）在本机装一次根，对同一次访问看三件事：① 地址栏的锁**还在**；② 点开证书，`issuer` 从 `GlobalSign` 变成 `mitmproxy`；③ 抓包里能看到完整的 URL 和请求体。再做对照：卸载根后同一步访问，浏览器立刻告警 |
| **关闭条件** | ① 对任意一次 HTTPS 会话，能把「加密了没有」和「对面是不是源站」分成两个独立问题回答；② 能说清装根后浏览器为什么不告警（链**确实**通到了本机受信根，它验的只有这一件事）；③ 能说出这个区分在红队里的用途——拿下终端后装根做凭据拦截，流量看起来一切正常，日志里只有一行 issuer 变了 |
| **状态** | 待验证（第 1 轮后 D+7 复述时自问一遍；`_样本` 里第一次撞到 issuer 异常时关） |
