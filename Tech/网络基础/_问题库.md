## 活着的问题

### N01｜我判断不出一个包该走 ARP 还是走网关

| | |
|---|---|
| **来源** | 诊断 Q3（2026-10-27），答"网关不在同网段，所以连 192.168.1.20 都不通" |
| **现象** | 给一个目的地址，无法稳定判出同网段/跨网段，进而判不出下一步 ARP 谁 |
| **我的猜测** | 我把"能通信"当成一个整体能力，没有把「同网段直连」和「跨网段经网关」拆成两条独立路径 |
| **实验设计** | M0-Q1 四个地址各写网络号计算过程 + 判定 + ARP 对象；M0-Q2 只改掩码看结论翻转；M0-Q4 单向 ping 的两个方向分别推 |
| **关闭条件** | ① 不看资料，对任意 `/24`–`/28` 给出一组地址，能在 60 秒内写出：网络号、是否同网段、ARP 谁；② 能说出"掩码决定的是广播域边界，不是地址计算工具"；③ 能说出这条判定在什么情况下失效（如代理 ARP、超网/VLSM 混用） |
| **状态** | 待验证 |

### N02｜我原以为内网地址必须"有外网地址"才能上网

| | |
|---|---|
| **来源** | 诊断 Q3 第二问，答案写"内网地址没有与外网通信的地址" |
| **现象** | 无法解释公司里全是 10.x/192.168.x 却人人能上网 |
| **我的猜测** | 我把"端到端可达"当成前提，不知道路径上存在改写地址的设备 |
| **实验设计** | M9（NAT）之前先自测：画出"我的 192.168.1.10 → 8.8.8.8"这一路，标出源 IP 在哪一跳改变的、改成什么；用 `traceroute` 找改写点 |
| **关闭条件** | ① 能说清 NAPT 在哪个设备、改哪个字段、靠什么表回程；② 能说出为什么 NAT 会破坏"端到端透明"以及这带来的一个实际后果（如某些协议要 ALG）；③ 能说出 IPv6 下为什么不需要它 |
| **状态** | 待验证（等 M9） |

### N03｜`/26` 的 62，我是算出来的还是记下来的

| | |
|---|---|
| **来源** | 诊断 Q5，只给了结果没给过程；要求补答 `192.168.1.0/26` 的网络地址与广播地址，尚未提交 |
| **现象** | 常见掩码的答案来得太快，怀疑是记忆而非推导 |
| **我的猜测** | 会算 /24、/25、/26，但换个不常见的（/27、/29、/30）就会卡 |
| **实验设计** | 随机取 3 个：`10.20.30.40/27`、`172.16.5.200/29`、`192.168.7.66/30`，各写网络地址、广播地址、可用范围、可用数 |
| **关闭条件** | ① 三个全对且过程可复现（不查表）；② 能说出"为什么 /31 和 /32 是特例"；③ 能说出 VLSM 划分时最容易踩的坑（地址重叠/网关占用） |
| **状态** | 待验证 |
