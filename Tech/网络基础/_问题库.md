### N01｜我判得出走 ARP 还是走网关，但说不清"用谁的掩码"

| | |
|---|---|
| **来源** | 诊断 Q3（10-27）→ M0-Q1 重考（10-28） |
| **现象** | M0-Q1 四个结论全对，但 (a) 是循环论证（拿"同网段"证"同网段"），(b)(d) 写"不清楚目的地址的网段怎么划分" |
| **我的猜测** | 我把掩码当成"地址的属性"，以为判断前要先知道对方的掩码 |
| **实验设计** | 不看资料，用自己的话回答：判断 `192.168.1.10/24 → 8.8.8.8` 时用的是谁的掩码？如果对方根本没有掩码配置，结论会变吗？ |

| **状态** | **部分达成**：①过关，②③未过 |

### N02｜内网地址为什么能上外网，我不知道中间发生了什么

| | |
|---|---|
| **来源** | 诊断 Q3 第二问 → M0-Q2 第 1 问（"可以，但原理不太清楚"） |
| **现象** | 知道结果是通，说不出源 IP 在哪一跳被改写、靠什么表回程 |

| **实验设计** | M9（NAT）之前自测：画出 `192.168.9.231 → 8.8.8.8` 这一路，标出源 IP 在哪一跳改变；配合 `traceroute` 找改写点 |

### N04｜我只算发起方，不算响应方（单向可达性）

| | |
|---|---|
| **来源** | M0-Q4（10-28），答"A 能 ping 通 B" |
| **现象** | A/B 掩码不一致时，我判断"A→B 通、B→A 不通"，只推了 A 的发出，没推 B 的回包 |
| **我的猜测** | 我把"包能发出去"等同于"能通"，默认对方一定会回、且回得来 |
| **实验设计** | 两台虚机接同一交换机：A=`/24`，B=`/25`。① 先不给 B 配网关，双向 ping，抓包看 A 的 ICMP 到了 B、B 的 reply 走了哪；② 再给 B 配 `192.168.1.1`，双向 ping；③ 对比两次的路径跳数 |
| **关闭条件** | ① 能给任意一对地址判出双向可达性，并分别说出两端的判断依据；② 能说出"ping 通 = 去 + 回都成立"；③ 能说出单向通是**正常**的场景（防火墙单向策略、NAT 后外部不能主动连内部） |
| **状态** | 待验证 |

### N05｜我把 ARP 当成了三层协议

| | |
|---|---|
| **来源** | M0-Q4（10-28），答"B 会把 ARP 回复返给网关 `192.168.1.128`" |
| **现象** | 认为 ARP 回复要经过网关；把子网网络地址 `192.168.1.128` 当成网关 |
| **我的猜测** | 我没有把 ARP 归到二层，也没意识到"网络地址不能分配给设备" |
| **实验设计** | M5 单元用 Wireshark 抓一次完整 ARP request / reply：看 reply 的目的 MAC 是不是请求者、整个交互有没有经过路由转发；再对 `192.168.1.128` 尝试 ping，看是否有人应答 |
| **关闭条件** | ① 能说出 ARP 报文封装在以太网帧里、reply 单播回请求者、全程不过路由器；② 能说出 ARP 为什么不需要掩码（点名 vs 路由决策）；③ 能说出为什么网络地址和广播地址不能分配给主机 |
| **状态** | 待验证（等 M5；M0 反馈已给答案，需自己复述一遍才算过） |

### N07｜我把「机制失效」写成「链路故障」

| | |
|---|---|
| **来源** | M0 沉淀 v1（10-28）：失效条件答成"网关 ARP 不到对端网关" |
| **现象** | 把设备坏了、链路断了当成机制失效；说不出"判定照常执行、但结论已经不对"的情况 |
| **我的猜测** | 我把"失效"理解成"这条链路走不通"，而不是"这条规则的结论不再成立" |
| **实验设计** | 给出任意一条判定规则，说出一种"规则本身没坏、但结论错了"的场景。至少三种：地址规划类（两端掩码不一致 / VLSM 混用）、二层欺骗类（有人替别人的地址应答）、以及代理转发类 |
| **关闭条件** | ① 能区分"故障"与"失效"并各举一例；② 能对任意一条学过的判定（掩码判定、路由表最长匹配、防火墙首条匹配）说出它的失效条件；③ 能说出这些失效的共同根源（单方面计算 / 无协商 / 信任默认值） |
| **状态** | **部分达成**：已能举一例「判定没坏、结论相反」（两端掩码不一致）；另两类（地址规划混用、有人代答 ARP）未触及。M5 抓 ARP 时验 |
