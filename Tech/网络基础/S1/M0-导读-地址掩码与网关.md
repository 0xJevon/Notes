## 1. 这个单元要回答什么

一台机器在发包之前，脑子里只判断一件事：

> **这个目的地址，是"自己人"还是"外人"？**

自己人 → 直接在局域网里喊。外人 → 交给网关。**没有第三种选择。**

网关不是"必须配置的东西"，它只是"外人的出口"。这个视角一换，Q3 那道题就不可能答错。

## 2. 核心机制

### 2.1 三件套各管什么

| 配置项 | 例子 | 职责 |
|---|---|---|
| 地址 | 192.168.1.10 | 我是谁 |
| 掩码 | /24（255.255.255.0） | **谁算自己人** |
| 网关 | 192.168.1.1 | 外人往哪送 |

注意职责划分：**掩码决定"判断标准"，网关决定"外人出口"。** 两个功能完全不同，很多人把它们混着记。

### 2.2 判定流程（就三步）

```text
本机：192.168.1.10/24        网关：192.168.1.1

【目的 192.168.1.20】
① 本机网络号  = 192.168.1.10 AND 255.255.255.0 = 192.168.1.0
② 目的网络号  = 192.168.1.20 AND 255.255.255.0 = 192.168.1.0
③ 相同 → 同网段 → ARP 问"谁是 192.168.1.20" → 直接发（不经过网关）

【目的 8.8.8.8】
② 目的网络号  = 8.8.8.0  ≠ 192.168.1.0
③ 不同 → 跨网段 → 查路由表 → 下一跳 = 网关
                → ARP 问"谁是网关 192.168.1.1" → 发给网关
```

**这里有一句必须刻进去的话：**

> **ARP 问的永远是"下一跳"，不是"最终目的地"。**

发给 8.8.8.8 的包，以太网帧的目的 MAC 是**网关的 MAC**，不是 8.8.8.8 的 MAC（你根本不知道它的 MAC，也不该知道）。IP 头里写 8.8.8.8，MAC 头里写网关——**这就是"封装"最直观的一次体现**（M5 展开）。

### 2.3 掩码的算法：网络号 = IP AND 掩码

`192.168.1.0/26` 完整拆解：

| 项目 | 值 | 怎么来的 |
|---|---|---|
| 前缀长度 | /26 | 前 26 位是网络位 |
| 主机位数 | 32 − 26 = 6 | 剩下 6 位给主机 |
| 本子网地址总数 | 2^6 = 64 | |
| 可用地址数 | 64 − 2 = 62 | 扣掉网络地址和广播地址 |
| 掩码 | 255.255.255.192 | 前 26 位为 1 |

一个 /24 被切成 4 个 /26：

| 子网 | 网络地址 | 可用范围 | 广播地址 |
|---|---|---|---|
| 1 | .0 | .1 – .62 | .63 |
| 2 | .64 | .65 – .126 | .127 |
| 3 | .128 | .129 – .190 | .191 |
| 4 | .192 | .193 – .254 | .255 |

**定义要记死的两条（比记 254 这个数字重要得多）：**
- 网络地址 = **主机位全 0**
- 广播地址 = **主机位全 1**

在 /24 里它们恰好是 .0 和 .255，所以很多人误以为"扣掉 0 和 255"是通用规则。**在 /26 里，第二个子网的网络地址是 .64，广播地址是 .127——根本不是 0 和 255。**

## 3. 为什么必须划网段（这才是"深入理解"的部分）

大多数人学掩码只学到"会算地址"，但真正的问题是：**为什么要有网段这个概念？**

答案是**广播**。

以太网是一个广播介质：一台机器发一个广播帧，**同一广播域内所有机器都要停下来处理它**。广播域越大，无谓消耗越多；一旦出现广播风暴，整片网络会被打到瘫痪。

所以必须切分广播域。用什么切？

- **交换机不切**——它只转发，广播照旧扩散到所有端口
- **路由器切**——路由器**不转发广播**，广播到此为止

于是有了这条因果链：

```text
广播必须被限制
   → 必须用路由器隔开
      → 路由器每个接口后面就是一片广播域
         → 这片广播域的边界，就是"网段"
            → 掩码，就是宣告这个边界的写法
```

**结论：掩码的本质不是"地址计算工具"，是"广播域的边界"。** 这句话能解释后面很多事，包括为什么网关必须和本机同网段——因为 **ARP 是广播，广播过不了路由器**。

这就回答了"为什么网关必须在同网段"这个配置规定的根因：不是规定如此，是物理上做不到。

## 4. 代价：网段划得越细越好吗

不是。切分是有代价的：

| 划细的好处 | 划细的代价 |
|---|---|
| 广播域小，干扰少 | 跨网段流量必须过路由器，多一跳、多一次排队 |
| 故障域小，好定位 | 路由器成为瓶颈和单点 |
| 便于按部门/安全等级隔离策略 | 路由条目变多，规划与维护成本上升 |

所以你看到的企业网通常是"按功能/安全区划网段"（办公、DMZ、生产、管理），而不是"每个机柜一个网段"。**这又是那个主旋律：所有网络设计都是在矛盾目标之间取平衡。**

## 6. 动手验证（10 分钟）

```bash
# 1. 看清自己的三件套
ifconfig | grep -A3 "en0"          # 看 inet / netmask
netstat -rn | head -5              # 看默认路由（default 那一行）

# 2. 看 ARP 表怎么长出来的
arp -a                             # 先看现状
ping -c 2 192.168.1.1              # 同网段的网关
arp -a                             # 再看一次：多了一条记录

# 3. 验证"跨网段时 ARP 的是网关"
ping -c 2 8.8.8.8
arp -a                             # 表里不会出现 8.8.8.8，只有网关
```

**第 3 步是本单元最重要的验证**：你会发现 ARP 表里只有网关的 MAC，没有 8.8.8.8 的。这就是"ARP 问的是下一跳"的直接证据。

再算一遍：

```bash
python3 -c "
import ipaddress
n=ipaddress.ip_network('192.168.1.0/26')
print(n, n.network_address, n.broadcast_address, n.num_addresses, list(n.hosts())[0], list(n.hosts())[-1])
"
```
