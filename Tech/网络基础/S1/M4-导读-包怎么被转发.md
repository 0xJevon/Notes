# M4 包怎么被转发

> 归属：[[00-学习地图]] ｜ 答题：[[M4-问答]] ｜ 上一单元：[[M3-导读-套接字与连接]]

## 1. 这个单元要回答什么

一个问题：**你的包从网卡出去，到你打的那个 IP，中间被谁碰过、被改了什么。**

这一单元把三件事压在一起讲，因为它们本来就是一条链上的三个动作：

| 谁 | 看什么决定往哪送 | 改什么 |
|---|---|---|
| 交换机 | 目的 MAC 查 MAC 表 | 什么都不改，只转发 |
| 路由器 | 目的 IP 查路由表 | 改**源/目的 MAC**（重写帧头），IP 不动 |
| NAT 设备（通常是出口路由器/防火墙） | 查转换表 | 改**源 IP 和源端口** |

**一个包在路上被改 MAC 很多次，被改 IP 通常一次（出公网那次）。** 记住这一句，很多现象就通了。

## 2. 核心机制

### 2.1 为什么既要 IP 又要 MAC

分工一句话：**IP 是"最终要去哪"（端到端，全程不变）；MAC 是"下一跳交给谁"（逐跳，每跳换一次）。**

```text
你 192.168.1.10 ──┐        路由器 A          路由器 B        目标 8.8.8.8
                  │  帧: 目的MAC=A的MAC
                  ├──────────────→ │
                  │                │  帧: 目的MAC=B的MAC（重写）
                  │                ├──────────────→ │
                  │                │                │  帧: 目的MAC=目标的MAC
                  │                │                ├──────────────→
  源IP/目的IP 全程不变：192.168.1.10 → 8.8.8.8（直到 NAT 那一次）
```

所以：**交换机不认识 IP，路由器才认识 IP**。交换机只负责"这一小段里，这个 MAC 在哪个口后面"。

### 2.2 路由器怎么决定下一跳

每个路由器维护一张路由表，规则是**最长前缀匹配**：目的地址同时符合多条时，选**掩码最长（最具体）**的那条。

```text
目的网段          下一跳
192.168.1.0/24    直连          ← 命中这条就走这条
0.0.0.0/0         192.168.1.1   ← 默认路由，谁都不匹配时才用
```

`0.0.0.0/0` 就是默认路由（"其余全部"）。你自己机器上的 `default` 那行就是它——它的下一跳就是网关。**这也回答了单元 1 的遗留问题：网关这个角色，就是"默认路由指向的那台设备"。**

### 2.3 NAT：改地址，还要记账

内网地址不能出现在公网上（私网段不可路由），所以出口设备做**地址转换**：

```text
出去：192.168.1.10:52341  →  1.2.3.4:61000
回程：1.2.3.4:61000        →  192.168.1.10:52341
```

关键是**为什么要改端口**：如果只改 IP 不改端口，内网两台机器恰好都用 52341 连同一个目标，回包就分不清该给谁。**改端口是为了让"回来的包"能被唯一认领**——所以它叫 NAPT（网络地址端口转换），靠一张转换表记账。

这条记账有一个直接后果：**表里没有的，回不来。** 所以外部不能主动连内部——这是 NAT 的副作用，不是防火墙的功劳（K06 会分清这两件事）。

## 4. 为什么这样设计

**为什么不让交换机直接按 IP 转发？** 因为那要求每台交换机记住全网所有地址，规模一大就崩。分成"逐跳的 MAC"+"端到端的 IP"，等于把"全局寻址"和"本地投递"分开——每台设备只需要知道自己那一小段。

**NAT 的代价**：破坏了端到端透明。外面无法主动访问内网，任何需要"从外向内建连"的协议都要额外打洞或加 ALG。IPv6 不需要 NAT，也是因为它地址够多，不需要靠复用地址省。

## 5. 动手验证（可选，2 分钟）

```bash
# 看自己的路由表：找 default 那行，它的 gateway 就是你的网关
netstat -rn -f inet | head -8

# 看一个包走到目标要经过几跳（每行就是一个路由器）
traceroute -n -m 8 8.8.8.8

# 看本机的 ARP 缓存：哪些 IP 已经换成了 MAC
arp -an | head -5
```

三样东西对照看：**路由表决定交给谁，ARP 把那个 IP 换成 MAC，traceroute 让你看见沿途的路由器。** 三者是一条链。

## 6. 钩子（不设题，下一单元用）

- 你的公网出口 IP 是多少？用 `curl ifconfig.me` 看，再和本机 `ifconfig` 的地址比——**不一样就说明中间有 NAT**。
- 公司里访问不到某个外网服务，是路由不通、NAT 没放行、还是防火墙拦了？这三种现象长得很像，K06 才分得开。
