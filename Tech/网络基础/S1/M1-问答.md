### Q1｜推演：交给下一层的到底是什么

`GET http://a.example.com:8080/x?y=1` 这个请求，浏览器最终要交给操作系统的，**不是 URL 这个字符串**。

请说清楚：它具体交出去的是哪几样东西？（提示：其中一样是字节流，另有两项是"目的地"的组成部分）

如果只能交出一个 IP 而不知道端口，会发生什么？

**我的回答**：HTTP协议，主机名a.example.com和端口8080，程序x和参数y=1。因为一个IP上可以搭建多个网站并通过端口映射网站服务，所以只有IP操作系统并不知道要将请求内容交给哪个网站服务器处理自然得不到任何响应。

### Q2｜反例：这句话错在哪

> "HTTP 是无状态协议，服务端不会记得你，所以 HTTP 根本做不了登录功能。"

这句话哪一半是对的，哪一半是错的？错的那一半，靠什么补上的？补上之后，"HTTP 无状态"这句话还成立吗？

**我的回答**：HTTP是无状态协议，所以服务端记不到客户端是正确的，为了通过HTTP实现登录功能添加了Cookie、Session和Token等机制，客户端登录后为用户颁发这些识别标识从而实现认证用户身份的功能，所以通过HTTP可以做登录功能但是通过其他机制实现的所以HTTP还是无状态的。

### Q3｜预测：把 Host 头拿掉会怎样

假设时间回到 HTTP/1.0，没有 Host 头。某公司只有一个公网 IP，却想在这个 IP 上同时提供 `www.a.com` 和 `mail.a.com` 两个完全不同的网站。

在当时，这件事能做到吗？如果做不到，他们有哪些变通的笨办法？HTTP/1.1 加了 Host 之后，为什么这个限制就消失了？

**我的回答**：做不到，因为HTTP/1.0强制绑定一个IP对应一个网站，将公网IP绑定到a.com，然后通过目录访问以实现可访问不同的两个网站。HTTP/1.1加了Host后就可以通过端口区分要访问的网站了，所以可以在一个IP上提供不同的网站。

### Q4｜归因：为什么"加载完成"了图还在转

浏览器状态栏已经显示"完成"，但页面里的图片还在一个个慢慢出来。

请用"请求-响应"模型解释这个现象的成因。并回答：**如果这个页面在 HTTP/1.1 下打开很慢，换到 HTTP/2 会明显变快，原因是什么？**（这题超纲一点，答不出没关系，说出你的猜测即可）

**我的回答**：状态栏显示完成是对网站页面的请求完成了，但每个请求对应一个响应所以页面中的图片也需要通过请求加载，图片的加载也会有大小和先后顺序的区别所以是一个个慢慢出来。我猜底层应该还是一样需要对资源分别请求但请求资源的格式可能换成更适应传输的格式，然后请求的方式也类似并发请求可以异步传输请求并返回响应。

### Q5｜推演：换成二进制协议，这些概念还在吗

HTTP/1.1 是文本协议，有"请求行""消息头"这些说法。HTTP/2 改成了二进制帧。

那么"这是一个 GET 请求""我要访问 /x""我的 Host 是 a.com"这三条**信息**还在吗？如果还在，它们变成了什么形式？

由此追问一句：**协议"长什么样"和协议"表达什么"，是同一件事吗？**

**我的回答**：还在只是从原本的格式换成了二进制格式。协议长什么样只是对于人而言的，文本协议方便人阅读但底层都是二进制数据，因为完成操作的始终是计算机，如同汇编与二进制码一样，汇编只是方便人识别但计算机操作的始终是二进制码，所以长什么样对于计算机而言没区别，表达的是什么，要完成什么操作才重要。

### Q6｜前瞻：加密之后 Host 藏起来了

承 Q3：Host 头让一台机器能服务多个网站。但 HTTPS 把整个 HTTP 报文加密了，服务器在解密之前看不到 Host。

那它**怎么在解密之前就知道该用哪张证书**？如果这一步做不到，会发生什么后果？

（这题是本单元的伏笔，答不出完全正常——请写下你的猜测，答完 M15 我们回头对答案）

**我的回答**：可能有个第三方机构去辨别网站使用的证书，然后告知服务器该什么什么证书解密，如果服务器在解密前不知道要使用哪张证书自然不能完成HTTPS报文的解密，识别不出Host头自然就不知道请求该给哪个服务器也就无法返回响应消息。

## 沉淀（本单元唯一入库物）

> **先确认「这个机制」指哪一条**——不是整章的主题，是导读第 2 节「核心机制」里那条**判定/流程**。
> 找不到就问自己一句：**「这一课到底在教我做一个什么判断？」**
>
> **M1 的答案在导读第 2 节**：本单元要你抓到的是「一条 HTTP 请求报文是怎么被拼出来的」，以及 Host 头在里面承担什么。别把「HTTP 是什么」当成机制。

**按四个空填，别写成一段散文**（散文会掩盖空缺）：

| 空 | 填什么 |
|---|---|
| ① 机制 | （谁）在 ______ 时，用 ______ 算出 ______，据此决定 ______ |
| ② 它解决的矛盾 | 没有它，会退化成什么笨办法 / 出什么乱子 |
| ③ 代价 | 这样做牺牲了什么（一定有的，找不到就是没读透） |
| ④ 失效条件 | 什么情况下这条不成立 |

**我的结论**（把 ①②③④ 串成 2–3 句自己的话，不许分点照抄）：
机制是浏览器通过HTTP协议获得网站服务时会对URL进行拆解，分为主机名、端口、服务器目录、文件及参数等，据此决定服务器等响应，是返回文本还是程序结果。没有该机制会导致服务请求的混乱，浏览器不对请求目标进行拆解导致服务端不知道处理哪些请求，对请求作出怎样的响应。这样做牺牲了请求效率，一条请求对应一条响应会导致资源的浪费。
