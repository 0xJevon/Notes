### Q1｜概念：什么被改，什么不变

一个包从你的机器（`192.168.1.10`）发到 `8.8.8.8`，经过两台路由器后出公网。

1. 一路上**源 MAC、目的 MAC、源 IP、目的 IP** 这四项，哪些会被改、哪些不变？分别在哪一跳被改？
2. 为什么必须这么分工——为什么不干脆让交换机也按 IP 转发？
3. 如果目标是 `192.168.1.20`（同网段），这个包会经过路由器吗？为什么？

**我的回答**：
目的IP始终不变，源IP会在出公网时经由地址转换变为公网IP，源MAC和目的MAC会在交换机转发下一跳时改变。交换机如果也按IP转发则需要记住大量的IP，不适合规模大的网络，现在这样IP负责传包，MAC负责寻址的设计更稳定。应该不会吧，同网段直接ARP对方获得MAC之后就能发包。
**反馈**：

**1、3 对，2 里有两处角色说反——这一单元的核心就是这个分工，得抠。**

**第 1 问的后半句错了：改 MAC 的不是交换机，是路由器。**

交换机不看 IP，也**不改任何字段**——它只是把帧从另一个口送出去，源 MAC、目的 MAC 原样不动。每过一个路由器，路由器用自己的 MAC 当源、下一跳的 MAC 当目的，**把整个帧头重写一遍**。

```text
本机 → 交换机 → 路由器A → 路由器B → 目的
       ↑ 只转发      ↑ 重写帧头    ↑ 重写帧头
```

一句记法：**交换机转发帧，路由器重写帧再转发。**

**第 2 问规模答对了，但「IP 负责传包，MAC 负责寻址」说反了。**

- **IP 负责寻址**：最终要去哪，端到端，全程不变
- **MAC 负责投递**：这一小段里交给谁，逐跳换

你在第 1 问其实答对了"IP 不变、MAC 变"，第 2 问却把两个角色对调——说明你记住的是"两个东西配合着用"，没记住"各自管哪一段"。这两句在排障时是分水岭：查不通时先问"是端到端的目的到不了（IP/路由），还是这一跳交不出去（ARP/MAC）"。

**第 3 问对**：同网段 ARP 到对端 MAC 直接发，不过路由器。

### Q2｜过程：路由表怎么决定下一跳

下面是一张真实的路由表（macOS 的 `netstat -rn -f inet`，已截断）：

```text
Destination        Gateway            Flags        Netif Expire
default            192.168.68.1       UGScg          en0
127                127.0.0.1          UCS            lo0
192.168.68.0/24    link#11            UCS            en0
192.168.68.1/32    0:11:22:33:44:55   UHLWIir       en0
```

1. 一个包发往 `8.8.8.8`，走哪一行？为什么？它的下一跳是谁？
2. 一个包发往 `192.168.68.50`，走哪一行？这个包会不会经过网关？
3. `default` 那行如果被删掉，会发生什么？

**我的回答**：
走默认路由，因为路由表没有该8.8.8.8对应的IP，下一跳是192.168.68.1
走192.168.68.0/24，需要看是不是跨网段发包，如果是则需要网关代为传包，不是就可以直接传包
会导致为写入路由表中的IP找不到发包的IP直接被丢弃
**反馈**：

**1 ✔、3 ✔（一般报 `No route to host`），2 是空的。**

**第 2 问：`192.168.68.50` 就在 `192.168.68.0/24` 里，不跨段，不经网关。**

你答"要看是不是跨网段"——这就是把题目给的规则原样复述了一遍，没有落到那个具体地址上算一下。它就在里面，一眼能看出来。

**判据不用猜，表里写着**：

| 看哪 | 含义 |
|---|---|
| Gateway 列写 `link#11` | **直连**，从这个口直接发，ARP 对端拿 MAC |
| Gateway 列写一个 IP（如 `192.168.68.1`） | **要交给网关**转发 |
| Flags 里有 `G` | gateway 路由（要经网关） |
| Flags 里没有 `G` | 直连路由 |

对照看：`default` 是 `UGScg`——**有 G**，所以 8.8.8.8 交给 .1；`192.168.68.0/24` 是 `UCS`——**没有 G**，所以同段直接发。

这张表是整个网络排障的第一个岔路口：**"不通"要先分是"根本没发出去（没路由）"还是"发出去了没人接（ARP/链路/策略）"。** 你现在能读 Gateway 列，这个岔路口就通了。

### Q3｜判定：NAT 靠什么把回包认领回去

内网两台机器，出口设备做了 NAT：

```text
A：192.168.1.10:52341  →  1.2.3.4:61000  →  8.8.8.8:53
B：192.168.1.11:52341  →  1.2.3.4:61001  →  8.8.8.8:53
```

1. 回包到达出口时是 `1.2.3.4:61000`，设备怎么知道该给 A 而不是 B？靠什么查？
2. **为什么 A 和 B 用了同一个源端口 52341，却没有冲突？** 如果 NAT 只改 IP、不改端口，会出什么问题？
3. 现在外部一台机器想主动连 `192.168.1.10` 的 80 端口，能连上吗？为什么？**这是 NAT 的副作用还是防火墙的拦截？**

**我的回答**：
NAT表中会记录1.2.3.4:61000是由内网地址192.168.1.10:52341转换来的，所以设备知道该给A
因为二者转换为公网地址同时修改了IP和端口所以不会有冲突，如果NAT只改IP不改端口则会导致如果两个内网地址的端口相同，在进行地址转换时就会发生冲突
不行，因为外部机器的地址在NAT表中没有记录，也就无法转换为内网地址，也就无法连上内网IP的端口，这是NAT的副作用
**反馈**：

**三问全对。** 第 3 问还接住了钩子——"这是 NAT 的副作用"，不是防火墙拦的。这两个在现象上一模一样（都是"连不上"），但处置路径完全不同：NAT 要加端口映射，防火墙要改规则。**分错这一条，就会去改不该改的东西。**

补一句第 2 问背后那句话，你已经摸到了但没说透：**改端口的根本目的不是"避免冲突"，是"让回包能被唯一认领"。** 冲突只是这个目的的反面——认领不了，就是冲突。

顺带记一个现场形态：你在自己机器上 `curl ifconfig.me` 得到 `182.150.27.68`，而本机是 `192.168.68.195`——**两个不一样，就是 NAT 在中间**。以后判断"我在几层 NAT 后面"，就看这几个地址差多少。

## 动手验证（可选，2 分钟，不做不影响判定）

> 三样东西对照看，能串成一条链就够了。

```bash
netstat -rn -f inet | head -6     # 路由表：default 那行的 gateway 就是网关
Routing tables

Internet:
Destination        Gateway            Flags               Netif Expire
default            192.168.68.1       UGScg                 en0
127                127.0.0.1          UCS                   lo0
127.0.0.1          127.0.0.1          UH                    lo0
169.254            link#14            UCS                   en0      !

arp -an | head -5                 # ARP 缓存：IP 已经换成了哪个 MAC
? (192.168.68.1) at fc:60:9b:82:ad:85 on en0 ifscope [ethernet]
? (192.168.68.20) at 46:8c:fc:23:84:ef on en0 ifscope [ethernet]
? (192.168.68.34) at c2:23:9a:98:70:18 on en0 ifscope [ethernet]
? (192.168.68.42) at 4:f0:ee:d:37:75 on en0 ifscope [ethernet]
? (192.168.68.74) at 7c:b2:7d:bb:5c:a1 on en0 ifscope [ethernet]

curl -s ifconfig.me; echo        # 出口公网 IP，和本机地址比一比
182.150.27.68
```

**我看到了什么**（跑了才写）：我期待看到路由表也确实看到了默认路由对应的网关是192.168.68.1，看到了网关ip对应的MAC地址，但ARP只知道是转换IP为MAC的协议，公网IP就是除那三类私有地址外的地址。

**验证区批注（2026-11-04）**：

**你跑出了整条链最关键的一条证据，但没读出结论。**

```text
本机     192.168.68.195
出口     182.150.27.68
```

**两个地址不一样 → 你的包出去时被改过 → 中间有 NAT。** 这就是 K05 的现场形态，比任何定义都硬。

你把公网 IP 当成了定义题（"公网 IP 是除私有地址外的地址"）——那是背的。这题要的是推论：**拿两个地址一比，就能判出自己在 NAT 后面，还能判出 NAT 在你这台机器的上游某一个设备上。**

另外两处：

- `arp -an` 前五行不全是网关。第一条 `.1` 是网关，后面 `.20/.34/.42/.74` 是你最近通信过的**同网段其他设备**。ARP 缓存里就是"这台机最近跟谁说过话"，这个视角以后查内网存活很有用。
- `169.254` 那条是网卡没拿到 DHCP 时自己编的地址（link-local），说明有个接口没配上，可以忽略。

## 沉淀（本单元唯一入库物）

> **先确认「这个机制」指哪一条**：不是整章主题，是导读第 2 节里那条**判定/流程**。
> M4 的那条是：**一个包在路上按什么规则换手、哪个字段在第几跳被改。**

| 格 | 填什么 |
|---|---|
| ① 过程 | ______ 先 ______，然后 ______，最后 ______ |
| ② 为什么这样设计 | 不这么做会 ______；代价是 ______ |
| ③ 什么时候不成立 | 如果 ______，这套就不适用 |

**我的结论**（三格串成 2–3 句自己的话，不许分点照抄）：
通过IP发包源目IP在内网内不会改变，源目MAC在交换机给到下一跳路由时会改变，源IP会在出公网时通过NAT表重新分配修改为公网IP。不这样发包而是由MAC直接向IP发包则会导致大规模网络因IP地址过多导致错误，代价就是需要记录路由表，如果表中未记录对应IP则会无法运作。

**反馈（沉淀 · 第一版，2026-11-04）**：

**判定：补一格。** ① 有一处角色错（和 Q1 第 1 问同一个错，不是笔误），② 把"必要条件"当成了"代价"，③ 空着。

| 格 | 这次盯什么 |
|---|---|
| ① 过程 | 前半段（IP 不变、源 IP 出公网被改）✔ 保留。改这一句：**"源目 MAC 在交换机给到下一跳路由时改变"** → 改成 **"每过一个路由器，路由器用自己口的 MAC 当源、下一跳的 MAC 当目的，把帧头整个重写；交换机只转发，一个字段都不动"** |
| ② 为什么这样设计 | 规模那句 ✔。"代价"写偏了——路由表是**必要条件**，不是代价。真代价写这两条里的一条：**端到端透明被破坏**（NAT 后外部连不进来，任何要"从外向内建连"的协议都得额外打洞）；或者 **每台设备都得维护并同步表**，表错一条就是绕路或黑洞 |
| ③ 什么时候不成立 | 空。至少一条：**同一个包被改 IP 的不止一次**——过两层 NAT 就改两次（家宽 + 运营商大内网）；或者 **MAC 在跨网段时根本没有"对方的 MAC"**，只有下一跳路由器的 MAC（这一条你 Q1 答对了，搬过来就行） |
目的IP不变，源IP会在出公网时修改，交换机负责转发，源目MAC会在过路由器时被重写，源MAC改为路由的MAC，目的MAC改为下一跳的MAC；不这样做就需要MAC直接向IP发包，需要MAC记忆IP当网络规模较大后会导致错误，代价就是没台设备都得维护同步表否则会转发错误或绕路，当跨网段没有目的MAC时就没发转发。
补完交回，过了 K05 入库，然后开 K06「目标前面隔着谁」——那一单元分的是**防火墙、代理、CDN 三件事**，正好接你 Q3 第 3 问答对的"NAT 副作用"往下走。

**反馈（沉淀 · 第二版，2026-11-04）**：

**判定：过。** → 已入 [[_结论]] K05

| 格 | 判 |
|---|---|
| ① 过程 | **四个动作全对了。** "交换机负责转发"这次改对了，源 MAC 换成出口路由器的、目的 MAC 换成下一跳的，一句话到位 |
| ② 为什么 | 规模 ✔；代价采纳了"每台设备都得维护同步表，错了就绕路或黑洞"——这条比 v1 的"要有路由表"准，因为**表错不等于表不存在，表错的表现是绕路和黑洞，那才是代价** |
| ③ 不成立 | 事实抓对了（跨网段确实拿不到目的主机的 MAC），**但结论写反了一句**，见下 |

**③ 那句要掰正：不是"没法转发"，是"换个人填"。**

你写「当跨网段没有目的 MAC 时就没法转发」——包照样发得出去。跨网段时，**帧头里"目的 MAC"这一栏填的从来不是最终目的地，而是下一跳路由器的 MAC**。目的主机在哪台路由器后面，你根本不知道也不需要知道。

所以正确的说法是：

> **同网段：目的 MAC = 对方的 MAC（ARP 直接问）。跨网段：目的 MAC = 网关的 MAC。** 无论哪种，这一栏填的都是"下一个接棒的人"，从来不是终点。

这恰恰是这一单元的结论本身：**MAC 只在这一跳有效，端到端的定位只能靠 IP。** 而你 v1 的 Q1 第 3 问已经答对了这条（同网段才 ARP 对方）——这里只是把结论的方向接反了一次，概念本身你已经有了。
