# M6 加密在哪一层

> 归属：[[00-学习地图]] ｜ 答题：[[M6-问答]] ｜ 上一单元：[[M5-导读-目标前面隔着谁]]

## 1. 这个单元要回答什么

两个问题，一个是你上次自己提出来的：

1. **HTTPS 之后，中间那层还看得见什么、看不见什么？**（M5 ③ 你写"反代无法解析 Host 头"——对了一半）
2. **证书到底在证明什么？** 为什么浏览器信它，为什么装个根就能骗过它。

这一单元不讲 TLS 的密码学，只讲**位置和边界**——因为你要判断的是"谁能看见什么"，不是去实现它。

## 2. 核心机制

### 2.1 位置：夹在 TCP 和 HTTP 之间

```text
HTTP      ← 明文，里面有 Host、URL、Cookie、Body
TLS       ← 加密层，吃进上面的东西，吐出密文
TCP       ← 负责可靠送达，不知道上面是什么
IP        ← 负责寻址
```

所以 TLS 不属于"网络层加密"，它是**应用层与传输层之间的一个夹层**。这也解释了为什么防火墙看不见内容：它站在 IP/TCP 那层，看到的只是密文流。

### 2.2 加密之后，链路上还剩什么明文

这是本单元最该记住的一张表：

| 还看得见               | 为什么                                  |
| ------------------ | ------------------------------------ |
| **目标 IP**          | IP 头必须明文，否则路由器没法转发                   |
| **SNI**（你要访问哪个域名）  | TLS 握手第一个包（ClientHello）里明文带着，除非用 ECH |
| **证书里的域名**（服务端返回的） | 证书本身是明文传输的                           |
| **流量大小、时间、连接数**    | 加密不改变包的长度和节奏，只能靠填充部分掩盖               |

| 看不见 | 因为 |
|---|---|
| Host 头 | 在 HTTP 里，被加密了 |
| URL 路径、参数 | 同上 |
| Cookie、请求体、响应体 | 同上 |

**结论一句话：HTTPS 藏住了"你在读什么"，没藏住"你在跟谁说话"。** 这句话在流量分析和红队侦察里都是起点。

### 2.3 证书在证明什么

一句话：**证明"这个公钥属于这个域名"，且这句话是某个 CA 说的，而你的系统无条件相信那几个 CA。**

```text
www.example.com 的证书
  ├─ 公钥：一串值
  ├─ 域名：www.example.com
  ├─ 签发者：中间 CA
  └─ 签名：中间 CA 用自己私钥对上面内容算的
```

验证是一条链：叶证书 → 中间 CA → 根 CA。**根证书预装在系统里**，链条只要一路验到某个受信的根，就通过。

所以"能不能冒充"这个问题，答案不在技术难度，在**你能不能拿到一条受信的链**。三种情况：

| 情况 | 结果 |
|---|---|
| 自己签一张 | 浏览器告警（链到不了受信根） |
| 域名不对 | 浏览器告警（证书里的域名和你访问的不符） |
| 企业/代理设备**把自己的根装进了你的系统** | **无感**，因为它确实是一条受信的链 |

第三种是这一单元的现实意义：**中间人不需要破解加密，只需要让你的机器相信它。** 公司做流量审查就是这么干的，攻击者拿到一台内网机器后装根也是这么干的。

### 2.4 还有一种更省事的冒充：拿真证书

`Let's Encrypt` 这类 DV 证书，只要你能证明域名归你（比如控制了解析），几分钟就能签一张**真的、受信的**证书。所以：**DNS 被劫持 + DV 证书 = 浏览器完全无感。** 这条把 K03（DNS）和本单元接了起来。

## 4. 为什么这样设计

**为什么不在 IP 层就加密（像 VPN 那样）？** 因为那样每台中间设备都要参与密钥协商，任何一台不支持就走不通。放在应用层上方，中间设备可以完全不理解内容，只负责转发——**代价是每台设备都成了睁眼瞎，包括你希望它看见内容的那台**（所以企业只能靠装根来重新看见，这就是 2.3 的第三条）。

**为什么不把 SNI 也加密？** 早期是因为服务端要先知道你要访问哪个站才能选证书，而这时还没建立加密。ECH 正在解决它，但需要 DNS 配合，目前普及有限。**这条是现在流量分析还能工作的主要原因。**

## 5. 动手验证（3 分钟）

```bash
# 1. 看证书链：谁签的、签给谁、有效期
echo | openssl s_client -connect www.baidu.com:443 -servername www.baidu.com 2>/dev/null | openssl x509 -noout -subject -issuer -dates

# 2. 看握手里 SNI 是不是明文（能不能抓到域名）
sudo tcpdump -nn -i en0 'tcp port 443' -c 5
# 另开一个终端：curl -s https://www.baidu.com -o /dev/null
# 抓包里看 ClientHello 里有没有 server_name

# 3. 看本机信任了哪些根（数量会让你意外）
security find-certificate -a -p /System/Library/Keychains/SystemRootCertificates.keychain | grep -c 'BEGIN CERTIFICATE'
```

第 3 条的意义：**这些根里任何一个的私钥泄露（或被塞进来一个），你后面所有的 HTTPS 都不再可信。**
