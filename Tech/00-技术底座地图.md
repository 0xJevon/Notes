## 二、网络基础（在跑的子线之一）

`网络基础/` 是全库**训练形态最好的一条线**，Security 主线的方法论有好几条是从它的设计里反推出来的：

- 定位是"**训练场**"不是知识库——"网络的概念 AI 一秒给你解释，你缺的是不看答案能不能预测一条链路的行为"
- 结构是 **导读 + 问答**成对出现，**先自己答再看反馈**
- 目标是每条结论能答三问：解决什么问题 / 代价是什么 / 为什么不用更简单的

**进度**：S1 的 M0–M4 已出材料（地址掩码与网关 / URL 到 HTTP / 域名到 IP / 套接字与连接 / 包怎么被转发），K06（防火墙·代理·CDN 识别）与 K07（TLS 与证书）待写。全表 7 节点、约 6 小时。

**状态**：`进行中`，但**优先级低于 Security**。它吸收的是碎片时间，不是主攻时段。

## 三、操作系统（在跑的子线之二）

**9 个单元，Linux 与 Windows 对照**：主体标识 → 认证凭证 → 特权能力 → 提权切换 → 访问控制 → 对象句柄 → 服务守护进程 → 隔离保护 → 日志审计。

只讲"权限如何生效、行为如何留痕"，不讲操作系统教材那套（调度、内存、文件系统实现一概不学）。**入口：[[操作系统/00-学习地图]]**；起点：[[操作系统/01-诊断]]。

它与网络基础的分工：网络回答"包怎么走"，这里回答"谁能做什么、做了留什么"。两者都不替代 Security 主线。

> 对应主线单元：网络 → A02 / E01；OS → D01 / D02 / D06。**只在这三处被调用，其余不打开。**

## 五、覆盖边界：这两条线管到哪，不管什么（2026-11-18 按六域重写）

问"网络和 OS 够不够用"，先看它服务哪个单元。**底座不服务 Q1（覆盖）和 Q3（定级），只服务 Q4（纵深到位）的前半步。**

| 主线单元 | 底座给什么 | 够不够 |
|---|---|---|
| **A02 外网资产测绘** | 网络 K01–K05：判"通不通、打到的是谁、经过哪些设备" | **够** |
| **D01/D02 提权** | OS M0–M5：判"能不能提、为什么被拒"（令牌 / 权限位 / ACL） | **够** |
| **D06 痕迹认知** | OS M7–M8：判"做了留什么" | **够到"留了什么"，不到"检测器在哪一层"** |
| **E04/E05 域与到域控** | **不够，且不是这两条线能补的** | 缺 AD（目录服务与授权模型） |
| **E01/E03 隧道与横向** | **不够** | 网络七节点全是"公网请求"视角，没有内网协议栈（SMB/RPC/LDAP/Kerberos/WinRM） |
| **D05 权限维持** | **不够** | OS M6 讲"服务以谁跑、能不能劫持"，是提权视角；载体不在其中 |
| **D04 载荷落地** | **不够** | K07 只回答"证书在证明什么"，不回答"怎么签一张能过的" |

**五样明确不在这两条线里，别在这儿找：**

| 缺的东西 | 为什么不属于底座 | 归哪 |
|---|---|---|
| **AD / 域** | 是目录服务与授权模型，不是操作系统的子集；OS M1 只讲令牌、登录类型、Kerberos 名字 | **E04–E05** |
| **内网协议栈**（SMB/RPC/LDAP/Kerberos/WinRM 的线上形态） | 网络线七节点全是"公网请求"视角（URL→IP→TCP→包→前置设备） | **E01/E03** |
| **驻留载体**（计划任务 / WMI / 注册表 Run / COM / 启动项） | OS M6 讲的是"服务以谁跑、能不能劫持"，是提权视角 | **D05** |
| **PKI 与证书链** | 网络 K07 只回答"证书在证明什么"，不回答"怎么给自己签一张能过的" | **D04** |
| 云 / 容器 / 虚拟化 | 各家实现不同，且现在才刚碰到 ZStack | **C04** |

**一句话：底座线的判据层已经够用。缺的不是学科，是链路上的域。** 继续往底座里加内容，就是在用"学基础"回避"打不穿"（违反 G03）。
