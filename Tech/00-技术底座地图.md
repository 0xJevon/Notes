# Tech · 技术底座线

> **定位：补给线，不是主攻方向。**
> 它只为"主线卡住时回补"服务。它不该抢主线的任何一分钟——抢了，就是用"学基础"逃避"动手做"（违反 G03）。

---

## 一、边界规则（先看这个）

| 规则 | 说明 |
|---|---|
| **不主动推进** | 没有具体卡点，不打开这条线 |
| **只补卡住的那一点** | 不是"系统学一遍网络"，是"隧道走不通，去查 M11 那一节" |
| **一次回补不超过 2 小时** | 超了说明补错了方向，回到 G04 |
| **不许因为"应该懂"而学** | "应该懂"是最容易变成收藏夹的理由 |

**例外**：`网络基础` 这条线正在跑，它是唯一有训练形态的技术线，允许独立推进（见第二节）。

**关于新增子目录（2026-11-02）**：曾计划按网络基础的形态，为系统与权限、数据库、密码学应用、Web 架构、代码阅读各建一套"学习地图 + 诊断 + 问题库 + 结论"。**这五套撤回了**——那是 5 套各 8 单元的训练场，约 160 小时，学不完。

**最终只补建一套：`操作系统/`**（7 单元：SID → 令牌 → 特权 → 完整性级别 → DACL → 句柄与服务 → 日志痕迹）。理由和另外四块不同：

| | 为什么要/不要训练场 |
|---|---|
| **操作系统/权限** | 是**判据链**：缺一环，后面全是猜；且答案不在书里，只能在"我以为能、实际被拒"的摩擦里长出来。必须有答题、有沉淀、有台账 |
| 数据库 / 密码学 / Web 架构 / 代码阅读 | 是**条目**，不是链。写进 [[../Career/03-必学清单]] 当清单，卡住再查，不需要答题形态 |

`Tech/` 下其余散稿（关系型数据库、开发语言）保持"查得到就行"，不升级成线。

## 二、网络基础（在跑的子线之一）

`网络基础/` 是全库**训练形态最好的一条线**，红队线的方法论有好几条是从它的设计里反推出来的：

- 定位是"**训练场**"不是知识库——"网络的概念 AI 一秒给你解释，你缺的是不看答案能不能预测一条链路的行为"
- 结构是 **导读 + 问答**成对出现，**先自己答再看反馈**
- 目标是每条结论能答三问：解决什么问题 / 代价是什么 / 为什么不用更简单的

**进度**：S1 的 M0–M3 已出材料（地址掩码与网关 / URL 到 HTTP / 域名到 IP / 套接字与连接），M4 起未出。

**状态**：`进行中`，但**优先级低于 Security**。它吸收的是碎片时间，不是主攻时段。

## 三、操作系统（在跑的子线之二）

**9 个单元，Linux 与 Windows 对照**：主体标识 → 认证凭证 → 特权能力 → 提权切换 → 访问控制 → 对象句柄 → 服务守护进程 → 隔离保护 → 日志审计。

只讲"权限如何生效、行为如何留痕"，不讲操作系统教材那套（调度、内存、文件系统实现一概不学）。**入口：[[操作系统/00-学习地图]]**；起点：[[操作系统/01-诊断]]。

它与网络基础的分工：网络回答"包怎么走"，这里回答"谁能做什么、做了留什么"。两者都不替代 Security 主线。
