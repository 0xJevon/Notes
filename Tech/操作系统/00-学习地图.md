# 操作系统 · 学习地图

> 一条**双平台对照**的知识线：Linux 与 Windows，同一件事两边怎么做。
> 与 [[../网络基础/00-学习地图|网络基础]] 同一套形态（导读 → 本机验证 → 合书答题 → 五格沉淀 → 过验收入 [[_结论]]），操作手册共用 [[../网络基础/02-怎么用]]。
> 上位：[[../../Career/01-能力分层与学习大纲]]。

---

## 一、这条线是什么

**一个完整的操作系统知识库，方向是"权限如何生效、行为如何留痕"。** 不是操作系统教材。

范围划在两条主轴上，双平台各走一遍：

| 主轴 | 回答什么 | 单元 |
|---|---|---|
| **权限** | 谁能做什么，凭什么 | M0–M7 |
| **可观测** | 做了之后留下什么，可不可信 | M8 |

**不学**：进程调度算法、内存分配策略、文件系统实现、驱动开发、内核漏洞挖掘、性能调优。这些答错不会让你做错任何动作——它们只影响你能不能把话说得更漂亮。

## 二、为什么两个平台都要，而且要对照

只学一边的人有一个共同缺陷：**把一边的实现当成"操作系统的原理"**。

- 只学 Windows 的人，会以为"权限就是 ACL 加令牌"，看到 Linux 的 `sudo` 就不知道归到哪一层
- 只学 Linux 的人，会以为"提权就是改 euid"，遇到 Windows 的 deny-only 组会完全失判

对照学的收益不是"多会一套命令"，是**分清哪些是机制、哪些是某个系统的实现选择**。分清之后，判断才能迁移；分不清，换个环境就重新学一遍。

你的情况特殊一点：Linux 有底子、Windows 是空的。所以这条线不是两边等量投入——**Windows 侧要点对点打地基，Linux 侧重点在"修正旧认知"**。每单元的「Linux 侧」一节，多数时间在告诉你"你原来的理解哪里需要改"。

## 三、九个单元

| 序 | 单元 | Windows 侧 | Linux 侧 | 要回答的那一个问题 |
|---|---|---|---|---|
| 1 | [M0 主体标识](S1/M0-导读-主体标识.md) | SID、RID、组、知名 SID | uid/gid、`/etc/passwd`、附加组 | 系统认的"你是谁"到底是什么 |
| 2 | [M1 认证与凭证上下文](S1/M1-导读-认证与凭证上下文.md) | 令牌（主/模拟）、登录类型、UAC 双令牌 | PAM 会话、`cred`（uid/euid/suid/fsuid）、环境 | 登录那一刻拿到了什么，它能用来干什么 |
| 3 | [M2 特权与能力](S1/M2-导读-特权与能力.md) | Privileges（`SeDebug` 等六个） | capabilities、SUID/SGID | 哪些能力是"绕过正常检查" |
| 4 | [M3 提权与身份切换](S1/M3-导读-提权与身份切换.md) | UAC、`runas`、服务账户 | `sudo`、`su`、setuid 程序 | 从低权限到高权限，一共几条路 |
| 5 | [M4 访问控制](S1/M4-导读-访问控制.md) | DACL/ACE 求值、所有者、继承 | mode bits、`umask`、POSIX ACL | 一次访问，按什么顺序判 |
| 6 | [M5 对象与句柄](S1/M5-导读-对象与句柄.md) | 句柄、对象管理器、访问掩码 | fd、`/proc`、inode | 打开之后拿到了什么，为什么关不掉 |
| 7 | [M6 服务与守护进程](S1/M6-导读-服务与守护进程.md) | SCM、服务账户、服务 ACL | systemd unit、`User=`、cron | 后台进程以谁的身份跑，能不能劫持 |
| 8 | [M7 隔离与保护](S1/M7-导读-隔离与保护.md) | 完整性级别、PPL、Credential Guard、AppContainer | namespace、cgroup、seccomp、SELinux/AppArmor | "有权限也拿不到"，是被什么挡的 |
| 9 | [M8 日志与审计](S1/M8-导读-日志与审计.md) | Security EVTX、Sysmon、7042/7045 | auditd、`auth.log`、journald | 一次动作留下什么，这个记录可不可信 |

**顺序的理由**：M0 定义主体 → M1 怎么打包成一次身份上下文 → M2/M3 身份上挂的能力与升级路径 → M4 能力与对象怎么比对 → M5 比对通过后拿到什么 → M6 长期运行的身份 → M7 保护层 → M8 全过程的记录。前一环空着，后一环就是猜。

**M0–M4 必须连做**（一条判据链）。M5–M7 可以插空先后。M8 建议放最后，因为它的反推要用前面全部概念。

## 四、每个单元的固定结构

导读统一四块，Linux 与 Windows 并列写：

```text
1. 这个单元要回答什么
2. 核心机制（先讲"两边共同的问题"，再分平台讲实现）
3. 两边对照（一张表：同一件事各自怎么做、哪里不能迁移）
4. 动手验证（Windows 一段命令 + Linux 一段命令，都要跑）
```

答题时**两边都要答**。问答文件里的题按"共同问题"设计，平台差异用追问带出。

## 五、职业校准：六个判定场景

学完一个单元回来划一格。**填不满说明方向偏了。**

| 场景 | 现场长什么样 | 判错的后果 | 补它的单元 |
|---|---|---|---|
| 判"这个权限够不够" | `whoami /priv` 有 `SeImpersonate`；Linux 侧 `CapEff` 里有一位 | 走不需要特权的笨路，或以为有特权就能打 | M2 |
| 判"为什么拒绝访问" | `icacls` 有 `(M)` 却被拒；Linux `ls -l` 看着可写却写不进 | 乱改 ACL / chmod，真因是组标记、IL、挂载只读或 SELinux | M4、M7 |
| 判"这个服务能不能劫持" | Windows 路径带空格；Linux unit 里 `ExecStart` 指向可写目录 | 报了不可利用的提权，被打回 | M6 |
| 判"能不能读到进程内存" | mimikatz 报 0x5；Linux `ptrace` 被拒 | 直接放弃，转走更慢的路 | M5、M7 |
| 判"他是怎么进来的" | 4624 的 LogonType、`auth.log` 的 sudo 行 | 定位到错的人或错的路径 | M8 |
| 判"日志能不能信" | 1102；Linux 日志被截断或缺失 | 把"没记录"当成"没发生" | M8 |

## 六、资源

| 资源 | 用途 | 处理 |
|---|---|---|
| Microsoft Learn：Access Tokens / Privileges / ACL / Mandatory Integrity Control | Windows 侧字段与求值顺序的**权威定义** | 当字典查 |
| *Windows Internals* 7th Ed Part 1 Ch7、Part 2 Ch10 | 令牌、登录会话、服务的内核视角 | 只在"为什么这样设计"卡住时翻一节 |
| `man 7 credentials`、`man 7 capabilities`、`man 5 passwd`、`man 8 auditctl` | Linux 侧权威定义 | 当字典查，**优先于任何博客** |
| *Linux 系统编程*（Kerrisk）相关章节 | cred 与 fd 的细节 | 只查卡住的那节，不从头读 |
| HackTricks（Windows / Linux PrivEsc 两节） | 提权路径清单 | 清单型，用到才查 |
| 本机：Win10/Server 虚机 + 一台 Linux 虚机（都能快照） | 复现场 | 一次性搭好，两边都要有 |
| `whoami /all`、`icacls`、`accesschk`、`id`、`getfacl`、`capsh`、`auditctl` | 取证工具 | 熟练到不看帮助 |

## 七、阶段产物（两张）

### ① 权限判别表（M4 后）

**输入**：任给一边的现场材料——Windows 给 `whoami /all` + `icacls`，Linux 给 `id` + `ls -l` + `getfacl`。
**输出**：判出"这个主体能不能对这个对象做这个操作"，并指出**卡在哪一层**（DACL / 组标记 / IL / 挂载 / MAC）。
**判据**：两边各 3 个案例，5 分钟内判完，不许答"权限不够"。

### ② 痕迹反推表（M8 后）

**输入**：你自己手上的 3 条真实告警或日志片段（Windows 与 Linux 各至少 1 条）。
**输出**：每条写清「触发行为 → 命中哪个日志/事件 → 命中哪一层检测 → 我能不能独立复现」。
**判据**：至少 1 条能反推到具体命令行或具体进程链。

## 八、怎么用

1. 每单元：读导读 → 查指定文档 → **两边本机各复现一次** → 合书答题（两边都答）→ 五格沉淀 → 交回
2. 反馈三段：对在哪 / 错在哪 + 缺的那一环 / 再深一层追问
3. 答错的原文留着（G09）
4. 收到反馈 24 小时内回炉 10 分钟：重写沉淀、改问题库、改 `status`
5. 五格（机制 / 矛盾 / 代价 / 失效条件 / **现场信号**）过验收才进 [[_结论]]
6. 每 3 个单元回访一次（见 [[_问题库]]）

**单单元 75 分钟**（两边各多 15 分钟复现）。Linux 侧熟悉的地方可以只跑验证区、跳过答题，但**不许跳过"你原来的理解哪里错了"那一节**。
