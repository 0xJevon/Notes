## 答完之后

我会给两样东西：

| 产出 | 用途 |
|---|---|
| 逐题反馈（对在哪 / 错在哪 / 缺哪一环） | 定位真实的洞，不是笼统的"权限模型不熟" |
| **跳过表** | 哪几个单元可以不看导读直接答题，哪几个必须从 M0 起 |

经验判断：

- **Q1、Q5、Q10** 考的是"标识与规则求值"。Linux 底子在的人一般不会全错，但 **Q10 第 2 问**（改属主后能不能读）栽的人最多——它考的是"命中即停"，和 Windows 的"累加"正好相反
- **Q3、Q4、Q6、Q9** 基本会栽：令牌、完整性级别、PPL、日志审计是 Windows 独有的第二道门，Linux 里没有对应物，没有迁移优势
- **Q11** 考 Linux 侧的痕迹。多数人会答"看 auth.log"，但答不出 `auditctl -l` 为空意味着"进程执行根本查不到"

判读方式：

| 结果 | 结论 |
|---|---|
| Q1、Q5、Q10 全对 | M0、M4 可以只跑验证区，不答题 |
| Q3、Q4、Q6 错两个以上 | 必须从 M1 老实走，不许跳 |
| Q11 答不出审计规则 | M8 不要跳过，且要先补 `auditctl` 的基本用法 |
