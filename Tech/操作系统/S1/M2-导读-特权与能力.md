# M2 特权与能力：Privileges 与 capabilities

> 归属：[[Tech/操作系统/00-学习地图]] ｜ 答题：[[M2-问答]] ｜ 上一单元：[[M1-导读-认证与凭证上下文]]

## 1. 这个单元要回答什么

`whoami /priv` 列出的那些行，**哪几行等于直接换一个身份？**

这是你排提权路径时最先看的一张表。看不出来，后面全是猜。

## 2. 核心机制

### 2.1 特权不是权限

两件事经常被混成一件：

| | 权限（permission / access right） | 特权（privilege） |
|---|---|---|
| 作用对象 | 某个具体对象 | 系统级操作 |
| 例子 | 读这个文件、写那个注册表键 | 调试任意进程、备份任意文件、关闭系统 |
| 怎么获得 | ACL 里给你 | 令牌上带着 |
| 检查方式 | 打开对象时比对 DACL | 执行操作时查令牌 |

一句话：**权限是"能不能碰这个东西"，特权是"能不能绕过规则"。**

### 2.2 六个必须认识的

| 特权 | 它能干什么 | 典型滥用 |
|---|---|---|
| `SeDebugPrivilege` | 打开**任意**进程，包括别人的 | 读 lsass、注入、转储内存 |
| `SeImpersonatePrivilege` | 借用一个已认证客户端的身份 | Potato 系（Rotten/Juicy/Print），把自己变成 SYSTEM |
| `SeAssignPrimaryTokenPrivilege` | 给新进程指定令牌 | 与上一条配合 |
| `SeBackupPrivilege` | **绕过 ACL 读**任意文件 | 复制 SAM / SYSTEM 注册表 hive 出来离线解 |
| `SeRestorePrivilege` | **绕过 ACL 写**任意文件 | 覆盖系统文件、写启动项 |
| `SeTakeOwnershipPrivilege` | 把任意对象的所有者改成自己 | 拿到所有权后改 DACL，再正常访问 |

另外两个见过就行：`SeLoadDriverPrivilege`（加载驱动，能进内核）、`SeTcbPrivilege`（"作为操作系统的一部分"，几乎等于 SYSTEM）。

### 2.3 `Disabled` 不等于没有

```text
SeImpersonatePrivilege    Impersonate a client after authentication    Disabled
```

这一行**表示特权在令牌上，只是当前没启用**。任何代码都可以用 `AdjustTokenPrivileges` 把它打开，不需要额外授权。

判据很硬：**看这一行在不在，不看它是 Enabled 还是 Disabled。** 不在，才是真的没有。

只有一种情况会让"在"变成"不在"：**UAC 的过滤令牌会把一部分特权剔掉**（M3 讲为什么）。所以同一个管理员，提权前后 `whoami /priv` 的输出会不一样。

### 2.4 谁默认有什么

| 身份 | 默认带的关键特权 |
|---|---|
| 本地管理员（完整令牌） | 几乎全部，含 `SeDebug`、`SeBackup`、`SeRestore`、`SeTakeOwnership` |
| **服务账户 / IIS 应用池** | **`SeImpersonate` + `SeAssignPrimaryToken`** ← 这就是 Potato 系的入口 |
| `LOCAL SERVICE` / `NETWORK SERVICE` | 同上，另加一些服务相关特权 |
| 普通用户 | 极少，通常只有 `SeShutdown`、`SeChangeNotify` 这类无害的 |

表里第二行是重点：**只要一个服务以这几个内置账户运行，它就有借身份的能力**，而这在 IIS、SQL Server、大多数自建服务里是默认的。这也是为什么"拿到一个 WebShell，先看应用池身份"是标准动作。

### 2.5 Linux 侧：capabilities 与 SUID

Linux 把"root 的全部权力"拆成了几十个 **capability** 位。这是它和 Windows 最像、也最容易混淆的一块。

| capability | 相当于 Windows 的 | 它能干什么 |
|---|---|---|
| `CAP_DAC_OVERRIDE` | `SeRestore`（半个） | 绕过文件的读/写/执行权限检查 |
| `CAP_DAC_READ_SEARCH` | `SeBackup` | 绕过读检查，能遍历所有目录 |
| `CAP_SETUID` / `CAP_SETGID` | `SeAssignPrimaryToken`（近似） | 任意改自己的 uid |
| `CAP_SYS_PTRACE` | `SeDebug` | 跟踪/读任意进程内存 |
| `CAP_SYS_ADMIN` | 没有精确对应 | 挂载、命名空间、大量系统管理操作——"新的 root" |

四个集合，看前两个就够：

```bash
cat /proc/self/status | grep Cap
capsh --decode=0000003fffffffff     # 把十六进制位解成名字
```

| 集合 | 含义 |
|---|---|
| **Permitted**（P） | 这个进程**最多**能持有哪些 |
| **Effective**（E） | 当前**真正生效**的（检查看这个） |
| Bounding | 上限，exec 之后不能超过它 |

**关键差异**：Windows 的特权是"**这个账号**有"，跟着令牌走；Linux 的 capability 是"**这个进程**有"。所以 Linux 上同一个用户跑不同程序，能力可以不一样。

**SUID** 是另一半，也是 Linux 独有的：文件设了 SUID 位且属主是 root，任何人运行它，进程的 **euid 立刻变成 0**。

```bash
find / -perm -4000 -type f 2>/dev/null | head -20
getcap -r / 2>/dev/null | head
```

这两条命令列出的东西，就是 Linux 上"合法的提权面"：一个 SUID 程序如果有命令执行或文件写入功能，就等于把 root 借给了所有用户。**这和 Windows 的"服务路径可写"是同一类问题，只是载体从服务换成了文件。**

## 4. 动手验证（两边各 15 分钟）

```cmd
:: ① 普通权限下看自己的特权
whoami /priv

:: ② 用管理员身份再开一个 cmd，对比差异
::    （开始菜单搜 cmd → 右键"以管理员身份运行"）
whoami /priv

:: ③ 看某个服务的运行身份
sc qc MyAppSvc
```

**要亲眼看到的**：两次 `whoami /priv` 的输出**不一样**。差异就是过滤令牌剔掉的那些——这些特权在提权后才回来。

如果手边有 IIS 或 SQL Server，看它的服务账户，再对照 2.4 的表。

Linux 侧：

```bash
# ① 当前 shell 的能力（普通用户大概率是空的）
grep Cap /proc/self/status
capsh --print | sed -n '1,6p'

# ② 哪些程序带了额外能力（不是 SUID，但同样给权限）
getcap -r /usr/bin /usr/sbin 2>/dev/null | head

# ③ SUID 清单：Linux 上"合法的提权面"
find /usr/bin /usr/sbin /bin -perm -4000 -type f 2>/dev/null | head -15

# ④ 一个典型例子：ping 为什么普通用户能用（它带 cap_net_raw）
getcap "$(command -v ping)" 2>/dev/null
```

**要亲眼看到的**：普通 shell 的 `CapEff` 基本为空，而 `getcap` 和 SUID 清单里那些程序**带着权限**。这就是"能力不跟人走、跟程序走"的直接证据。

## 5. 为什么这样设计

**为什么不把特权直接做成权限，塞进 ACL？**

因为有些操作根本没有"对象"可以挂 ACL——"调试任意进程"影响的是所有进程，"备份任意文件"影响的是整个文件系统。特权是给这类**跨对象的、系统级的**能力留的口子。

**代价：**

- 它是全有或全无的："能备份"意味着能读**任何**文件，包括你不该读的
- 默认配置把 `SeImpersonate` 给了服务账户，等于给每个服务留了一个"借身份"的能力
- 判断成本高：光看服务在跑没用，得看它**以谁的身份**在跑
