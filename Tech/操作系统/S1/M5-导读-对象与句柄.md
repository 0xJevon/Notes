# M5 对象与句柄：handle 与 fd

> 归属：[[../00-学习地图]] ｜ 答题：[[M5-问答]] ｜ 上一单元：[[M4-导读-访问控制]] ｜ 下一单元：M6 服务与守护进程

## 1. 这个单元要回答什么

M4 讲"权限怎么判"，这一单元讲**判完之后拿到的东西**：

- 打开一个文件/进程之后，手里到底是什么？
- 为什么权限只查一次，之后不再查？
- 为什么"有权限"仍然可能读不到（lsass、`/proc/pid/mem`）？
- 为什么删掉的文件还占着磁盘？

## 2. 核心机制

### 2.1 Windows：句柄

```text
你的进程 ──[句柄表]──→ 内核对象（进程/文件/注册表键/令牌…）
                   └── 附带「访问掩码」：这次打开允许我做什么
```

三个要点：**权限检查在 `Open*` 那一刻完成**；句柄是进程私有的；**句柄不关，权限就还在**。

所以"改权限后当前程序没反应"是正常的——它用的是旧句柄。

### 2.2 读 lsass 要过四道门

| 门 | 要求 | 卡住的样子 |
|---|---|---|
| 1. 打开进程 | `PROCESS_VM_READ` + `PROCESS_QUERY_INFORMATION` | `Access is denied (0x5)` |
| 2. 跨账户 | `SeDebugPrivilege` **且已启用** | 同上 |
| 3. 进程保护 | lsass 开 **RunAsPPL**，`SeDebug` 也不够 | 同上，但"看起来什么都对" |
| 4. 虚拟化保护 | **Credential Guard**：凭据不在可读内存 | 能打开，读到空壳 |

第 3、4 道是"有权限也拿不到"，M7 专门讲。

### 2.3 Linux：fd、file description、inode

Linux 比 Windows 多一层：

```text
进程 ──[fd 表]──→ file description（偏移、标志、引用计数）──→ inode ──→ 数据
      fd = 3            ↑ Windows 没有这一层
```

| 层 | 是什么 | 关键点 |
|---|---|---|
| **fd** | 进程内小整数（0/1/2 = 标准输入输出错误） | 只在本进程有意义 |
| **file description** | 一次 `open()` 的结果 | `fork`/`dup` 后**共享**（共享读位置） |
| **inode** | 文件的真实身份（权限、属主、数据块） | 文件名只是目录里的一条映射 |

三条推论：

1. **权限只在 `open()` 查一次**，之后 `read`/`write` 不查 → "改了权限但程序还能写"是正常现象
2. **删文件不释放空间**：`unlink` 只删目录项，有 fd 拿着，inode 就还在
3. **硬链接是同一个 inode 的多个名字**，删一个不影响数据

### 2.4 看别人的内存

| | Windows | Linux |
|---|---|---|
| 机制 | `OpenProcess` + `ReadProcessMemory` | `ptrace(PTRACE_ATTACH)` |
| 权限 | `SeDebug` 或同账户 | 同 uid，或 `CAP_SYS_PTRACE` |
| 限制 | PPL、Credential Guard | **Yama `ptrace_scope`**、`/proc` 挂载、SELinux |
| 有权限者能否绕过 | **PPL 挡得住 SYSTEM** | `ptrace_scope` 是 sysctl，**root 能改回去** |

最后一行是两边最重要的差异：Windows 的保护在内核里，Linux 的这个限制只是一个参数。

所以"Linux 上拿到 root 却读不到别的进程"，通常意味着 **SELinux/AppArmor 或容器边界**，而不是 `ptrace_scope`。

### 2.5 对照表

| 概念 | Windows | Linux |
|---|---|---|
| 打开后的引用 | 句柄（进程私有） | fd + file description |
| 权限检查时机 | `Open*` 一次 | `open()` 一次 |
| 文件身份 | 文件对象 | inode |
| 删除已打开的文件 | 通常被拒（被占用） | **允许**，空间等 fd 关闭才释放 |

## 4. 动手验证（两边各 15 分钟）

Windows：

```cmd
:: 看当前进程句柄数，以及谁开着文件
handle.exe -p explorer | more
(Get-Process -Id $PID).HandleCount
```

Linux：

```bash
# ① 删了不释放（本单元的重点实验）
dd if=/dev/zero of=/tmp/hold bs=1M count=200 2>/dev/null
exec 3</tmp/hold
rm /tmp/hold
ls -l /proc/self/fd/3      # 显示 (deleted)
df -h /tmp | tail -1       # 空间没回来
exec 3<&-                  # 关掉才释放

# ② 看别人的 fd（需权限）
sudo ls -l /proc/1/fd | head

# ③ ptrace 的限制在哪
cat /proc/sys/kernel/yama/ptrace_scope 2>/dev/null
```

**要亲眼看到的**：文件删了、`df` 没变。这和 Windows"文件被占用删不掉"是同一件事的两种表现。

## 5. 为什么这样设计

**为什么不在每次读写时查权限？** 太贵。用"打开时查一次、发一个引用"换来速度，代价是：权限回收有延迟（已开的引用不受影响）、引用传递成了新的安全问题、泄漏会累积。

Linux 多一层 file description，是为了让 `fork` 的父子进程**共享读位置**——shell 管道靠它工作。
