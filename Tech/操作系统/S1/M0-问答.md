### Q1｜判定：这份 ACL 拷过去还能用吗

机器 A：

```text
> whoami /user
User Name        SID
================ ==============================================
machine-a\test   S-1-5-21-1111111111-2222222222-3333333333-1001

> icacls D:\share
D:\share machine-a\test:(OI)(CI)(M)
```

机器 B：

```text
> whoami /user
machine-b\test   S-1-5-21-4444444444-5555555555-6666666666-1001
```

把 `D:\share` 连 ACL 一起拷到 B 机。B 机上的 `test` 打开这个目录，能不能写？为什么？

1. 能不能？说明卡在哪。
2. 你的结论依据的是 SID 的**哪一段**？把两边的 SID 对齐着指出来。

**追问**：如果两台机器都加入了 `CORP` 域，改用域账号 `CORP\test` 做同样的拷贝，结果会变吗？为什么？

**我的回答**：不能，目录的权限是绑定在machine-a\test账户上的，账户的权限由SID决定，SID又与本地机器域绑定，所以拷到B机的test用户没有打开目录的权限。A机的SID依据是1111111111-2222222222-3333333333，B机是4444444444-5555555555-6666666666。CORP域是什么我不知道，但我猜应该会改变，如果这是个共享账号的话则权限应该不与本机绑定，那拷贝到不同机器上的权限应该就一致，也就可以打开目录。

### Q2｜为什么：为什么不直接用用户名

系统用一串数字（SID / uid）标识主体，而不是直接用用户名。

1. 不用数字会退化成什么？说出**两种**会出的乱子，各举一个具体场景。
2. 这么做的**代价**是什么？挑最麻烦的那一条说清它麻烦在哪。

**追问**：什么情况下 `icacls` 会显示成一串 `S-1-5-21-...` 而不是 `machine-a\test`？列举至少两种原因，并指出**哪一种在安全上是有意义的信号**。

**我的回答**：不用数字用账号名吗，可能创建相同的账号会导致权限冲突。不太清楚代价。有重名吗，不太清楚。

## 验证区（命令直接从这里复制，输出贴回这里）

> **Windows 部分必须在管理员 PowerShell 里跑**（`Win + X` → 终端(管理员)）。cmd 里没有 `Get-LocalUser`、`Rename-LocalUser`。全部命令 Win11 自带，不需要下载任何东西；唯一被弃用的是 `wmic`，已换掉。

**Windows（整段粘进去即可，含清场）**

```powershell
# 必须是 PowerShell（cmd 里 2>$null 会生成一个叫 $null 的文件）
whoami /user
whoami /groups
Get-LocalUser | Select-Object Name, Enabled, SID | Format-Table -AutoSize -Wrap

net user test /delete 2>$null; net user test2 /delete 2>$null
net user test P@ssw0rd! /add
mkdir C:\sidtest
icacls C:\sidtest /grant "test:(OI)(CI)M"

(Get-Acl C:\sidtest).Access | Where-Object { $_.IdentityReference -like "*\test" } |
  Select-Object IdentityReference, FileSystemRights, IsInherited,
    @{ n='SID'; e={ $_.IdentityReference.Translate([System.Security.Principal.SecurityIdentifier]).Value } } |
  Format-List

Rename-LocalUser -Name test -NewName test2

(Get-Acl C:\sidtest).Access | Where-Object { $_.IdentityReference -like "*\test2" } |
  Select-Object IdentityReference, FileSystemRights, IsInherited,
    @{ n='SID'; e={ $_.IdentityReference.Translate([System.Security.Principal.SecurityIdentifier]).Value } } |
  Format-List
icacls C:\sidtest

Remove-LocalUser test2
Remove-Item C:\sidtest -Recurse -Force
```

**我看到了什么**（三段式，各一句）：
Windows我预期看到用户的SID，以及改变账户名前后账户权限和分配的目录权限不变，实际上两次SID和IdentityReference一致，所以权限是与SID绑定的，与账户名无关。
Linux我期待看到用户权限与uid绑定，实际上uid为0代表root用户，1000以后为普通用户。
